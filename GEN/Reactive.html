Reactive Programming

Reactive programming is a declarative programming paradigm concerned with data streams and the propagation of change.

Reactive programming allows applications to react to updates automatically and efficiently.

Like reacting to something when user clicks this button run this function or when file IO operation is complete run this function. Imperative means when we are doing all the steps.

While declarative is where we are declaring this is what i want to happen and something is going to make that happen.

An imperative approach involves explicitly writing out the sequence of steps to achieve a result.

While a declarative approach describes the desired outcome and the programming language figures out the execution.

Reactive programming is a declarative programming paradigm that focuses on data streams and the propagation of change, using asynchronous, non-blocking code to react to events and data. It allows applications to handle dynamic data and real-time updates efficiently and is built on concepts like streams, observables, and operators to transform and combine data. This approach enhances responsiveness, resilience, and scalability in applications.

Core concepts
  • Data Streams: A sequence of ongoing data that can be transformed and combined as it is processed.
  • Observables: A type of stream that can be observed and reacted to.
  • Operators: Functions that take an observable and return a new observable, used to perform operations on the data stream.
  • Asynchronous and Non-Blocking: Instead of waiting for a task to complete, reactive programming uses a non-blocking model to handle events as they happen.
Key characteristics and benefits
  • Responsiveness: Applications remain responsive by processing data as it arrives rather than waiting for a complete request.
  • Resilience: Designed to handle failures and errors, allowing applications to continue functioning.
  • Scalability: Efficiently handles multiple requests asynchronously, making it ideal for handling high-traffic applications.
  • Efficiency: Optimizes resource usage by not blocking threads while waiting for I/O operations.
Code
void main(String[] args) {
    Flux<Integer> numbers = Flux.range(1, 5)
        .map(n -> n * n)                  // transform each item
        .filter(n -> n % 2 == 1)         // keep odds
        .delayElements(Duration.ofMillis(100));

    numbers.subscribe(
        n -> System.out.println("got: " + n),
        err -> System.err.println(err),
        () -> System.out.println("done")
    );
}
How it works

Flux is a publisher of 0..N items emitted asynchronously.

Operators build a pipeline but run only after subscribe().

The subscriber reacts to each item, an error, or completion.

Work runs without blocking the calling thread.
