State Pattern

State is a behavioral design pattern that lets an object alter its behavior when its internal state changes, so the object appears to change its class.

Each possible state is represented by a separate class, and the context delegates state-specific behavior to the current state object.

It is essentially an object-oriented way to implement a finite state machine, replacing large conditional statements with polymorphism.

When to use
  • When an object's behavior depends on its state and must change at runtime.
  • When you have large conditionals that branch on the object's state.
  • When state-specific code is duplicated across many methods.
  • Typical uses: workflow engines, TCP connections, vending machines, and media players.
Advantages
  • Removes bulky conditional statements by using polymorphism.
  • Organizes state-specific behavior into separate, cohesive classes.
  • Follows the Single Responsibility and Open/Closed Principles.
  • Makes state transitions explicit and easier to reason about.
Disadvantages
  • Increases the number of classes, one per state.
  • Can be overkill when there are only a few states with simple logic.
  • Transition logic may be scattered across the state classes.
Code
interface State {
    void next(TrafficLight light);
    String color();
}

class RedState implements State {
    public void next(TrafficLight l) { l.setState(new GreenState()); }
    public String color() { return "RED"; }
}

class GreenState implements State {
    public void next(TrafficLight l) { l.setState(new RedState()); }
    public String color() { return "GREEN"; }
}

class TrafficLight {              // Context
    private State state = new RedState();
    void setState(State s) { state = s; }
    void change() { state.next(this); }
    String show() { return state.color(); }
}

void main() {
    TrafficLight light = new TrafficLight();
    System.out.println(light.show());  // RED
    light.change();
    System.out.println(light.show());  // GREEN
}
How the State works
  • State defines behavior common to all states.
  • TrafficLight is the context that delegates to its current state.
  • Each state decides the next state in its next() method.
  • Behavior changes without any if/switch in the context.
