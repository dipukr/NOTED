Coroutines Support

Kotlin coroutines provide lightweight, suspendable computations for asynchronous, non-blocking code.

A suspend function can pause without blocking its underlying thread, resuming later.

Spring integrates coroutines so controllers can use suspend and return Flow.

They read like sequential code while running asynchronously under the hood.

When to use / Key points
  • Kotlin services doing concurrent I/O that should stay non-blocking.
  • suspend functions bridge to Reactor's Mono/Flux.
  • Flow is the coroutine analog of Flux.
  • Use structured concurrency with coroutineScope to bound lifetimes.
Advantages
  • Sequential-looking code without callback nesting.
  • Extremely cheap compared to OS threads.
  • Structured concurrency simplifies cancellation and error handling.
Disadvantages / Trade-offs
  • Kotlin-only; not available to plain Java code.
  • Mixing blocking calls inside coroutines defeats the purpose.
  • Dispatcher misuse can still block threads.
Code
// Kotlin with Spring WebFlux coroutine support
@RestController
class OrderController(val service: OrderService) {

    @GetMapping("/orders/{id}")
    suspend fun get(@PathVariable id: Long): Order {
        // suspends without blocking the thread
        return service.load(id)
    }

    @GetMapping("/orders")
    fun all(): Flow<Order> = service.stream()
}

@Service
class OrderService {
    suspend fun load(id: Long): Order = coroutineScope {
        val user = async { loadUser(id) }
        val items = async { loadItems(id) }
        Order(user.await(), items.await())
    }
}
How it works
  • suspend marks functions that can pause and resume without blocking.
  • coroutineScope with async runs the two loads concurrently.
  • await() suspends until each async result is ready, then combines them.
