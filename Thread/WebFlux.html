WebFlux Reactive

Spring WebFlux is a non-blocking, reactive web framework built on Project Reactor.

It uses Mono (0-1 items) and Flux (0-N items) as its core publisher types.

A small event-loop thread pool serves many concurrent requests without one-thread-per-request.

It shines under high concurrency and I/O-bound workloads.

When to use / Key points
  • High-concurrency, I/O-bound services and streaming responses.
  • Never block an event-loop thread; keep the chain reactive end to end.
  • Use WebClient instead of blocking RestTemplate.
  • Offload unavoidable blocking calls to a bounded scheduler.
Advantages
  • Handles many concurrent connections with few threads.
  • Backpressure prevents fast producers from overwhelming consumers.
  • Natural fit for streaming and server-sent events.
Disadvantages / Trade-offs
  • Steeper learning curve than blocking MVC.
  • Debugging reactive stack traces is harder.
  • A single blocking call can cripple the event loop.
Code
@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserRepository repo;

    public UserController(UserRepository repo) {
        this.repo = repo;
    }

    @GetMapping("/{id}")
    public Mono<User> byId(@PathVariable String id) {
        // non-blocking single result
        return repo.findById(id)
                   .switchIfEmpty(Mono.error(new RuntimeException("not found")));
    }

    @GetMapping
    public Flux<User> all() {
        // streams users as they arrive
        return repo.findAll();
    }
}
How it works
  • Mono<User> represents an async single value resolved without blocking.
  • Flux<User> streams many items with backpressure support.
  • The event loop subscribes and pushes data as it becomes available.
