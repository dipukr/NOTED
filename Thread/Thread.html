Thread

A thread of execution is the smallest sequence of programmed instructions that can be managed independently by an OS scheduler. Threads of a process share its executable code and the values of its dynamically allocated variables and non-thread-local global variables at any given time.

Local primitive variables are thread-safe because each thread has separate stack memory; local reference variables are not, because each thread shares heap memory. Each thread has its own stack (program counter and local variables) but shares the same code and heap with the rest of the process.

Code
void main(String[] args) throws InterruptedException {
    Runnable task = () -> {
        for (int i = 0; i < 3; i++)
            System.out.println(Thread.currentThread().getName() + " " + i);
    };

    Thread t = new Thread(task, "worker");
    t.start();                 // runs task on a new thread
    t.join();                  // wait for it to finish
    System.out.println("main done");
}
How it works
  • A Runnable holds the code to run concurrently.
  • start() spawns a new thread that invokes run().
  • Calling run() directly would execute on the current thread.
  • join() blocks main until the worker completes.
Thread Creation

In Java a thread can be created by extending Thread or by implementing Runnable. The Runnable approach is preferred because it keeps the task separate from the thread and leaves the class free to extend something else.

Calling start() allocates a new OS thread and invokes run() on it; calling run() directly just executes on the current thread, with no new thread involved.

Code
void main(String[] args) {
    // 1) Implement Runnable (preferred)
    Runnable task = () -> System.out.println("from runnable");
    Thread t1 = new Thread(task);
    t1.start();      // launches a new thread

    // 2) Extend Thread
    Thread t2 = new Thread() {
        public void run() { System.out.println("from subclass"); }
    };
    t2.start();
}
How it works
  • A Runnable holds the task; new Thread(task) wraps it.
  • start() allocates a stack and runs run() on the new thread.
  • Extending Thread overrides run() directly.
  • Never call run() yourself; it executes on the current thread.
Thread Priority

Each thread has a priority, and the thread scheduler uses priority to decide which Runnable thread should be allowed to execute next.

Threads with higher priority are executed in preference to threads with lower priority; when two threads share the same priority, the JVM runs them in FIFO order. Priorities range from Thread.MIN_PRIORITY (1) to Thread.MAX_PRIORITY (10), with Thread.NORM_PRIORITY (5) as the default.

Code
public class PriorityDemo {
    public static void main(String[] args) {
        Thread high = new Thread(new Counter("high"));
        Thread low = new Thread(new Counter("low"));

        high.setPriority(Thread.MAX_PRIORITY);   // 10
        low.setPriority(Thread.MIN_PRIORITY);     // 1

        System.out.println("high priority: " + high.getPriority());
        System.out.println("low priority: " + low.getPriority());

        high.start();
        low.start();
    }

    static class Counter implements Runnable {
        private final String name;
        Counter(String name) { this.name = name; }
        public void run() {
            for (int i = 0; i < 3; i++)
                System.out.println(name + " " + i);
        }
    }
}
How it works
  • setPriority() hints to the scheduler how urgently a thread should run.
  • Thread.MAX_PRIORITY/MIN_PRIORITY bound the valid range (10 to 1).
  • Priority is only a scheduling hint — the OS and JVM are free to interpret it differently across platforms.
  • It does not guarantee execution order, only a statistical preference for higher-priority threads.
Thread Lifecycle

A thread moves through a defined set of states during its life: New, Runnable, Blocked, Waiting, Timed-Waiting and Terminated.

A thread enters Waiting via wait() or join(), and Blocked when contending for a monitor lock. Once run() completes, the thread reaches Terminated and cannot be restarted.

Code
void main(String[] args) throws InterruptedException {
    Thread t = new Thread(() -> {
        try { Thread.sleep(100); } catch (InterruptedException e) {}
    });

    System.out.println(t.getState());   // NEW
    t.start();
    System.out.println(t.getState());   // RUNNABLE
    Thread.sleep(10);
    System.out.println(t.getState());   // TIMED_WAITING
    t.join();                            // wait for completion
    System.out.println(t.getState());   // TERMINATED
}
How it works
  • getState() reports the current Thread.State.
  • Before start() the thread is NEW.
  • sleep puts it in TIMED_WAITING.
  • After run() finishes and join() returns, it is TERMINATED.
Daemon Threads

A daemon thread is a background thread that does not prevent the JVM from exiting. The JVM shuts down once only daemon threads remain running; user (non-daemon) threads keep the JVM alive until they finish.

Daemons suit background chores like housekeeping, monitoring or garbage collection — never work that must complete or persist data, since they are abruptly stopped at JVM exit.

Code
void main(String[] args) throws InterruptedException {
    Thread monitor = new Thread(() -> {
        while (true) {                   # Endless background loop
            System.out.println("monitoring...");
            try {Thread.sleep(200);}
            catch (InterruptedException e) {return;}
        }
    });

    monitor.setDaemon(true);          # must be set before start()
    monitor.start();

    Thread.sleep(500);                 # Main is the only user thread
    System.out.println("main done, JVM exits and kills daemon");
}
How it works
  • setDaemon(true) marks the thread as background before start.
  • The daemon loops forever but does not block shutdown.
  • When main ends, no user thread remains.
  • The JVM exits and the daemon is terminated immediately.
Key points
  • Prefer implementing Runnable over extending Thread so the class can still extend something else.
  • Use setPriority() only as a scheduling hint, never to guarantee ordering.
  • Use setDaemon(true) before start() for BG work that should die automatically when the JVM exits.
  • For many short-lived tasks, prefer a thread pool / ExecutorService over raw threads.
