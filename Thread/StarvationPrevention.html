Starvation Prevention

Starvation prevention ensures every thread eventually gets the resources it needs to progress.

It counters greedy threads and unfair scheduling that indefinitely postpone others.

Fair locks grant access to the longest-waiting thread rather than an arbitrary one.

Balanced priorities and bounded critical sections also help.

When to use / Key points
  • Contended locks where some threads rarely win under load.
  • Use fair ReentrantLock or fair Semaphore for FIFO ordering.
  • Keep critical sections short so locks release quickly.
  • Avoid extreme priority differences that always favour a few threads.
Advantages
  • Guarantees progress for every waiting thread.
  • Predictable, fair acquisition order.
  • Reduces tail latency for unlucky threads.
Disadvantages / Trade-offs
  • Fairness lowers overall throughput.
  • FIFO ordering adds bookkeeping overhead.
  • Not needed for uncontended locks.
Code
public class FairAccess {
    // fair = true: longest-waiting thread acquires the lock next
    private final ReentrantLock lock = new ReentrantLock(true);

    public void access() {
        lock.lock();
        try {
            // keep this section short to free the lock quickly
            System.out.println(Thread.currentThread().getName() + " served");
        } finally {
            lock.unlock();
        }
    }
}
How it works
  • ReentrantLock(true) enforces first-come-first-served ordering.
  • No thread can be perpetually skipped over.
  • A short critical section releases the lock promptly for the next waiter.
  • unlock in finally guarantees the queue keeps moving.
