Scheduling Tasks

Spring's @Scheduled runs methods automatically on a fixed rate, fixed delay, or cron schedule.

It is enabled with @EnableScheduling and needs no external scheduler.

By default all scheduled tasks share a single thread; configure a pool for parallelism.

It is ideal for periodic jobs like cleanups, polling, and report generation.

When to use / Key points
  • Periodic maintenance: cache eviction, health polling, batch jobs.
  • fixedRate starts by clock; fixedDelay waits after completion.
  • Use cron for calendar-based schedules.
  • Configure a TaskScheduler pool so slow jobs do not block others.
Advantages
  • Declarative scheduling with no boilerplate.
  • Flexible cron, rate, and delay options.
  • No dependency on an external cron daemon.
Disadvantages / Trade-offs
  • Single-threaded by default; one long job delays the rest.
  • Not cluster-aware; runs on every instance unless coordinated.
  • Overlapping executions need explicit handling.
Code
@EnableScheduling
@Component
public class CleanupJob {

    // every 30 seconds, measured from start to start
    @Scheduled(fixedRate = 30000)
    public void pollQueue() {
        System.out.println("Polling...");
    }

    // wait 5s after each run finishes
    @Scheduled(fixedDelay = 5000)
    public void flush() {
        System.out.println("Flushing...");
    }

    // 2 AM every day
    @Scheduled(cron = "0 0 2 * * *")
    public void nightlyReport() {
        System.out.println("Nightly report");
    }
}
How it works
  • @EnableScheduling activates Spring's scheduling infrastructure.
  • fixedRate triggers on a strict interval; fixedDelay spaces runs by gap.
  • cron expresses calendar schedules with second-level precision.
