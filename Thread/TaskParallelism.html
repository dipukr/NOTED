Task Parallelism

Task parallelism runs different, independent tasks at the same time on separate threads.

Where data parallelism repeats one operation over data, task parallelism runs distinct operations.

Each task can do unrelated work and produce its own result.

Java expresses it with futures that are launched together and joined.

When to use / Key points
  • Independent operations such as fetching from several services at once.
  • Launch tasks concurrently, then combine their results.
  • CompletableFuture.allOf waits for a group to finish.
  • Best when tasks differ in nature or duration.
Advantages
  • Overlaps unrelated work to cut total latency.
  • Naturally maps to service calls and pipelines.
  • Composes cleanly with futures.
Disadvantages / Trade-offs
  • Coordination and error handling add complexity.
  • Uneven task durations leave cores idle.
  • Shared dependencies reintroduce synchronization needs.
Code
public class TaskParallel {
    public static void main(String[] args) {
        // Two different tasks run concurrently
        CompletableFuture<String> a = CompletableFuture.supplyAsync(() -> loadUser());
        CompletableFuture<String> b = CompletableFuture.supplyAsync(() -> loadStats());

        // Combine both results when ready
        String result = a.thenCombine(b, (u, s) -> u + " | " + s).join();
        System.out.println(result);
    }

    static String loadUser()  { return "user=alice"; }
    static String loadStats() { return "visits=12"; }
}
How it works

Two supplyAsync calls start distinct tasks in parallel.

thenCombine merges the two results once both complete.

join waits for the combined outcome.

The unrelated tasks overlap instead of running one after another.
