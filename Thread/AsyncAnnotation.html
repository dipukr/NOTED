Async Annotation

Spring's @Async runs a method in a separate thread so the caller returns immediately.

It must be enabled with @EnableAsync and works through Spring's proxy mechanism.

Async methods can return void, Future, or CompletableFuture.

It is the simplest way to offload work like emails or notifications in a Spring app.

When to use / Key points
  • Fire-and-forget tasks: sending email, audit logging, notifications.
  • Enable with @EnableAsync and define a dedicated executor.
  • Self-invocation is not proxied, call from another bean.
  • Return CompletableFuture when the caller needs the result later.
Advantages
  • Declarative; no manual thread management.
  • Integrates with Spring's executor configuration.
  • Keeps request threads free and responsive.
Disadvantages / Trade-offs
  • Only works on public methods invoked through the proxy.
  • Uncaught exceptions in void methods are easily lost.
  • Default SimpleAsyncTaskExecutor creates unbounded threads; configure your own.
Code
@EnableAsync
@Service
public class NotificationService {

    @Async("taskExecutor")
    public void sendEmail(String to) {
        // runs on a pool thread, caller returns at once
        System.out.println("Sending to " + to);
    }

    @Async("taskExecutor")
    public CompletableFuture<String> report(long id) {
        String result = buildReport(id);
        return CompletableFuture.completedFuture(result);
    }

    private String buildReport(long id) { return "report-" + id; }
}
How it works
  • @EnableAsync turns on proxy-based async processing for the context.
  • @Async("taskExecutor") runs the method on the named executor bean.
  • Returning CompletableFuture lets the caller compose or await the result.
