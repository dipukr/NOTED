Work-Stealing Algorithm

Work-stealing is a scheduling strategy where idle worker threads steal tasks from busy workers' queues.

Each worker owns a double-ended queue (deque) of tasks and processes its own end.

When a worker runs out of work, it steals from the opposite end of another worker's deque.

It underpins Java's Fork-Join framework and the common pool used by parallel streams.

When to use / Key points
  • Divide-and-conquer workloads that spawn many small subtasks.
  • Uneven task sizes where load must self-balance.
  • Workers push/pop their own end (LIFO); thieves take the other end (FIFO).
  • Use ForkJoinPool or Executors.newWorkStealingPool().
Advantages
  • Automatic load balancing across cores.
  • Low contention because workers mostly touch their own deque.
  • Great cache locality from LIFO on the owner's end.
Disadvantages / Trade-offs
  • Overhead is wasted if tasks are too fine-grained.
  • Stealing itself has synchronization cost.
  • Poor fit for tasks that block on I/O.
Code
void main(String[] args) throws Exception {
    // Pool sized to available cores, using work-stealing
    ExecutorService pool = Executors.newWorkStealingPool();

    for (int i = 0; i < 8; i++) {
        final int id = i;
        pool.submit(() -> {
            System.out.println("Task " + id +
                " on " + Thread.currentThread().getName());
        });
    }
    pool.shutdown();
    pool.awaitTermination(1, TimeUnit.SECONDS);
}
How it works
  • newWorkStealingPool() creates a ForkJoinPool with per-worker deques.
  • Submitted tasks are distributed and idle workers steal pending ones.
  • awaitTermination waits for all tasks to finish after shutdown.
  • Load spreads across threads without manual assignment.
