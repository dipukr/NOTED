TaskExecutor Configuration

Spring's TaskExecutor abstraction decouples code that submits work from the pool that runs it.

Configuring named executor beans lets different workloads use isolated, right-sized pools.

Isolation prevents one slow workload from starving another sharing the same threads.

Async methods and schedulers select an executor by bean name.

When to use / Key points
  • Define separate executors per workload (email, reports, imports).
  • Name beans so @Async("name") can target them.
  • Set bounded queues and explicit rejection policies.
  • Enable graceful shutdown to drain in-flight tasks.
Advantages
  • Workload isolation avoids cross-starvation.
  • Central, testable configuration.
  • Tunable per use case rather than one global pool.
Disadvantages / Trade-offs
  • More beans to manage and document.
  • Over-partitioning wastes idle threads.
  • Misnamed qualifiers silently fall back to defaults.
Code
@Configuration
public class TaskExecutors {

    @Bean("reportExecutor")
    public TaskExecutor reportExecutor() {
        return build("report-", 4, 8, 50);
    }

    @Bean("emailExecutor")
    public TaskExecutor emailExecutor() {
        return build("email-", 2, 4, 200);
    }

    private TaskExecutor build(String prefix, int core, int max, int queue) {
        ThreadPoolTaskExecutor ex = new ThreadPoolTaskExecutor();
        ex.setThreadNamePrefix(prefix);
        ex.setCorePoolSize(core);
        ex.setMaxPoolSize(max);
        ex.setQueueCapacity(queue);
        ex.setWaitForTasksToCompleteOnShutdown(true);
        ex.initialize();
        return ex;
    }
}
How it works
  • Each named bean is an isolated pool sized for its workload.
  • @Async("reportExecutor") routes a method to that specific pool.
  • setWaitForTasksToCompleteOnShutdown(true) drains work on graceful shutdown.
