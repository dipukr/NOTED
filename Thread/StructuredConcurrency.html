Structured Concurrency

Structured concurrency treats a group of related tasks as a single unit of work with a clear lifetime.

Subtasks are spawned within a scope and the scope does not return until all of them finish.

If one subtask fails, the others are cancelled, avoiding leaked or orphaned threads.

Java models this with StructuredTaskScope, introduced as a preview API.

When to use / Key points
  • Fan-out/fan-in work where a parent needs several concurrent results.
  • Scope ties subtask lifetimes to the enclosing block.
  • ShutdownOnFailure cancels siblings when one fails.
  • Errors and cancellation propagate predictably up the call tree.
Advantages
  • No leaked threads; lifetimes are scoped like local variables.
  • Cleaner error propagation and cancellation.
  • Easier reasoning than free-floating futures.
Disadvantages / Trade-offs
  • Preview API; syntax may change across JDK versions.
  • Requires a recent JDK with preview features enabled.
  • Less flexible than unstructured futures for long-lived tasks.
Code
// Preview API: run two subtasks, fail fast if either fails
public class Aggregator {
    String load() throws Exception {
        try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
            Subtask<String> user  = scope.fork(() -> fetchUser());
            Subtask<String> order = scope.fork(() -> fetchOrder());

            scope.join();               // wait for both
            scope.throwIfFailed();      // propagate any error

            return user.get() + " / " + order.get();
        }
    }

    String fetchUser()  { return "alice"; }
    String fetchOrder() { return "#42"; }
}
How it works
  • fork starts each subtask concurrently within the scope.
  • join blocks until every forked subtask completes.
  • throwIfFailed cancels siblings and rethrows on any failure.
  • The try-with-resources scope guarantees no thread outlives the block.
