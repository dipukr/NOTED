Phaser Coordination

Phaser is a flexible, reusable synchronization barrier introduced in Java 7.

It combines features of CountDownLatch and CyclicBarrier and supports a dynamic number of parties.

Parties can register and deregister at runtime, and it advances through numbered phases.

It suits multi-phase algorithms where the participant count changes between phases.

When to use / Key points
  • Multi-stage parallel algorithms where each stage is a phase.
  • When the number of participating threads varies dynamically.
  • arriveAndAwaitAdvance() waits for all parties at the phase boundary.
  • register()/arriveAndDeregister() adjust party count on the fly.
Advantages
  • Reusable across many phases, unlike CountDownLatch.
  • Dynamic registration, unlike the fixed CyclicBarrier.
  • Supports tiered phasers to reduce contention.
Disadvantages / Trade-offs
  • More complex API than a latch or barrier.
  • Overkill for simple one-shot coordination.
  • Phase-number overflow after ~2 billion phases needs care.
Code
public class PipelineStage {

    public void runStages(int workers, int phases) {
        Phaser phaser = new Phaser(1); // register self

        for (int i = 0; i < workers; i++) {
            phaser.register(); // add a party
            final int id = i;
            new Thread(() -> {
                for (int p = 0; p < phases; p++) {
                    doPhaseWork(id, p);
                    // wait for all before next phase
                    phaser.arriveAndAwaitAdvance();
                }
                phaser.arriveAndDeregister();
            }).start();
        }
        phaser.arriveAndDeregister(); // main leaves
    }

    private void doPhaseWork(int id, int phase) { /* ... */ }
}
How it works
  • register() adds a party dynamically for each worker thread.
  • arriveAndAwaitAdvance() blocks until every registered party reaches the phase.
  • arriveAndDeregister() removes a party when a thread is finished.
