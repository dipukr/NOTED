Runnable Interface

Runnable is a functional interface representing a task with a single run() method.

It separates the work to be done from the thread that runs it.

Because it is functional, a Runnable can be written as a lambda.

It carries no return value and throws no checked exceptions, unlike Callable.

When to use / Key points
  • Any fire-and-forget task with no result.
  • Pass to a Thread or submit to an ExecutorService.
  • Prefer over extending Thread to preserve inheritance.
  • Use Callable instead when you need a result or checked exception.
Pros and Cons
Decouples Task and Execution

It separates the task logic from the mechanism that runs it.

Concise Syntax

It can be written concisely as a lambda or method reference.

Reusable Across Executors

The same instance is reusable across threads and executors.

No Return Value

It cannot return a value directly from its task.

No Checked Exceptions

It cannot throw checked exceptions from the run() method.

Relies On Shared State

Any result must be communicated back via shared state.

Code
void main(String[] args) {
    // Runnable as a lambda: no result, no checked exception
    Runnable job = () -> {
        System.out.println("running on " + Thread.currentThread().getName());
    };

    // Run on a dedicated thread
    new Thread(job).start();

    // Or submit to an executor
    ExecutorService pool = Executors.newSingleThreadExecutor();
    pool.execute(job);
    pool.shutdown();
}
How it works

The lambda implements run() as the task body.

new Thread(job).start() runs it on a new thread.

execute(job) hands the same task to a pool thread.

The identical Runnable works with both mechanisms.
