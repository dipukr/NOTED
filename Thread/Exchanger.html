Exchanger Data Swap

Exchanger is a synchronization point where two threads swap objects with each other.

Each thread calls exchange() and receives the object offered by the other thread.

The first thread to arrive blocks until its partner arrives, then both proceed.

It is a specialized rendezvous for exactly two parties.

When to use / Key points
  • Producer-consumer buffer swapping (fill one buffer while draining another).
  • Pipeline handoff between exactly two threads.
  • exchange(x, timeout, unit) avoids waiting forever.
  • Strictly two-party; use a barrier or queue for more.
Advantages
  • Clean, allocation-free handoff of data between two threads.
  • Built-in bidirectional swap in a single call.
  • Enables efficient double-buffering.
Disadvantages / Trade-offs
  • Limited to exactly two threads.
  • A missing partner blocks indefinitely without a timeout.
  • Rarely needed compared to queues.
Code
public class DoubleBuffer {

    private final Exchanger<List<String>> exchanger = new Exchanger<>();

    public void producer() throws InterruptedException {
        List<String> buffer = new ArrayList<>();
        while (true) {
            buffer.add("item");
            if (buffer.size() == 10) {
                // swap full buffer for an empty one
                buffer = exchanger.exchange(buffer);
            }
        }
    }

    public void consumer() throws InterruptedException {
        List<String> empty = new ArrayList<>();
        while (true) {
            List<String> full = exchanger.exchange(empty);
            full.forEach(System.out::println);
            full.clear();
            empty = full;
        }
    }
}
How it works
  • Both threads meet at exchange() and trade their buffers atomically.
  • The producer gets an empty buffer back; the consumer gets the full one.
  • The first to arrive blocks until its partner reaches the exchange point.
