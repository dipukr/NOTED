Wait-Notify Methods

wait(), notify() and notifyAll() are the low-level object monitor methods for thread coordination.

A thread goes to the waiting state once it calls wait() on an object and stays there until another thread calls notify() or notifyAll().

They must be called while holding the object's monitor, i.e. inside a synchronized block.

They form the basis of the classic producer-consumer pattern.

When to use / Key points
  • Always call inside synchronized on the same monitor object.
  • Always wait in a while loop that re-checks the condition (guards spurious wakeups).
  • Prefer notifyAll() unless you are certain one waiter suffices.
  • For new code prefer higher-level tools like BlockingQueue or Condition.
Advantages
  • Built into every object; no extra imports.
  • Releases the monitor while waiting, allowing others to proceed.
  • Foundation for understanding higher-level concurrency utilities.
Disadvantages / Trade-offs
  • Error-prone: missing the while guard leads to subtle bugs.
  • A missed notify() can leave a thread waiting forever.
  • Only one condition per monitor, unlike Lock with multiple Conditions.
Code
public class Buffer {

    private final java.util.Queue<Integer> q = new java.util.LinkedList<>();
    private final int capacity = 10;

    public synchronized void put(int item) throws InterruptedException {
        while (q.size() == capacity) {
            wait(); // releases monitor, waits for space
        }
        q.add(item);
        notifyAll(); // wake consumers
    }

    public synchronized int take() throws InterruptedException {
        while (q.isEmpty()) {
            wait(); // wait for a producer
        }
        int item = q.remove();
        notifyAll(); // wake producers
        return item;
    }
}
How it works
  • wait() releases the monitor and parks the thread until notified.
  • The while loop re-checks the condition to handle spurious wakeups.
  • notifyAll() wakes all waiters so both producers and consumers re-evaluate.
