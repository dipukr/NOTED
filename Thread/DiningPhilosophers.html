Dining Philosophers Problem

The Dining Philosophers problem is a classic synchronization problem illustrating deadlock and resource contention.

Five philosophers sit around a table, each needing two shared forks (one on each side) to eat.

If every philosopher grabs their left fork simultaneously, all wait forever for the right fork, causing deadlock.

It models the challenge of allocating multiple shared resources without deadlock or starvation.

Key points
  • Study scenario for deadlock, livelock and starvation in resource allocation.
  • Deadlock needs mutual exclusion, hold-and-wait, no preemption and circular wait to all hold.
  • Common fixes: enforce a global lock ordering, use a waiter/arbitrator, or limit concurrent diners.
  • Applicable to any system where an actor must hold several locks at once.
Advantages
Breaks Circular Wait

It teaches concrete strategies for breaking the circular-wait condition.

Provably Deadlock-Free

The resource-ordering solution is simple and provably deadlock-free.

Concurrency Versus Safety

It highlights the trade-off between concurrency and safety.

Disadvantages
Reduced Parallelism

Strict lock ordering can reduce parallelism.

Risk Of Starvation

Naive solutions can trade deadlock for starvation of some philosophers.

Central Bottleneck

Arbitrator solutions add a central bottleneck.

Code
# Break circular wait by always locking the lower-id fork first
public class Philosopher implements Runnable {
    private final Object left;
    private final Object right;
    private final int id;

    public Philosopher(int id, Object left, Object right) {
        this.id = id;
        this.left = left;
        this.right = right;
    }

    public void run() {
        Object first = System.identityHashCode(left) <
                   System.identityHashCode(right) ? left : right;
        Object second = (first == left) ? right : left;
        synchronized (first) {
            synchronized (second) {
                System.out.println("Philosopher " + id + " is eating");
            }
        }
    }
}
How it works

synchronized acquires each fork's intrinsic monitor lock.

Ordering by identityHashCode gives a global lock order for every philosopher.

Because no one ever waits while holding a higher-ordered lock, circular wait cannot form.

This eliminates deadlock without a central arbitrator.
