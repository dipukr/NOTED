Deadlock

A deadlock occurs when there is more than one thread, each waiting for a resource held by another. It happens when multiple threads acquire the same set of locks in different orders.

The most obvious kind of resource is an object monitor, but any resource that causes blocking (such as wait-notify) can qualify. Deadlock happens when two or more threads become interlocked: Thread A holds the lock on object1 but is waiting on object2, while Thread B holds the lock on object2 but is waiting on object1.

Code
// DEADLOCK: threads lock A and B in opposite orders
void main() {
    Object a = new Object(), b = new Object();

    Thread t1 = new Thread(() -> {
        synchronized (a) {
            synchronized (b) { /* work */ }
        }
    });
    Thread t2 = new Thread(() -> {
        synchronized (b) {          // reversed order!
            synchronized (a) { /* work */ }
        }
    });

    t1.start();
    t2.start();
    // FIX: both threads should lock a THEN b (consistent order)
}
How it deadlocks

t1 holds a and waits for b.

t2 holds b and waits for a: circular wait.

Neither can proceed, so both block permanently.

Enforcing one global lock order (a then b) removes the cycle.

Deadlock Avoidance

Avoidance breaks one of the four Coffman conditions that deadlock requires: mutual exclusion, hold-and-wait, no preemption, and circular wait.

The most practical technique is imposing a consistent global lock ordering; another is using tryLock with a timeout so a thread backs off and retries instead of blocking forever.

Code
public class Transfer {
    // tryLock with timeout avoids waiting forever
    boolean move(ReentrantLock a, ReentrantLock b) throws InterruptedException {
        if (a.tryLock(1, TimeUnit.SECONDS)) {
            try {
                if (b.tryLock(1, TimeUnit.SECONDS)) {
                    try { /* do transfer */ return true; }
                    finally { b.unlock(); }
                }
            } finally { a.unlock(); }
        }
        return false;   // could not get both; caller retries
    }
}
How it works

tryLock(timeout) gives up rather than blocking indefinitely.

If the second lock is unavailable, the first is released in finally.

Returning false lets the caller back off and retry.

No thread holds one lock while waiting forever for another.

When to use / Key points
  • Any code that acquires more than one lock at a time.
  • Deadlock needs mutual exclusion, hold-and-wait, no preemption and circular wait.
  • Break circular wait with a fixed ordering of lock acquisition.
  • Use tryLock with timeout to back off and retry.
Advantages
  • Lock ordering is simple and provably deadlock-free.
  • tryLock lets threads recover instead of hanging.
  • Fewer, coarser locks reduce ordering complexity.
Disadvantages / Trade-offs
  • Global ordering can be hard to maintain in large codebases.
  • tryLock retry loops can cause livelock if unthrottled.
  • Coarser locks lower concurrency.
