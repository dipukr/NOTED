Performance Tuning

Concurrency performance tuning is about maximizing throughput while minimizing contention and latency.

The main levers are thread pool sizing, lock granularity, and reducing shared mutable state.

CPU-bound work scales with core count; I/O-bound work benefits from more threads.

Always measure with a profiler before and after any change.

When to use / Key points
  • Size CPU pools near availableProcessors(); size I/O pools higher.
  • Reduce lock scope and prefer lock-free atomics where possible.
  • Use striped or partitioned data to cut contention.
  • Profile first; never optimize on a guess.
Advantages
  • Higher throughput and lower response times.
  • Better hardware utilization across cores.
  • Fewer thread stalls and context switches.
Disadvantages / Trade-offs
  • Premature tuning adds complexity for little gain.
  • Over-threading causes context-switch thrashing.
  • Micro-optimizations can hurt readability and correctness.
Code
public class PoolSizing {

    // CPU-bound: threads ~ cores
    public ExecutorService cpuPool() {
        int cores = Runtime.getRuntime().availableProcessors();
        return Executors.newFixedThreadPool(cores);
    }

    // I/O-bound: size by Little's Law
    public ExecutorService ioPool(double waitFraction) {
        int cores = Runtime.getRuntime().availableProcessors();
        // threads = cores * (1 + wait/compute)
        int threads = (int) (cores * (1 + waitFraction));
        return Executors.newFixedThreadPool(Math.max(cores, threads));
    }
}
How it works

availableProcessors() anchors CPU pool size to real core count.

The I/O formula adds threads proportional to wait time so cores stay busy.

Bounding the pool prevents excessive context switching.
