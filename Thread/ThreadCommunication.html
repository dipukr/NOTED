Thread Communication

Thread communication (cooperation) lets threads coordinate so one can wait for another to reach a state.

It is achieved with the wait-set associated with an object's monitor and the wait-notify mechanism.

A thread calling wait releases the lock and suspends until another thread signals.

notify or notifyAll wakes waiting threads to re-check their condition.

When to use / Key points
  • When one thread must wait for data another thread will produce.
  • wait, notify, notifyAll require owning the object's monitor.
  • Always call wait inside a loop that re-checks the condition (spurious wakeups).
  • Prefer notifyAll unless you can prove one waiter suffices.
Advantages
  • Avoids busy waiting by suspending idle threads.
  • Built into every Java object's monitor.
  • Foundation for producer-consumer and other patterns.
Disadvantages / Trade-offs
  • Easy to misuse: missed signals and lost notifications.
  • Must hold the monitor or an IllegalMonitorStateException is thrown.
  • Higher-level constructs like BlockingQueue are usually safer.
Code
public class SignalBox {
    private boolean dataReady = false;

    public synchronized void awaitData() throws InterruptedException {
        while (!dataReady) {
            wait();          // release lock, wait for notify
        }
        System.out.println("data received");
    }

    public synchronized void publish() {
        dataReady = true;
        notifyAll();         // wake all waiting threads
    }
}
How it works
  • wait() releases the monitor and parks the thread in the wait-set.
  • The while loop re-checks dataReady after each wakeup.
  • notifyAll() moves waiters back to the entry-set to reacquire the lock.
  • Both methods are synchronized so the monitor is always owned.
