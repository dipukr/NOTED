Daemon Threads

A daemon thread is a background thread that does not prevent the JVM from exiting.

The JVM shuts down once only daemon threads remain running.

User (non-daemon) threads keep the JVM alive until they finish.

Daemons suit background chores like housekeeping, monitoring or garbage collection.

When to use / Key points
  • Background services that should die with the application.
  • Call setDaemon(true) before start().
  • Daemons are abruptly stopped at JVM exit, running no further code.
  • Never use daemons for work that must complete or persist data.
Advantages
  • Do not block JVM shutdown.
  • Ideal for supporting/background tasks.
  • No need to track and join them at exit.
Disadvantages / Trade-offs
  • Killed mid-work without cleanup at shutdown.
  • finally blocks may not run on exit.
  • Unsafe for writing files or releasing external resources.
Code
public class DaemonDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread monitor = new Thread(() -> {
            while (true) {                   // endless background loop
                System.out.println("monitoring...");
                try { Thread.sleep(200); } catch (InterruptedException e) { return; }
            }
        });

        monitor.setDaemon(true);          // must be set before start()
        monitor.start();

        Thread.sleep(500);                 // main is the only user thread
        System.out.println("main done, JVM exits and kills daemon");
    }
}
How it works
  • setDaemon(true) marks the thread as background before start.
  • The daemon loops forever but does not block shutdown.
  • When main ends, no user thread remains.
  • The JVM exits and the daemon is terminated immediately.
