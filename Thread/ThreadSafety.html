Thread Safety

Thread safety means a class behaves correctly when accessed from multiple threads at once.

When multiple threads modify a shared resource simultaneously the outcome is non-deterministic unless access is synchronized.

Read-read sharing is safe, but read-write and write-write races cause memory inconsistencies.

It is achieved through confinement, immutability, synchronization, or thread-safe libraries.

When to use / Key points
  • Prefer immutability and confinement before reaching for locks.
  • Guard all access to shared mutable state, not just writes.
  • Use ConcurrentHashMap and other concurrent collections.
  • Local primitives are safe; shared heap references are not.
Advantages
  • Correct results under concurrency, no corrupted state.
  • Prevents race conditions and visibility bugs.
  • Enables safe scaling across cores.
Disadvantages / Trade-offs
  • Synchronization adds latency and contention.
  • Over-locking can serialize an otherwise parallel program.
  • Subtle bugs are hard to reproduce and test.
Code
public class WordStats {

    // thread-safe map, no external lock needed
    private final ConcurrentHashMap<String, LongAdder> counts =
            new ConcurrentHashMap<>();

    public void record(String word) {
        // atomic get-or-create then atomic increment
        counts.computeIfAbsent(word, k -> new LongAdder()).increment();
    }

    public long count(String word) {
        LongAdder a = counts.get(word);
        return a == null ? 0 : a.sum();
    }
}
How it works
  • ConcurrentHashMap allows concurrent reads and segmented writes safely.
  • computeIfAbsent atomically inserts the adder only once per key.
  • LongAdder.increment() scales better than a locked counter under contention.
