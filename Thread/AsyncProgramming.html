Asynchronous Programming

Asynchronous programming lets work start and complete without blocking the calling thread.

Synchronous is sequential; asynchronous is non-sequential, using callbacks or futures for results.

The main purpose is to avoid blocking so threads stay free for other work.

Java's CompletableFuture composes async steps declaratively.

When to use / Key points
  • I/O-bound work such as network calls, disk and database access.
  • When you want to chain dependent steps without blocking threads.
  • thenApply, thenCompose and thenCombine build pipelines.
  • Handle failures with exceptionally or handle.
Advantages
Higher Throughput

Threads are not blocked on I/O, so the system handles more work concurrently.

Declarative Composition

Multi-step workflows can be composed declaratively into readable pipelines.

Better Resource Use

It uses resources more efficiently than a one-thread-per-request model.

Disadvantages
Harder To Debug

Asynchronous code is harder to read and debug than sequential code.

Complex Callback Chains

Callback chains can become complex and exceptions propagate subtly.

Thread Pool Management

It requires care about which thread pool runs each stage.

Code
public class AsyncDemo {
    public static void main(String[] args) {
        CompletableFuture
            .supplyAsync(() -> fetchPrice())      // runs on a pool thread
            .thenApply(p -> p * 1.1)              // transform result
            .thenAccept(p -> System.out.println("Total: " + p))
            .exceptionally(ex -> {                // handle failure
                System.out.println("failed: " + ex.getMessage());
                return null;
            });
    }

    static double fetchPrice() { return 100.0; }
}
How it works

supplyAsync runs the task on a background thread and returns a future.

thenApply transforms the value when it becomes available.

thenAccept consumes the final result without blocking the caller.

exceptionally supplies a fallback if any stage throws.
