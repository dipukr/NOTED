Busy Waiting

Busy waiting (spinning) is when a thread repeatedly checks a condition in a tight loop instead of blocking.

It keeps the CPU fully occupied while waiting, wasting cycles.

The alternative is to suspend the thread and be woken by a signal such as wait-notify.

Spinning is only worthwhile when the wait is expected to be extremely short.

When to use / Key points
  • Only for very brief waits where a context switch costs more than spinning.
  • Prefer wait/notify, locks or blocking queues for anything longer.
  • Spin loops on plain fields need volatile for visibility.
  • Low-level spin locks are used inside JVM and OS internals.
Pros and Cons
No Wakeup Latency

Avoids context-switch and wakeup latency for ultra-short waits.

Simple To Write

It is simple to write for a quick prototype.

Lower Latency

Can be lower latency on lightly loaded multi-core systems.

Wastes CPU

Wastes CPU and drains power while spinning.

Starves Threads

Starves other threads that could use the core.

Stale Cached Value

Missing volatile can loop forever on a cached value.

Code
public class SpinVsBlock {
    // volatile ensures the flag change is visible across threads
    private volatile boolean ready = false;

    public void busyWait() {
        while (!ready) {
            // spin: burns CPU until another thread sets ready
        }
        System.out.println("proceeding");
    }

    public synchronized void blockingWait() throws InterruptedException {
        while (!ready) {
            wait();     // releases lock, sleeps until notified
        }
    }

    public synchronized void signal() {
        ready = true;
        notifyAll();
    }
}
How it works

busyWait spins on ready, consuming the CPU.

volatile forces each read to see the latest value.

blockingWait uses wait() to sleep and free the CPU.

notifyAll() wakes blocked waiters without any spinning.
