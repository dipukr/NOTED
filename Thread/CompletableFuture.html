CompletableFuture Async

CompletableFuture (Java 8+) represents an asynchronous computation that can be composed and chained.

It implements Future and CompletionStage, enabling non-blocking pipelines.

Callbacks like thenApply, thenCompose and thenCombine run when results become available.

It handles errors with exceptionally and handle without blocking.

When to use / Key points
  • Compose multiple async calls without nested callbacks.
  • Run independent tasks in parallel and combine results.
  • Always supply an explicit Executor for I/O-bound work.
  • Avoid blocking with get() inside async pipelines.
Pros and Cons
Fluent Composition

Dependent and independent tasks can be composed together in a readable, chained pipeline.

Non-Blocking Callbacks

Callbacks run without blocking and error handling is built directly into the pipeline.

Combine Many Futures

Multiple futures can be combined with allOf and anyOf.

Default Pool Pitfall

It defaults to the common ForkJoinPool, which is a poor fit for blocking I/O.

Hard To Debug

Deep chains can be difficult to debug and read.

Wrapped Exceptions

Exceptions are wrapped in a CompletionException.

API Reference
static <U> CompletableFuture<U> completedFuture(U value)

Wraps an already-known value in a future that is done immediately, useful as a default or a cache hit.

CompletableFuture<String> cached = CompletableFuture.completedFuture("cached-value");
CompletableFuture<String> cf = cache.containsKey(id) ? cached : loadAsync(id);
static CompletableFuture<Void> runAsync(Runnable r)

Runs a fire-and-forget task with no return value on the common ForkJoinPool.

CompletableFuture<Void> cf = CompletableFuture.runAsync(() -> {
    auditLog.write("user logged in");
});
cf.join(); // wait for the audit write to finish
static CompletableFuture<Void> runAsync(Runnable r, Executor e)

Same as runAsync, but the task runs on the executor you supply instead of the common pool.

ExecutorService ioPool = Executors.newFixedThreadPool(4);
CompletableFuture.runAsync(() -> writeToDisk(payload), ioPool);
static <U> CompletableFuture<U> supplyAsync(Supplier<U> s)

Runs a value-returning task asynchronously on the common pool and completes the future with its result.

CompletableFuture<Integer> cf = CompletableFuture.supplyAsync(() -> {
    // expensive computation on the common pool
    return compute(42);
});
static <U> CompletableFuture<U> supplyAsync(Supplier<U> s, Executor e)

Same as supplyAsync, but the task runs on the given executor rather than the common pool.

ExecutorService dbPool = Executors.newFixedThreadPool(8);
CompletableFuture<User> cf = CompletableFuture.supplyAsync(
    () -> userRepository.findById(id), dbPool);
<U> CompletableFuture<U> thenApply(Function<? super T,? extends U> fn)

Transforms the result into a new value once it arrives, similar to Stream.map.

CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "order-42")
    .thenApply(String::toUpperCase)
    .thenApply(s -> s + " [READY]");
CompletableFuture<Void> thenAccept(Consumer<? super T> a)

Consumes the result for a side effect (like printing or saving) without producing a new value.

CompletableFuture.supplyAsync(() -> orderService.place(request))
    .thenAccept(order -> log.info("placed order {}", order.id()));
CompletableFuture<Void> thenRun(Runnable r)

Runs an action after completion while ignoring the result entirely, useful for cleanup or notifications.

CompletableFuture.supplyAsync(() -> saveReport(report))
    .thenRun(() -> notificationService.notifyAdmins());
<U> CompletableFuture<U> thenCompose(Function<? super T,? extends CompletionStage<U>> fn)

Chains a dependent asynchronous call and flattens the nested future, avoiding CompletableFuture<CompletableFuture<T>>.

CompletableFuture<Integer> count = fetchUserAsync(id)
    .thenCompose(u -> fetchOrdersAsync(u.id())) // flattened, not nested
    .thenApply(orders -> orders.size());
<U,V> CompletableFuture<V> thenCombine(CompletionStage<U> other, BiFunction<T,U,V> fn)

Waits for two independent futures and merges their results with the given function once both finish.

CompletableFuture<User> user = fetchUserAsync(id);
CompletableFuture<Stock> stock = fetchStockAsync(sku);
CompletableFuture<String> summary =
    user.thenCombine(stock, (u, s) -> u.name() + " has " + s.qty());
static CompletableFuture<Void> allOf(CompletableFuture<?>... cfs)

Completes only once every supplied future completes; join each one afterward to collect their results.

CompletableFuture<Void> f1 = sendEmail(order);
CompletableFuture<Void> f2 = updateInventory(order);
CompletableFuture<Void> f3 = chargeCard(order);
CompletableFuture.allOf(f1, f2, f3).join(); // waits for all three
static CompletableFuture<Object> anyOf(CompletableFuture<?>... cfs)

Completes as soon as the first of the supplied futures completes, carrying that future’s value.

CompletableFuture<String> primary = fetchFromPrimary();
CompletableFuture<String> mirror = fetchFromMirror();
Object fastest = CompletableFuture.anyOf(primary, mirror).join();
CompletableFuture<T> exceptionally(Function<Throwable,? extends T> fn)

Recovers from a failure by supplying a fallback value, without affecting a successful result.

CompletableFuture<String> cf = fetchProfile(id)
    .exceptionally(ex -> {
        log.warn("profile fetch failed: {}", ex.getMessage());
        return "anonymous";
    });
<U> CompletableFuture<U> handle(BiFunction<? super T, Throwable, ? extends U> fn)

Processes either the result or the exception, whichever occurred, and always runs regardless of outcome.

CompletableFuture<Response> cf = callRemoteService(request)
    .handle((res, ex) -> ex != null
        ? Response.error(ex.getMessage())
        : Response.ok(res));
CompletableFuture<T> whenComplete(BiConsumer<? super T, ? super Throwable> a)

Peeks at the result or exception for logging or metrics, without changing what the future ultimately carries.

callPaymentGateway(order)
    .whenComplete((res, ex) -> {
        metrics.recordLatency("payment");
        if (ex != null) alerting.notify(ex);
    });
boolean complete(T value)

Completes the future manually with the given value if it is not already done; returns true only if this call did it.

CompletableFuture<String> cf = new CompletableFuture<>();
listener.onDataReceived(data -> cf.complete(data)); // completed from a callback
String result = cf.get(); // blocks until complete() is called
boolean completeExceptionally(Throwable ex)

Completes the future manually with a failure, propagating the exception to every dependent stage.

CompletableFuture<Response> cf = new CompletableFuture<>();
watchdog.onTimeout(() -> cf.completeExceptionally(
    new TimeoutException("gateway timed out")));
CompletableFuture<T> completeOnTimeout(T value, long timeout, TimeUnit unit)

Falls back to the given default value if the future has not completed within the timeout (Java 9+).

CompletableFuture<Config> cf = fetchRemoteConfig()
    .completeOnTimeout(Config.defaults(), 2, TimeUnit.SECONDS);
applyConfig(cf.join());
CompletableFuture<T> orTimeout(long timeout, TimeUnit unit)

Fails the future with a TimeoutException if it has not completed within the given time (Java 9+).

CompletableFuture<Price> cf = fetchLivePrice(symbol)
    .orTimeout(500, TimeUnit.MILLISECONDS)
    .exceptionally(ex -> Price.lastKnown(symbol));
boolean cancel(boolean mayInterruptIfRunning)

Attempts to cancel the future, completing it exceptionally with a CancellationException.

CompletableFuture<Report> cf = generateReportAsync(query);
if (userClosedTab) {
    cf.cancel(true);
}
T get()

Blocks the calling thread until the result is available, throwing checked InterruptedException or ExecutionException.

CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "data");
try {
    String result = cf.get(); // blocks here
} catch (InterruptedException | ExecutionException e) {
    throw new RuntimeException(e);
}
T get(long timeout, TimeUnit unit)

Blocks like get(), but gives up and throws TimeoutException after the specified duration.

try {
    String result = cf.get(3, TimeUnit.SECONDS);
} catch (TimeoutException e) {
    result = "fallback";
}
T join()

Blocks until the result is available like get(), but throws an unchecked CompletionException on failure.

List<String> names = ids.stream()
    .map(id -> fetchNameAsync(id)) // returns futures
    .map(CompletableFuture::join) // blocks per future, in order
    .toList();
T getNow(T valueIfAbsent)

Returns the result immediately without blocking, or the given fallback if the future is not yet complete.

CompletableFuture<String> cf = startBackgroundRefresh();
String value = cf.getNow(cachedValue); // non-blocking read
boolean isDone(), isCancelled(), isCompletedExceptionally()

Non-blocking checks that report whether the future has finished, was cancelled, or failed.

if (poll.isDone()) {
    if (poll.isCompletedExceptionally()) {
        handleFailure();
    } else {
        handleResult(poll.getNow(null));
    }
}
Most stage-transforming methods above (thenApply, thenAccept, thenRun, thenCompose, handle, whenComplete…) also have *Async and *Async(…, Executor) forms for explicit thread control.
Code
public class OrderService {

    private final ExecutorService pool;

    public OrderService(ExecutorService pool) {
        this.pool = pool;
    }

    public CompletableFuture<String> placeOrder(long id) {
        CompletableFuture<String> user =
                CompletableFuture.supplyAsync(() -> loadUser(id), pool);
        CompletableFuture<String> stock =
                CompletableFuture.supplyAsync(() -> checkStock(id), pool);

        return user.thenCombine(stock, (u, s) -> u + " / " + s)
                   .thenApply(String::toUpperCase)
                   .exceptionally(ex -> "FAILED: " + ex.getMessage());
    }

    private String loadUser(long id) { return "user"; }
    private String checkStock(long id) { return "in-stock"; }
}
How it works

supplyAsync(..., pool) runs each task on the provided executor in parallel.

thenCombine merges the two results once both complete.

exceptionally converts any failure into a fallback value without throwing.
