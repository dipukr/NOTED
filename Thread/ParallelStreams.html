Parallel Streams

Parallel streams split a stream's elements across threads to process them concurrently.

They run on the shared Fork-Join common pool using work-stealing.

You enable them by calling parallel() or parallelStream().

They shine on large data with cheap splitting and expensive per-element work.

When to use / Key points
  • Large collections with independent, CPU-bound element work.
  • Operations must be stateless, associative and side-effect-free.
  • Use array or ArrayList sources that split evenly.
  • Measure; parallel is not always faster than sequential.
Advantages
  • One call to parallelise existing stream code.
  • Automatic splitting and result merging.
  • Scales with cores for suitable workloads.
Disadvantages / Trade-offs
  • Overhead can make small streams slower.
  • Shares one common pool across the whole JVM.
  • Ordering and stateful ops reduce or lose gains.
Code
public class ParallelDemo {
    public static void main(String[] args) {
        // Parallel reduction over a large range
        long primes = LongStream.rangeClosed(2, 1_000_000)
            .parallel()                     // split across pool threads
            .filter(ParallelDemo::isPrime)
            .count();

        System.out.println("primes = " + primes);
    }

    static boolean isPrime(long n) {
        for (long i = 2; i * i <= n; i++) if (n % i == 0) return false;
        return true;
    }
}
How it works
  • parallel() marks the stream for concurrent processing.
  • The range is split into sub-ranges filtered on separate workers.
  • count is associative, so partial counts sum correctly.
  • The Fork-Join common pool schedules the chunks.
