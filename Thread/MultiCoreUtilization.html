Multi-core Utilization

Multi-core utilization means spreading work across all available CPU cores to run tasks in true parallel.

Parallelism is about doing multiple tasks at once, which needs multiple cores.

Sizing thread pools to the core count avoids both under-use and oversubscription.

Runtime.availableProcessors() reports the cores the JVM can use.

When to use / Key points
  • CPU-bound work that can be split into independent chunks.
  • Size compute pools near the number of cores.
  • I/O-bound work can use more threads than cores.
  • Avoid excessive threads that cause context-switch overhead.
Advantages
  • Near-linear speedup for parallelizable work.
  • Better hardware ROI by using all cores.
  • Lower wall-clock time for large computations.
Disadvantages / Trade-offs
  • Amdahl's law caps speedup by the serial fraction.
  • Shared-state contention can erase gains.
  • Oversubscription adds context-switching cost.
Code
public class CoreBound {
    public static void main(String[] args) throws Exception {
        int cores = Runtime.getRuntime().availableProcessors();
        System.out.println("cores = " + cores);

        // One worker per core for CPU-bound work
        ExecutorService pool = Executors.newFixedThreadPool(cores);
        for (int i = 0; i < cores; i++) {
            pool.submit(() -> heavyCompute());
        }
        pool.shutdown();
    }

    static long heavyCompute() { long s = 0; for (int i = 0; i < 1_000_000; i++) s += i; return s; }
}
How it works
  • availableProcessors() reports usable cores.
  • A fixed pool of that size keeps every core busy without oversubscribing.
  • Each submitted task runs on its own core in parallel.
  • shutdown lets the compute tasks drain and finish.
