Job-Scheduling Algorithm

Job scheduling decides when and in what order tasks run, often on a recurring or delayed basis.

Schedulers manage priorities, delays, fixed rates and fixed delays for background work.

Java offers ScheduledExecutorService for time-based task execution.

Good scheduling maximises throughput while respecting deadlines and resource limits.

When to use / Key points
  • Recurring maintenance jobs, polling, timeouts and cron-like tasks.
  • scheduleAtFixedRate fires on a fixed period regardless of task duration.
  • scheduleWithFixedDelay waits a gap after each task completes.
  • Pick a pool size that matches concurrent scheduled jobs.
Advantages
  • Centralised, reusable timing without manual sleep loops.
  • Thread pool prevents thread-per-timer explosion.
  • Supports both one-shot and periodic scheduling.
Disadvantages / Trade-offs
  • Fixed-rate tasks can pile up if they run longer than the period.
  • An uncaught exception silently cancels a periodic task.
  • Not a distributed scheduler; single-JVM only.
Code
public class Scheduler {
    public static void main(String[] args) {
        ScheduledExecutorService ses = Executors.newScheduledThreadPool(2);

        // Run once after a 2 second delay
        ses.schedule(() -> System.out.println("one-shot"),
                     2, TimeUnit.SECONDS);

        // Run every 3 seconds at a fixed rate
        ses.scheduleAtFixedRate(
            () -> System.out.println("heartbeat"),
            0, 3, TimeUnit.SECONDS);
    }
}
How it works
  • newScheduledThreadPool creates a pool for timed tasks.
  • schedule runs a task once after a delay.
  • scheduleAtFixedRate repeats on a fixed period.
  • Tasks share pool threads instead of one timer per job.
