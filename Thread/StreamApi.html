Stream API

The Stream API processes collections declaratively with a pipeline of operations.

You describe the desired outcome instead of writing explicit loops.

Intermediate operations are lazy; a terminal operation triggers execution.

The same pipeline can run sequentially or in parallel.

When to use / Key points
  • Transforming, filtering and aggregating collections.
  • Intermediate ops (map, filter) are lazy and chainable.
  • Terminal ops (collect, reduce, forEach) run the pipeline.
  • Prefer stateless, side-effect-free lambdas.
Advantages
  • Concise, readable declarative code.
  • Lazy evaluation can skip unnecessary work.
  • Trivial switch to parallel execution.
Disadvantages / Trade-offs
  • Streams are single-use and not reusable.
  • Debugging pipelines is harder than loops.
  • Side effects in lambdas break the model.
Code
public class StreamDemo {
    public static void main(String[] args) {
        List<String> names = List.of("alice", "bob", "amir", "cara");

        List<String> result = names.stream()
            .filter(n -> n.startsWith("a"))   // lazy intermediate
            .map(String::toUpperCase)         // lazy intermediate
            .sorted()
            .collect(Collectors.toList());  // terminal: runs pipeline

        System.out.println(result);          // [ALICE, AMIR]
    }
}
How it works
  • stream() creates a pipeline over the list.
  • filter and map are lazy and only describe steps.
  • collect is the terminal op that executes the whole pipeline.
  • Each element flows through the chain one pass at a time.
