Thread Lifecycle

A thread moves through a defined set of states during its life.

The states are New, Runnable, Blocked, Waiting, Timed-waiting and Terminated.

A thread enters Waiting via wait() or join(), and Blocked when contending for a monitor lock.

Once run() completes, the thread reaches Terminated and cannot restart.

When to use / Key points
  • New: created but start() not yet called.
  • Runnable: running or ready, waiting for CPU allocation.
  • Blocked: waiting to acquire a monitor lock for a synchronized section.
  • Waiting/Timed-waiting: awaiting a signal, optionally with a timeout; Terminated: finished.
Advantages
  • A clear model for reasoning about thread behaviour.
  • State names map directly to Thread.State.
  • Helps diagnose hangs from thread dumps.
Disadvantages / Trade-offs
  • Transitions are scheduler-controlled and not directly forced.
  • A terminated thread cannot be reused.
  • Runnable does not distinguish running from ready-to-run.
Code
public class LifecycleDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            try { Thread.sleep(100); } catch (InterruptedException e) {}
        });

        System.out.println(t.getState());   // NEW
        t.start();
        System.out.println(t.getState());   // RUNNABLE
        Thread.sleep(10);
        System.out.println(t.getState());   // TIMED_WAITING
        t.join();                            // wait for completion
        System.out.println(t.getState());   // TERMINATED
    }
}
How it works
  • getState() reports the current Thread.State.
  • Before start() the thread is NEW.
  • sleep puts it in TIMED_WAITING.
  • After run() finishes and join() returns, it is TERMINATED.
