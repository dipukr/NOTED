Thread Creation

A thread is the smallest sequence of instructions that an OS scheduler can manage independently.

In Java a thread can be created by extending Thread or by implementing Runnable.

The Runnable approach is preferred because it keeps the task separate from the thread.

Calling start() launches a new thread; calling run() directly does not.

When to use / Key points
  • Use Runnable so the class can still extend something else.
  • start() creates the OS thread and invokes run() on it.
  • Each thread has its own stack but shares heap and code.
  • For many tasks, prefer a thread pool over raw threads.
Advantages
  • Runnable separates work from thread mechanics.
  • Simple to launch independent units of execution.
  • Works with lambdas for concise task definitions.
Disadvantages / Trade-offs
  • Raw threads are costly to create at scale.
  • No built-in reuse, pooling or result handling.
  • Extending Thread wastes the single inheritance slot.
Code
public class CreateThreads {
    public static void main(String[] args) {
        // 1) Implement Runnable (preferred)
        Runnable task = () -> System.out.println("from runnable");
        Thread t1 = new Thread(task);
        t1.start();      // launches a new thread

        // 2) Extend Thread
        Thread t2 = new Thread() {
            public void run() { System.out.println("from subclass"); }
        };
        t2.start();
    }
}
How it works
  • A Runnable holds the task; new Thread(task) wraps it.
  • start() allocates a stack and runs run() on the new thread.
  • Extending Thread overrides run() directly.
  • Never call run() yourself; it executes on the current thread.
