CountDownLatch

CountDownLatch lets one or more threads wait until a set of operations in other threads completes.

It is initialized with a count; each countDown() decrements it and await() blocks until it reaches zero.

It is a one-shot device and cannot be reset.

Common uses are startup gating and waiting for parallel work to finish.

When to use / Key points
  • Wait for N worker threads to finish before aggregating results.
  • Hold threads at a starting gate until a service is ready.
  • The count cannot be reset; use CyclicBarrier for reuse.
  • Always call countDown() in a finally block.
Advantages
  • Simple, clear API for join-style coordination.
  • Decouples the waiting thread from the worker threads.
  • Supports timed await(timeout, unit).
Disadvantages / Trade-offs
  • One-time use only; not reusable.
  • Forgetting countDown() on an exception path causes a permanent hang.
  • Does not carry results, only signals completion.
Code
public class ParallelLoader {

    public void loadAll(int tasks) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(tasks);
        ExecutorService pool = Executors.newFixedThreadPool(4);

        for (int i = 0; i < tasks; i++) {
            final int id = i;
            pool.submit(() -> {
                try {
                    process(id);
                } finally {
                    latch.countDown(); // always signal
                }
            });
        }

        latch.await(); // block until all done
        pool.shutdown();
        System.out.println("All tasks finished");
    }

    private void process(int id) { /* ... */ }
}
How it works
  • The latch starts at tasks and reaches zero once every worker calls countDown().
  • await() blocks the main thread until the count hits zero.
  • countDown() in finally guarantees the count drops even if a task throws.
