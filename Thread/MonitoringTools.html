Monitoring Tools

Monitoring tools let you observe thread state, contention, and resource use in a running JVM.

Thread dumps reveal deadlocks, blocked threads, and hot lock contention.

Tools include jstack, jconsole, VisualVM, Java Flight Recorder, and Micrometer metrics.

They are essential for diagnosing concurrency problems in production.

When to use / Key points
  • Take a jstack thread dump when a service hangs.
  • Use JFR for low-overhead continuous profiling.
  • Expose pool metrics via Micrometer/Actuator.
  • ThreadMXBean can detect deadlocks programmatically.
Advantages
  • Pinpoints deadlocks and contention hotspots.
  • JFR adds negligible overhead in production.
  • Metrics enable alerting on pool saturation.
Disadvantages / Trade-offs
  • Thread dumps are point-in-time snapshots.
  • Interpreting dumps requires experience.
  • Excessive instrumentation adds overhead.
Code
public class DeadlockDetector {

    private final ThreadMXBean bean =
            ManagementFactory.getThreadMXBean();

    public void check() {
        // null if no deadlock detected
        long[] ids = bean.findDeadlockedThreads();
        if (ids != null) {
            System.err.println("Deadlock among threads:");
            for (long id : ids) {
                System.err.println("  thread id " + id);
            }
        } else {
            System.out.println("No deadlocks");
        }
    }

    public int liveThreads() {
        return bean.getThreadCount();
    }
}
How it works
  • ThreadMXBean exposes live JVM thread information via JMX.
  • findDeadlockedThreads() returns ids of threads stuck in a deadlock, or null.
  • getThreadCount() tracks live threads to spot leaks or runaway growth.
