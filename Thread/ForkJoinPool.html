ForkJoinPool Tasks

ForkJoinPool is designed for divide-and-conquer work that recursively splits into subtasks.

It uses a work-stealing algorithm where idle threads steal tasks from busy threads' queues.

Tasks extend RecursiveTask (returns a result) or RecursiveAction (no result).

It backs parallel streams and the common pool used across the JDK.

When to use / Key points
  • CPU-bound recursive problems: sorting, searching, aggregation.
  • Split until subtasks are small, then compute directly.
  • fork() schedules a subtask; join() waits for its result.
  • Do not use for blocking I/O; it starves the pool.
Advantages
  • Work-stealing keeps all cores busy with minimal idle time.
  • Excellent throughput for recursive CPU-bound tasks.
  • Powers parallel streams for free.
Disadvantages / Trade-offs
  • Blocking calls stall worker threads and hurt the whole pool.
  • Splitting overhead can outweigh gains for small inputs.
  • Sharing the common pool can cause cross-task interference.
Code
public class SumTask extends RecursiveTask<Long> {

    private static final int THRESHOLD = 1000;
    private final int[] data;
    private final int lo, hi;

    public SumTask(int[] data, int lo, int hi) {
        this.data = data; this.lo = lo; this.hi = hi;
    }

    @Override
    protected Long compute() {
        if (hi - lo <= THRESHOLD) {
            long sum = 0;
            for (int i = lo; i < hi; i++) sum += data[i];
            return sum;
        }
        int mid = (lo + hi) >>> 1;
        SumTask left = new SumTask(data, lo, mid);
        left.fork(); // run left asynchronously
        SumTask right = new SumTask(data, mid, hi);
        return right.compute() + left.join();
    }
}
How it works
  • compute() solves small ranges directly and splits large ones.
  • fork() queues the left half so another worker can steal it.
  • join() collects the forked result and combines it with the right half.
