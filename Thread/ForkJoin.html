Fork-Join Framework

The Fork-Join framework parallelises divide-and-conquer algorithms. A task forks into subtasks, which run in parallel and then join their results.

Tasks extend RecursiveTask (returns a value) or RecursiveAction (no value). It backs parallel streams and the JVM's common pool used across the JDK.

Code
public class SumTask extends RecursiveTask<Long> {

    private static final int THRESHOLD = 1000;
    private final int[] data;
    private final int lo, hi;

    public SumTask(int[] data, int lo, int hi) {
        this.data = data; this.lo = lo; this.hi = hi;
    }

    @Override
    protected Long compute() {
        if (hi - lo <= THRESHOLD) {
            long sum = 0;
            for (int i = lo; i < hi; i++) sum += data[i];
            return sum;
        }
        int mid = (lo + hi) >>> 1;
        SumTask left = new SumTask(data, lo, mid);
        left.fork(); // run left asynchronously
        SumTask right = new SumTask(data, mid, hi);
        return right.compute() + left.join();
    }
}
How it works

compute() solves small ranges directly and splits large ones.

fork() queues the left half so another worker can steal it.

join() collects the forked result and combines it with the right half.

ForkJoinPool

ForkJoinPool is the executor that runs Fork-Join tasks. It uses a work-stealing algorithm where idle worker threads steal tasks from busy threads' queues to keep all cores busy.

The JVM's shared common pool (used by parallel streams too) is available via ForkJoinPool.commonPool(), or you can create a dedicated pool with new ForkJoinPool(n).

Code
void main() {
    int[] data = new int[10_000];
    Arrays.fill(data, 1);

    ForkJoinPool pool = ForkJoinPool.commonPool();  // or new ForkJoinPool(n)
    long total = pool.invoke(new SumTask(data, 0, data.length));

    System.out.println("sum = " + total);
}
How it works

ForkJoinPool.commonPool() reuses the JVM-wide shared pool (also used by parallel streams).

pool.invoke(task) submits the root task and blocks until the whole computation completes.

Internally the pool's worker threads run compute(), forking and stealing subtasks as needed.

Prefer a dedicated new ForkJoinPool(n) instead of the common pool when isolating from other code that also uses it.

When to use / Key points
  • Recursively splittable, CPU-bound problems: sums, sorts, searches, aggregation.
  • Split until subtasks are small (below a threshold), then compute directly.
  • fork() schedules a subtask asynchronously; join() waits for and returns its result.
  • Avoid blocking I/O inside fork-join tasks — it stalls a worker and starves the pool.
Advantages
Automatic Load Balancing

Work-stealing lets idle workers pull tasks from busy ones, keeping all cores busy with minimal idle time.

High CPU Throughput

It delivers excellent throughput for recursive, divide-and-conquer CPU-bound work.

Powers Parallel Streams

It backs parallel streams and the shared common pool for free.

Disadvantages
Threshold Sensitivity

Choosing the wrong split threshold hurts performance whether it is too high or too low.

Poor For Blocking Work

It is not suited to blocking or I/O-bound tasks, since a blocked worker hurts the whole pool.

Splitting Overhead

Recursion and splitting overhead can outweigh the gains for small inputs.

Shared Pool Interference

Sharing the common pool across unrelated code can cause cross-task interference.
