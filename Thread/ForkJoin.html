Fork-Join Framework

The Fork-Join framework parallelises divide-and-conquer algorithms.

A task forks into subtasks, which run in parallel and then join their results.

It is backed by a work-stealing ForkJoinPool for load balancing.

Tasks extend RecursiveTask (returns a value) or RecursiveAction (no value).

When to use / Key points
  • Recursively splittable problems like sums, sorts and searches.
  • Split until a threshold, then compute sequentially.
  • fork() schedules a subtask; join() waits for its result.
  • Avoid blocking I/O inside fork-join tasks.
Advantages
  • Automatic load balancing via work-stealing.
  • Scales divide-and-conquer work across cores.
  • Powers parallel streams under the hood.
Disadvantages / Trade-offs
  • Wrong split threshold hurts performance.
  • Not suited to blocking or I/O-bound tasks.
  • Recursion overhead for small inputs.
Code
public class SumTask extends RecursiveTask<Long> {
    private final int[] arr; private final int lo, hi;
    SumTask(int[] arr, int lo, int hi) { this.arr = arr; this.lo = lo; this.hi = hi; }

    protected Long compute() {
        if (hi - lo <= 1000) {                 // small enough: do it directly
            long s = 0; for (int i = lo; i < hi; i++) s += arr[i]; return s;
        }
        int mid = (lo + hi) >>> 1;
        SumTask left = new SumTask(arr, lo, mid);
        SumTask right = new SumTask(arr, mid, hi);
        left.fork();                             // async subtask
        return right.compute() + left.join();       // join result
    }
}
How it works
  • compute solves small ranges directly and splits larger ones.
  • fork() queues the left half for another worker to steal.
  • join() waits for and returns the forked subtask's result.
  • The pool balances work so all cores stay busy.
