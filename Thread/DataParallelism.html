Data Parallelism

Data parallelism applies the same operation to many data elements concurrently.

The data set is split into chunks processed in parallel across cores.

It suits large collections where each element is handled independently.

Java expresses it through parallel streams and the Fork-Join pool.

When to use / Key points
  • Large data sets with independent, side-effect-free per-element work.
  • Operations must be stateless and associative for correct reduction.
  • Split cost should be small relative to element work.
  • parallelStream() or stream().parallel() enables it.
Advantages
  • Simple to express over collections.
  • Scales with data size and core count.
  • Runtime handles splitting and merging.
Disadvantages / Trade-offs
  • Overhead can dominate for small data sets.
  • Shared mutable state breaks correctness.
  • Uses the shared common pool, which can be contended.
Code
public class DataParallel {
    public static void main(String[] args) {
        List<Integer> nums = IntStream.rangeClosed(1, 1_000_000)
                                    .boxed().collect(Collectors.toList());

        // Same operation applied to every element in parallel
        long sum = nums.parallelStream()
                       .mapToLong(Integer::longValue)
                       .sum();

        System.out.println("sum = " + sum);
    }
}
How it works
  • parallelStream() splits the list into sub-ranges.
  • Each sub-range is mapped and summed on a separate worker.
  • sum is associative, so partial results merge correctly.
  • The Fork-Join common pool schedules the chunks across cores.
