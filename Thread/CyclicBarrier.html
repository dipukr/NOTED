CyclicBarrier Synchronization

CyclicBarrier makes a fixed set of threads wait for each other at a common barrier point.

Once all parties call await(), they are all released together to continue.

Unlike CountDownLatch it is reusable, resetting automatically for the next round.

An optional barrier action runs once when the last thread arrives.

When to use / Key points
  • Iterative algorithms where threads sync at the end of each round.
  • Fixed number of parties known up front.
  • Barrier action aggregates results between phases.
  • A broken barrier (timeout/interrupt) throws BrokenBarrierException.
Advantages
  • Reusable across many synchronization rounds.
  • Built-in barrier action for per-phase work.
  • Clean rendezvous for equal-sized worker groups.
Disadvantages / Trade-offs
  • Party count is fixed; use Phaser for dynamic sizes.
  • One failed thread breaks the barrier for all.
  • All parties must arrive or everyone blocks.
Code
public class Simulation {

    public void run(int workers, int rounds) {
        // barrier action runs once per round
        CyclicBarrier barrier = new CyclicBarrier(workers,
            () -> System.out.println("Round complete"));

        for (int i = 0; i < workers; i++) {
            final int id = i;
            new Thread(() -> {
                try {
                    for (int r = 0; r < rounds; r++) {
                        compute(id, r);
                        barrier.await(); // wait for all, then reset
                    }
                } catch (InterruptedException | BrokenBarrierException e) {
                    Thread.currentThread().interrupt();
                }
            }).start();
        }
    }

    private void compute(int id, int round) { /* ... */ }
}
How it works
  • The barrier is created for workers parties with a per-round action.
  • await() blocks each thread until all have finished the current round.
  • After release the barrier resets automatically, ready for the next round.
