Garbage Collection

Garbage collection automatically reclaims heap memory occupied by objects no longer reachable from GC roots.

The heap is generational: short-lived objects live in young space, long-lived ones are promoted to old space.

Collectors like G1, ZGC, and Shenandoah trade throughput against pause times.

GC interacts with concurrency because collector threads and pauses affect application threads.

When to use / Key points
  • Choose a low-pause collector (ZGC/Shenandoah) for latency-sensitive apps.
  • Prefer short-lived allocations so they die cheaply in the young generation.
  • Tune heap size to balance pause frequency and duration.
  • GC roots include stack variables, statics, and active threads.
Advantages
  • Frees developers from manual memory management.
  • Eliminates dangling pointers and double-free bugs.
  • Modern collectors deliver very low pauses.
Disadvantages / Trade-offs
  • Stop-the-world pauses can hurt tail latency.
  • GC overhead competes with application CPU.
  • Excessive allocation triggers frequent collections.
Code
public class AllocationDemo {

    public void churn() {
        for (int i = 0; i < 1_000_000; i++) {
            // short-lived: dies in young gen, cheap to collect
            byte[] tmp = new byte[1024];
            process(tmp);
        }
    }

    public void hint() {
        // only a suggestion; JVM may ignore it
        System.gc();
    }

    private void process(byte[] data) { /* ... */ }
}
# Run with G1 and a 2s pause target:
# java -XX:+UseG1GC -XX:MaxGCPauseMillis=200 AllocationDemo
How it works
  • Short-lived arrays are collected quickly in the young generation.
  • System.gc() is only a hint; relying on it is an anti-pattern.
  • JVM flags like -XX:+UseG1GC select the collector and pause targets.
