Critical Section

A critical section is a region of code where shared data between multiple threads is accessed.

Only one thread should execute the critical section at a time to prevent race conditions.

Access is controlled with synchronization techniques such as locks or synchronized blocks.

When one thread is inside, others must wait until it exits.

When to use / Key points
  • Wherever mutable shared state is read and written by several threads.
  • Keep the section as small as possible to maximise concurrency.
  • Mutual exclusion ensures write functionality is thread-safe.
  • Achievable via synchronized block, synchronized method, static synchronization or a monitor.
Advantages
Prevents Race Conditions

Guarding shared state prevents race conditions and memory inconsistency.

Simple Mental Model

The model is easy to reason about: only one thread is inside at a time.

Language Built-in

It is built into the language via the synchronized keyword.

Disadvantages
Reduced Parallelism

Serialising access to the section reduces parallelism.

Potential Bottleneck

Large critical sections become performance bottlenecks.

Deadlock Risk

Poor lock ordering across sections can cause deadlock.

Code
public class Counter {
    private int count = 0;
    private final Object lock = new Object();

    public void increment() {
        synchronized (lock) {
            // critical section: only one thread here at a time
            count++;
        }
    }

    public int get() {
        synchronized (lock) {
            return count;
        }
    }
}
How it works

synchronized (lock) acquires the monitor of lock.

The count++ read-modify-write runs atomically inside the section.

Other threads block on the same monitor until it is released.

Guarding both read and write keeps values consistent.
