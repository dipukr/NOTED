Task Execution

Task execution separates what work to do (the task) from how it runs (the executor).

Tasks are units of work submitted to an executor rather than run on hand-managed threads.

Runnable tasks return nothing; Callable tasks return a value and may throw.

The executor framework handles thread creation, reuse and queueing.

When to use / Key points
  • Whenever you would otherwise create raw threads manually.
  • Submit Runnable or Callable and receive a Future.
  • Future.get() blocks until the result is ready.
  • Choose an executor type that matches the workload.
Advantages
  • Decouples task logic from thread management.
  • Callable returns results and reports exceptions cleanly.
  • Futures let you await or cancel work.
Disadvantages / Trade-offs
  • Future.get() blocks the caller.
  • Uncaught task exceptions are hidden until get() is called.
  • Wrong executor sizing causes contention or resource exhaustion.
Code
void main(String[] args) throws Exception {
    ExecutorService exec = Executors.newFixedThreadPool(2);

    // Callable returns a value and can throw
    Callable<Integer> task = () -> {
        Thread.sleep(100);
        return 21 * 2;
    };

    Future<Integer> future = exec.submit(task);
    System.out.println("result = " + future.get());  // blocks

    exec.shutdown();
}
How it works
  • submit hands the Callable to the executor and returns a Future.
  • A pooled thread runs the task off the main thread.
  • future.get() waits for and returns the computed value.
  • shutdown stops accepting new tasks and lets running ones finish.
