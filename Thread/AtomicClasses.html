Atomic Classes

Classes in java.util.concurrent.atomic provide lock-free, thread-safe operations on single variables.

They use low-level compare-and-swap (CAS) CPU instructions instead of locks.

Common types include AtomicInteger, AtomicLong, AtomicBoolean and AtomicReference.

They solve the race condition that plain volatile cannot: atomic read-modify-write.

When to use / Key points
  • Use for counters, sequence generators, and accumulators under contention.
  • incrementAndGet(), compareAndSet() execute atomically.
  • LongAdder scales better than AtomicLong under very high write contention.
  • Prefer over synchronized when only a single variable is involved.
Advantages
  • No blocking, no deadlocks, no context switching.
  • Often faster than locks for single-variable updates.
  • Rich API: get-and-set, CAS, atomic accumulate.
Disadvantages / Trade-offs
  • Only atomic for one variable, not multi-field invariants.
  • CAS retries can spin under extreme contention.
  • Vulnerable to the ABA problem (use AtomicStampedReference if needed).
Code
public class HitCounter {

    private final AtomicInteger hits = new AtomicInteger(0);

    public void record() {
        // atomic read-modify-write, no lock needed
        hits.incrementAndGet();
    }

    public boolean reserveIfBelow(int limit) {
        int current;
        do {
            current = hits.get();
            if (current >= limit) return false;
        } while (!hits.compareAndSet(current, current + 1));
        return true;
    }

    public int total() { return hits.get(); }
}
How it works

incrementAndGet() performs the increment atomically via CAS.

compareAndSet(expected, new) only updates if the value is still expected.

The retry loop handles the case where another thread changed the value first.
