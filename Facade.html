Facade Pattern

Facade pattern is a structural design pattern that provides a unified interface to a set of interfaces in a subsystem. A complex interface to the client is considered as a fault in the design of a system.

Facade defines a higher-level interface that makes the subsystem easier to use.

Facade pattern makes a complex interface easier to use using a Facade class.

When-to use
  • When you want to simplify the usage of a complex system.
  • When there are multiple subsystems that need to be integrated.
  • To decouple clients from the internal components of a system.
  • When you want to create a layered architecture.
Advantages
  • Provides a simple and unified interface to a complex subsystem.
  • Reduces the coupling between the client and subsystem components.
  • Hides unnecessary implementation details from the client.
  • Makes client code cleaner, easier to understand, and easier to maintain.
  • Can make a complex subsystem easier to integrate and use.
Disadvantages
  • The Facade can become a large class if too much functionality is placed in it.
  • It may hide useful functionality of the underlying subsystem.
  • Changes in the subsystem may require corresponding changes in the Facade.
  • Adds an additional abstraction layer to the application.
Code
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

class PaymentService {
    public void processPayment() {
        System.out.println("Payment processed");
    }
}

class NotificationService {
    public void sendNotification() {
        System.out.println("Notification sent");
    }
}

class OrderFacade {

    @Autowired
    private PaymentService paymentService;

    @Autowired
    private NotificationService notificationService;

    public void placeOrder() {
        paymentService.processPayment();
        notificationService.sendNotification();
    }
}

void main() {
    System.out.println("Client calls OrderFacade.placeOrder()");
}
How the Facade works
  • PaymentService and NotificationService
    are subsystem classes.
  • OrderFacade provides one simple entry point for the client.
  • The client does not need to call each subsystem directly.
  • placeOrder() coordinates the required subsystem operations.
