Flyweight Pattern

Flyweight pattern is a structural design pattern that reduces memory uses by sharing similar objects.

Flyweight pattern uses a factory to manage these shared objects and ensures that each object is created only once.

When we need large number of similar objects then creating and storing each object separately can take too much memory.

Components
  • Flyweight interface – Declares methods that accept extrinsic state.
  • ConcreteFlyweight – Implements Flyweight and stores intrinsic state.
  • FlyweightFactory – Manages a pool of flyweight objects.
  • Client – Maintains or computes extrinsic state and passes it to the flyweight.
Pros and cons
  • Reduces memory usage by sharing objects.
  • Increases performance when creating many similar objects.
  • Makes code more complex.
  • Requires careful separation of intrinsic and extrinsic state.
Code
# Flyweight: intrinsic (shared) state only
class TreeType {
    private final String name;
    private final String color;
    public TreeType(String name, String color) {
        this.name = name;
        this.color = color;
    }
    public void draw(int x, int y) {  # extrinsic state passed in
        System.out.println(name + " at " + x + "," + y);
    }
}

# Factory shares flyweights via a pool
class TreeFactory {
    private static final Map<String, TreeType> pool
            = new HashMap<>();

    public static TreeType get(String name, String color) {
        return pool.computeIfAbsent(name + color,
                k -> new TreeType(name, color));
    }
}

void main() {
    TreeType oak = TreeFactory.get("Oak", "green");
    oak.draw(10, 20);
    oak.draw(30, 40);  # same shared object
}
How the Flyweight works
  • TreeType holds only intrinsic state (name, color) shared by many trees.
  • Extrinsic state such as position is passed into draw() by the client.
  • TreeFactory caches flyweights and returns the same instance for equal keys.
  • Thousands of trees can reuse a handful of TreeType objects, saving memory.
