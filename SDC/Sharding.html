Sharding

Sharding splits a database's data into subsets, called shards, and stores each shard on a separate database node. Each node handles only the reads and writes for its own shard, so the total load is spread across machines.

Scale vertically before sharding. Vertically scaling a database by throwing a bigger server at it is almost always smarter than sharding. Sharding introduces distributed transaction hell, complex cross-node queries and painful maintenance. Paying AWS extra money for a massive instance with more RAM and CPU is ridiculously cheap compared to the engineering months burned managing a sharded database cluster.
