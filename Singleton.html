Singleton Pattern

Singleton is a creational design pattern that ensures a class has only one instance and provides a global point of access to that instance.

The class itself is made responsible for controlling its instantiation, hiding the constructor and exposing a single accessor method.

It is commonly used for shared resources such as configuration holders, logging, caches, thread pools, and connection managers.

When to use
  • When exactly one instance of a class must exist across the application.
  • When you need a single, shared point of access to a resource.
  • For managing shared state such as configuration, caches, or logging.
  • When creating the object is expensive and it should be reused.
  • When stricter control over global variables is required.
Advantages
  • Guarantees that a class has only a single instance.
  • Provides a global access point to that instance.
  • The instance is created only once (lazy or eager initialization).
  • Saves memory by avoiding repeated object creation.
  • Useful for coordinating actions across a system.
Disadvantages
  • Introduces global state, which can make code harder to test and reason about.
  • Can hide dependencies instead of exposing them explicitly.
  • Requires careful handling to remain thread-safe.
  • Violates the single responsibility principle by controlling both logic and its own lifecycle.
Code
public class ConfigManager {

    # Eager, thread-safe instance
    private static final ConfigManager INSTANCE
            = new ConfigManager();

    private String environment;

    # Private constructor prevents external instantiation
    private ConfigManager() {
        this.environment = "production";
    }

    public static ConfigManager getInstance() {
        return INSTANCE;
    }

    public String getEnvironment() {
        return environment;
    }
}

void main() {
    ConfigManager cfg = ConfigManager.getInstance();
    System.out.println(cfg.getEnvironment());
}
How the Singleton works
  • The constructor is private, so no other class can create an instance.
  • A single static final instance is created when the class loads.
  • getInstance() returns that same shared instance every time.
  • Using a static final field makes this eager version inherently thread-safe.
