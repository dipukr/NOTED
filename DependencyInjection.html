Dependency Injection

Dependency injection generally means passing a dependent object as a parameter to a method rather than having the method create the dependent object.

Dependency injection is a software design pattern that allow us to develop loosely-coupled software.

Dependecy injection allows us to depends more on abstraction rather than the concrete implementation, which promotes loosely-coupled architecture, flexibility and pluggability within our code.

What it means in practice is that the method does not have a direct dependency on a particular implementation, any implementation that meets the requirements can be passed as a parameter.

Dependency injection is a programming technique where an object or function receives its dependencies (other objects or functions it needs) from an external source, rather than creating them itself. This approach, which is a form of Inversion of Control, makes code more flexible, maintainable, and testable by decoupling components and allowing them to be replaced or mocked easily.

Code
interface MessageService {
    void send(String msg);
}

@Service
class EmailService implements MessageService {
    public void send(String msg) {
        System.out.println("Email: " + msg);
    }
}

@Component
class Notifier {

    private final MessageService service;

    // Constructor injection
    @Autowired
    Notifier(MessageService service) {
        this.service = service;
    }

    void notifyUser() {
        service.send("Welcome!");
    }
}

// The Spring container injects EmailService into Notifier;
// Notifier never calls new EmailService() itself.
How Dependency Injection works
  • Notifier depends on the MessageService abstraction.
  • The dependency is passed in through the constructor.
  • The container picks the @Service bean and wires it in.
  • Swapping to an SMS service needs no change inside Notifier.
