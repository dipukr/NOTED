Memento Pattern

Memento is a behavioral design pattern that lets you save and restore the previous state of an object without exposing the details of its implementation.

The object whose state is captured is the originator; the snapshot itself is the memento; and the object that stores mementos is the caretaker.

Because the memento keeps the internal state opaque, encapsulation is preserved while still supporting undo and rollback.

When to use
  • When you need to produce snapshots of an object's state to restore later.
  • When you want undo/redo or rollback functionality.
  • When directly exposing an object's fields would break encapsulation.
  • Typical uses: text editors, transactions, game save points, and checkpoints.
Advantages
  • Preserves encapsulation by keeping the saved state private to the originator.
  • Simplifies the originator, which does not manage its own history.
  • Makes undo/redo and state restoration straightforward to implement.
  • The caretaker manages snapshots without knowing their contents.
Disadvantages
  • Storing many mementos can consume a lot of memory.
  • The caretaker must track the lifecycle of mementos to avoid leaks.
  • Frequent state capture of large objects can be expensive.
Code
class Editor {                       // Originator
    private String text = "";

    void type(String words) { text += words; }
    String getText() { return text; }

    Memento save() { return new Memento(text); }
    void restore(Memento m) { text = m.state; }

    static class Memento {          // Memento
        private final String state;
        Memento(String state) { this.state = state; }
    }
}

void main() {
    Editor editor = new Editor();
    editor.type("Hello");
    Editor.Memento saved = editor.save();  // caretaker holds it
    editor.type(" World");
    editor.restore(saved);
    System.out.println(editor.getText());  // Hello
}
How the Memento works
  • Editor is the originator that creates and reads snapshots.
  • Memento stores state with its fields kept private.
  • save() captures state; restore() rolls it back.
  • The caller (caretaker) holds mementos without inspecting them.
