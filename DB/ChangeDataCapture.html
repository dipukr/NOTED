Change Data Capture (CDC)

Change data capture (CDC) is a technique for detecting and streaming row-level changes (inserts, updates, deletes) from a database.

Log-based CDC reads the database's write-ahead log to capture changes with minimal overhead.

Captured changes are published as events other systems can consume.

It keeps caches, search indexes, data warehouses and microservices in sync.

Tools like Debezium implement CDC and publish changes to Kafka.

When to use / Key points
  • Use to propagate database changes to other systems in near real time.
  • Log-based CDC avoids polling and adds little load.
  • Powers the outbox pattern for reliable event publishing.
  • Keeps read models, search indexes and warehouses fresh.
  • Preserves change order per row via the log.
Advantages
  • Near real-time propagation of changes.
  • Low overhead when reading the WAL.
  • Decouples producers from consumers.
  • Captures every change, including deletes.
Disadvantages / Trade-offs
  • Adds pipeline infrastructure (connector, broker) to operate.
  • Consumers must handle eventual consistency and ordering.
  • Schema changes in the source can break consumers.
  • Initial snapshot of large tables can be heavy.
Code
-- Enable CDC on the database, then on a specific table
EXEC sys.sp_cdc_enable_db;

EXEC sys.sp_cdc_enable_table
    @source_schema = N'dbo',
    @source_name   = N'Customer',
    @role_name     = NULL,
    @capture_instance = N'dbo_Customer',
    @supports_net_changes = 1;

-- List available capture instances and their change tables
SELECT capture_instance, source_object_id, create_date
FROM cdc.change_tables;

-- Pull all inserts/updates/deletes since a given LSN
DECLARE @from_lsn BINARY(10) = sys.fn_cdc_get_min_lsn('dbo_Customer');
DECLARE @to_lsn   BINARY(10) = sys.fn_cdc_get_max_lsn();

SELECT __$operation,     -- 1=delete, 2=insert, 3=update(before), 4=update(after)
       CustomerId, Name, Email
FROM cdc.fn_cdc_get_all_changes_dbo_Customer(@from_lsn, @to_lsn, N'all')
ORDER BY __$start_lsn;
How it works
  • sys.sp_cdc_enable_db / sys.sp_cdc_enable_table turn on log-based capture for a table, creating a shadow change table and capture jobs.
  • cdc.change_tables lists which capture instances exist and where their data lives.
  • sys.fn_cdc_get_min_lsn / sys.fn_cdc_get_max_lsn define the log range to read.
  • cdc.fn_cdc_get_all_changes_dbo_Customer returns every row-level change in that range, with __$operation identifying insert/update/delete.
  • Consumers poll this function incrementally instead of scanning the whole table, keeping downstream systems in sync with minimal overhead.
