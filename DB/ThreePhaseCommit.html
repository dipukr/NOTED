Three-Phase Commit (3PC)

Three-phase commit (3PC) is a distributed commit protocol that extends 2PC to avoid its blocking problem.

It inserts an extra pre-commit phase between prepare and commit.

The added phase and timeouts let participants make progress even if the coordinator fails.

It is non-blocking under the assumption of a synchronous network with bounded delays.

In practice it is rarely used because that assumption often does not hold.

When to use / Key points
  • Phase 1 (canCommit): participants vote as in 2PC.
  • Phase 2 (preCommit): coordinator tells participants to prepare to commit.
  • Phase 3 (doCommit): coordinator issues the final commit.
  • Timeouts allow participants to decide autonomously if the coordinator vanishes.
  • Mostly of theoretical interest; real systems favour consensus (Paxos/Raft) or sagas.
Advantages
  • Non-blocking under synchronous network assumptions.
  • Participants can reach a decision after coordinator failure.
  • Reduces the in-doubt window compared to 2PC.
Disadvantages / Trade-offs
  • Extra phase adds latency and message overhead.
  • Correctness relies on bounded network delays, which real networks violate.
  • Network partitions can still cause inconsistency.
  • Rarely implemented in practice.
Code
-- Coordinator database enlists a remote resource via MS DTC
BEGIN DISTRIBUTED TRANSACTION;

BEGIN TRY

    -- Phase 1 (canCommit): each participant votes without committing
    -- local participant
    UPDATE Ledger SET balance = balance - 100 WHERE account_id = 1;
    -- remote participant, reached through a linked server
    UPDATE [RemoteServer].[Bank].dbo.Ledger
        SET balance = balance + 100 WHERE account_id = 2;
    -- if either UPDATE fails/times out here, all participants can still abort

    -- Phase 2 (preCommit): coordinator tells every participant to get ready
    -- (MS DTC issues PREPARE to each resource manager internally)
    IF XACT_STATE() = 1
    BEGIN
        -- all participants acknowledged prepare/ready; safe to proceed even
        -- if the coordinator now crashes, participants can resolve via timeout

        -- Phase 3 (doCommit): coordinator issues the final, irreversible commit
        COMMIT TRANSACTION;
    END

END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0
        ROLLBACK TRANSACTION;   -- abort: every participant undoes its local change
    THROW;
END CATCH;
How it works
  • BEGIN DISTRIBUTED TRANSACTION enlists MS DTC, which coordinates the local and linked-server (remote) resource managers as participants.
  • Phase 1 corresponds to each participant executing its statement and being ready to vote; a failure here lets everyone abort cleanly, unlike in 2PC where this window can block.
  • Phase 2 (preCommit) is where DTC asks every resource manager to prepare; XACT_STATE() = 1 confirms the transaction is still committable before moving on.
  • Phase 3 (doCommit) is the final COMMIT TRANSACTION, applied to all participants; TRY/CATCH with ROLLBACK handles the abort path if any phase fails.
