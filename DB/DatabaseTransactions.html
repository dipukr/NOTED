Database Transactions

A transaction is a single, indivisible unit of work made up of one or more database operations.

Either all operations within a transaction complete successfully, or none of them are applied.

If any part of the transaction fails, the entire transaction is rolled back to prevent partial updates.

Transactions provide the ACID guarantees that keep the database in a consistent state.

They are bounded by begin, commit and rollback operations.

When to use / Key points
  • Wrap multiple related writes that must succeed or fail together in one transaction.
  • Keep transactions short to reduce lock contention.
  • Choose an isolation level appropriate to the consistency you need.
  • Commit on success; roll back on any exception.
  • In Spring, @Transactional manages begin/commit/rollback automatically.
Advantages
  • Guarantees all-or-nothing atomic updates.
  • Keeps data consistent even during concurrent access.
  • Survives failures via rollback and durability.
  • Simplifies error handling for multi-step operations.
Disadvantages / Trade-offs
  • Long transactions hold locks and reduce concurrency.
  • Higher isolation levels cost performance.
  • Distributed transactions across services are complex and slow.
Code
-- A multi-step transfer using a SAVEPOINT so partial work can be undone
BEGIN TRANSACTION TransferTran;

UPDATE Accounts SET Balance = Balance - 200 WHERE AccountId = 1;

SAVE TRANSACTION AfterWithdraw;   -- checkpoint we can roll back to

UPDATE Accounts SET Balance = Balance + 200 WHERE AccountId = 999;

IF @@ROWCOUNT = 0
BEGIN
    -- destination account did not exist: undo only the deposit attempt,
    -- keep the withdrawal pending and retry with a valid account instead
    ROLLBACK TRANSACTION AfterWithdraw;

    UPDATE Accounts SET Balance = Balance + 200 WHERE AccountId = 2;
END;

COMMIT TRANSACTION TransferTran;
How it works

BEGIN TRANSACTION starts one indivisible unit of work spanning both balance updates.

SAVE TRANSACTION AfterWithdraw marks a checkpoint inside the transaction without committing anything yet.

ROLLBACK TRANSACTION AfterWithdraw undoes only the work done since that savepoint (the failed deposit), while keeping the earlier withdrawal intact and the outer transaction open.

This lets the code retry with a different account rather than discarding the whole transaction.

COMMIT TRANSACTION makes every surviving change durable at once; a full ROLLBACK without a savepoint name would have undone everything.
