ORM and JPA

Object-relational mapping (ORM) is the process of mapping Java objects to relational tables of a relational database.

Each row in a table corresponds to a single object, and each column corresponds to a field of the object.

The ORM is a layer between the object-oriented language and the SQL language of the relational database; it works like an adapter that adapts object graphs to relational tables.

JPA is the Java standard API for object-relational mapping, one of many possible approaches to ORM.

JPA is only a specification and needs an implementation to work; the most popular implementation is Hibernate.

When to use / Key points
  • Use JPA when you want to work with objects instead of hand-writing SQL for CRUD.
  • JPA is concerned with persistence: making Java objects outlive the process that created them.
  • Entities are managed within a persistence context that tracks changes.
  • Relationships are mapped with @OneToMany, @ManyToOne, etc.
  • Drop to native SQL when a query is too complex or performance-critical for the ORM.
Pros and Cons
Database Independence

Application code stays portable across different database vendors.

Caching Performance

Performance is enhanced through built-in caching mechanisms.

Simplified Development

Development is simplified by abstracting SQL and automating table creation.

Less Boilerplate

It eliminates much of the boilerplate JDBC code you would otherwise write.

N+1 Select Problem

Hidden queries can trigger the N+1 select problem and hurt performance.

Awkward Reporting Queries

Complex reporting queries are awkward to express through the ORM.

Learning Curve

There is a learning curve around the persistence context and lazy loading.

Suboptimal SQL

It can generate suboptimal SQL if used carelessly.

Code
CREATE TABLE Orders (
    OrderId INT PRIMARY KEY,
    CustomerId INT NOT NULL
);
CREATE TABLE OrderItem (
    ItemId INT PRIMARY KEY,
    OrderId INT REFERENCES Orders(OrderId),
    Sku VARCHAR(50),
    Quantity INT
);

-- SQL Hibernate/JPA generates for: order.getItems() via "JOIN FETCH"
SELECT o.OrderId, o.CustomerId, i.ItemId, i.Sku, i.Quantity
FROM Orders o
JOIN OrderItem i ON i.OrderId = o.OrderId
WHERE o.OrderId = @OrderId;

-- equivalent hand-written parameterized query (avoids SQL injection)
SELECT o.OrderId, o.CustomerId
FROM Orders o
WHERE o.CustomerId = @CustomerId
ORDER BY o.OrderId DESC;
How it works

The ORM maps the Order/OrderItem object graph onto these two tables, linked by the OrderId foreign key.

A JOIN FETCH-style association load translates into a single SELECT ... JOIN that pulls the order and its items in one round trip.
