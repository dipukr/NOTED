Webhooks

A webhook is an HTTP callback that one system sends to another when an event occurs.

Instead of the client polling for changes, the provider pushes data to a registered URL.

The receiver exposes an endpoint that the provider calls with the event payload.

It is a simple, event-driven way to integrate systems over HTTP.

When to use / Key points
  • Use for event notifications between services (payments, CI, git pushes).
  • The consumer registers a callback URL with the provider.
  • Payloads should be verified with a signature or secret.
  • Handlers must be idempotent since providers retry.
Advantages
  • Real-time push without wasteful polling.
  • Simple to implement over standard HTTP.
  • Decouples the producer from the consumer.
Disadvantages / Trade-offs
  • The receiver must expose a public, always-available endpoint.
  • Delivery can fail; retries risk duplicate processing.
  • Payloads must be authenticated to prevent spoofing.
Code
# Receiving and verifying a webhook
@RestController
public class WebhookController {

    private final SignatureVerifier verifier;

    public WebhookController(SignatureVerifier verifier) {
        this.verifier = verifier;
    }

    @PostMapping("/webhooks/payment")
    public ResponseEntity<Void> onPayment(
            @RequestHeader("X-Signature") String sig,
            @RequestBody String payload) {

        if (!verifier.isValid(payload, sig)) {  # reject spoofed calls
            return ResponseEntity.status(401).build();
        }
        System.out.println("Payment event: " + payload);
        return ResponseEntity.ok().build();      # 200 acknowledges receipt
    }
}
How it works

The provider POSTs the event to the registered URL.

The signature header is verified before trusting the payload.

Returning 200 tells the provider not to retry.
