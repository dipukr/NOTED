TCP

TCP (Transmission Control Protocol) is a connection-oriented transport protocol that delivers a reliable, ordered stream of bytes.

It establishes a connection with a three-way handshake before data flows.

It guarantees delivery through acknowledgements, retransmission, and sequencing.

Flow control and congestion control keep senders and networks from being overwhelmed.

When to use / Key points
  • Use when reliability and correct ordering matter (web, email, file transfer).
  • Handshake: SYN, SYN-ACK, ACK establishes the connection.
  • Underpins HTTP, HTTPS, and most application protocols.
  • Slower to start than UDP due to setup and acknowledgements.
Advantages
  • Reliable, guaranteed delivery of data.
  • Data arrives in order, with duplicates removed.
  • Built-in flow and congestion control.
Disadvantages / Trade-offs
  • Higher latency from handshake and acknowledgements.
  • More overhead per packet than UDP.
  • Head-of-line blocking can stall a stream.
Code
# A minimal TCP client using Java sockets

public class TcpClient {

    public static void main(String[] args) throws IOException {
        # opening the socket performs the 3-way handshake
        try (Socket socket = new Socket("localhost", 9090)) {

            PrintWriter out =
                new PrintWriter(socket.getOutputStream(), true);
            BufferedReader in = new BufferedReader(
                new InputStreamReader(socket.getInputStream()));

            out.println("PING");       # reliable, ordered send
            System.out.println(in.readLine());
        }
    }
}
How it works
  • Constructing the Socket completes the TCP handshake.
  • The stream guarantees bytes arrive in order and intact.
  • Closing the socket tears the connection down cleanly.
