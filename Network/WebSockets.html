WebSockets

WebSockets provide a full-duplex, persistent connection between client and server over a single TCP connection.

Unlike the request-response model, either side can send data at any time.

The connection starts as an HTTP request that is upgraded to the WebSocket protocol.

It is ideal for real-time, low-latency communication.

When to use / Key points
  • Use for chat, live dashboards, gaming, and collaborative apps.
  • Begins with an HTTP handshake carrying an Upgrade header.
  • The server can push data without the client polling.
  • Runs over ws:// or secure wss://.
Advantages
  • Real-time, bidirectional communication.
  • Low overhead after the initial handshake.
  • Eliminates constant polling of the server.
Disadvantages / Trade-offs
  • Persistent connections consume server resources.
  • Scaling across many servers needs sticky sessions or a broker.
  • Some proxies and firewalls interfere with upgrades.
Code
# A server-side WebSocket endpoint with Spring
@Component
public class ChatHandler extends TextWebSocketHandler {

    @Override
    public void afterConnectionEstablished(WebSocketSession session) {
        System.out.println("Client connected: " + session.getId());
    }

    @Override
    protected void handleTextMessage(
            WebSocketSession session, TextMessage message) throws Exception {
        # server can push a reply any time
        session.sendMessage(
            new TextMessage("Echo: " + message.getPayload()));
    }
}
How it works

afterConnectionEstablished fires once the upgrade completes.

The connection stays open for two-way messaging.

sendMessage pushes data to the client without a request.
