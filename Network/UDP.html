UDP

UDP (User Datagram Protocol) is a connectionless transport protocol that sends independent datagrams without setup.

It offers no delivery guarantees, ordering, or retransmission.

This makes it lightweight and low-latency compared to TCP.

Applications must handle any reliability they need themselves.

When to use / Key points
  • Use when speed matters more than guaranteed delivery.
  • Ideal for live streaming, gaming, VoIP, and DNS queries.
  • No handshake, so there is minimal startup latency.
  • Occasional lost packets are acceptable for the use case.
Advantages
  • Very low latency and overhead.
  • No connection state to establish or maintain.
  • Supports broadcast and multicast.
Disadvantages / Trade-offs
  • No guarantee of delivery; packets can be lost.
  • No ordering; datagrams may arrive out of sequence.
  • Reliability must be reimplemented by the application if needed.
Code
// Sending a UDP datagram in Java

void main(String[] args) throws Exception {
    try (DatagramSocket socket = new DatagramSocket()) {

        byte[] data = "PING".getBytes();
        InetAddress host = InetAddress.getByName("localhost");

        // no connection: just fire the datagram
        DatagramPacket packet =
            new DatagramPacket(data, data.length, host, 9090);

        socket.send(packet); // fire and forget, no ack
        System.out.println("Datagram sent");
    }
}
How it works

No handshake: the datagram is sent immediately.

send does not wait for or confirm delivery.

Lost or reordered packets are the app's problem to handle.
