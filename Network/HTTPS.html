HTTPS

HTTPS is HTTP layered over TLS, encrypting traffic between client and server.

It provides confidentiality, integrity, and authentication of the server.

A TLS handshake negotiates keys and validates the server's certificate before any data flows.

It is the standard for secure communication on the web.

When to use / Key points
  • Use for all web traffic; it is effectively mandatory today.
  • Certificates are issued by trusted Certificate Authorities.
  • Protects against eavesdropping and man-in-the-middle attacks.
  • Runs on port 443 by default.
Advantages
  • Encrypts data in transit.
  • Verifies server identity via certificates.
  • Detects tampering with message integrity checks.
Disadvantages / Trade-offs
  • Handshake adds some latency and CPU cost.
  • Certificates must be issued, renewed, and managed.
  • Misconfiguration can silently weaken security.
Code
# Enable HTTPS in Spring Boot (application.properties as code)
# server.ssl.key-store=classpath:keystore.p12
# server.ssl.key-store-password=changeit
# server.ssl.key-store-type=PKCS12
# server.port=8443

# Making an HTTPS call with Java's HttpClient
HttpClient client = HttpClient.newHttpClient();

HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/data"))
    .GET()
    .build();

HttpResponse<String> response =
    client.send(request, HttpResponse.BodyHandlers.ofString());

# TLS handshake and cert validation happen automatically
System.out.println(response.statusCode());
How it works

The https scheme triggers a TLS handshake before the request.

HttpClient validates the server certificate against trusted CAs.

All request and response bytes travel encrypted.
