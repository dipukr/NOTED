Builder Pattern

Builder is a creational design pattern that lets you construct complex objects step by step, separating the construction process from the final representation.

It is especially useful when an object has many optional parameters, avoiding the "telescoping constructor" problem where constructors take long, confusing argument lists.

The same construction process can produce different representations, and the resulting object is typically immutable.

When to use
  • When an object requires many parameters, several of them optional.
  • When you want to avoid long, ambiguous telescoping constructors.
  • When you want to build an immutable object in readable steps.
  • When the construction process should be independent of the parts that make up the object.
  • When you need to enforce validation before the object is created.
Advantages
  • Produces highly readable, self-documenting object creation code.
  • Handles optional parameters cleanly without multiple constructors.
  • Allows the final object to be immutable and thread-safe.
  • Isolates complex construction logic from the object itself.
  • Enables validation of the object state before it is built.
Disadvantages
  • Requires writing extra boilerplate for the builder class.
  • Increases the overall number of classes in the codebase.
  • Can be overkill for simple objects with few fields.
Code
public class User {
    private final String name;      # required
    private final int age;         # optional
    private final String email;     # optional

    private User(Builder b) {
        this.name  = b.name;
        this.age   = b.age;
        this.email = b.email;
    }

    public static class Builder {
        private final String name;
        private int age;
        private String email;

        public Builder(String name) {
            this.name = name;
        }
        public Builder age(int age) {
            this.age = age; return this;
        }
        public Builder email(String email) {
            this.email = email; return this;
        }
        public User build() {
            return new User(this);
        }
    }
}

void main() {
    User u = new User.Builder("Alice")
                    .age(30)
                    .email("alice@mail.com")
                    .build();
}
How the Builder works
  • The User constructor is private; objects are created only through the builder.
  • Required fields go into the Builder constructor; optional ones use fluent setters.
  • Each setter returns this, allowing calls to be chained.
  • build() assembles a final, immutable User instance.
