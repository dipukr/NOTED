Service Mesh

A service mesh is a dedicated infrastructure layer that manages service-to-service communication in a microservices system.

It handles routing, load balancing, retries, security, and observability without changing application code.

Logic runs in sidecar proxies deployed alongside each service, forming the data plane.

A control plane configures those proxies centrally.

When to use / Key points
  • Use at scale, when many services need consistent networking policies.
  • Data plane: sidecar proxies (e.g. Envoy) intercept all traffic.
  • Control plane: manages config, certificates, and policy.
  • Provides mTLS, traffic shifting, and telemetry out of the box.
Advantages
Networking Out of Code

It moves cross-cutting networking concerns out of application code and into the mesh.

Uniform Security and Observability

It provides consistent security with mTLS, retries, and observability across all services.

Advanced Traffic Control

It enables canary and blue-green deployments through fine-grained traffic control.

Disadvantages
Operational Complexity

It adds significant operational complexity to run and upgrade the mesh.

Latency and Overhead

Sidecar proxies add latency and consume additional resources.

Steep Learning Curve

Teams face a steep learning curve to adopt and operate the mesh effectively.

Code
# With a mesh, app code stays plain: no retry/TLS logic here
@Service
public class CatalogService {

    private final RestTemplate rest;

    public CatalogService(RestTemplate rest) {
        this.rest = rest;
    }

    public Item getItem(String id) {
        # calls the local sidecar, which handles mTLS + retries
        return rest.getForObject(
            "http://pricing-service/items/" + id, Item.class);
    }
}
# Retries, timeouts and TLS are declared in mesh config (YAML),
# not in Java. The sidecar enforces them transparently.
How it works

The service makes a plain HTTP call to the target name.

Its sidecar proxy intercepts and applies mTLS, retries, and routing.

Policies change via the control plane, not code redeploys.
