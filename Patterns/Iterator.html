Iterator Pattern

Iterator pattern is a behavioral design pattern that provides a way to access the elements of a collection (like a list, tree or graph) sequentially without exposing its underlying representation.

Iterator pattern is used to traverse elements in a container.

Intent is to provide a standard way to traverse through a collection of objects without exposing its internal structure.

Iterator pattern decouples container traversal algorithms from containers.

Components
  • Iterator (Interface) – declares the interface for accessing elements.
  • ConcreteIterator – implements the Iterator interface and keeps track of the current position.
  • Aggregate (Interface) – declares a method to return an iterator.
  • ConcreteAggregate – implements the method to return an iterator instance.
Advantages
Separation of Concerns

Separates collection traversal logic from the collection's underlying data structure.

Uniform Traversal

Provides a uniform way to traverse various types of collections.

Multiple Iterations

Supports multiple iterations over the same collection simultaneously.

Real-world example
  • java.util.Iterator – every Collection returns one via iterator() so for-each loops can traverse lists, sets and maps uniformly.
  • java.util.Enumeration – the legacy iterator used by Vector, Stack and Hashtable before the Iterator interface.
  • ListIterator – extends Iterator to allow bidirectional traversal and element modification while iterating a List.
  • java.util.Scanner – walks through tokens or lines of input one at a time without exposing the underlying buffer.
  • Spring Data Pageable/Iterable – repository results are exposed as iterables so callers stream rows without knowing the query mechanics.
  • java.util.stream.Stream – internally pulls elements through a Spliterator, an iterator variant built for splitting and parallel traversal.
  • TV remote channel button – a real-life analogy where you move to the next channel one by one without knowing how channels are stored.
Code
public interface Iterator<T> {
    boolean hasNext();
    T next();
}

public class NameRepository {
    private String[] names = { "Amit", "Bina", "Chandan" };

    public Iterator<String> iterator() {
        return new Iterator<>() {
            private int index = 0;

            public boolean hasNext() {
                return index < names.length;
            }

            public String next() {
                return names[index++];
            }
        };
    }
}

void main() {
    Iterator<String> it = new NameRepository().iterator();
    while (it.hasNext())
        System.out.println(it.next());
}
How the Iterator works

Iterator declares hasNext() and next().

NameRepository is the collection holding the data.

The inner iterator tracks its own index position.

The client traverses without knowing the array behind it.
