Factory Method

Factory Method is a creational design pattern that defines an interface for creating an object but lets subclasses decide which concrete class to instantiate. It defers instantiation to subclasses, so the client code depends only on an abstract product type rather than on concrete implementations. This promotes loose coupling by removing the need for the client to use the new operator on specific classes.

When to use
  • When a class cannot anticipate the type of objects it must create.
  • When you want subclasses to specify the objects they create.
  • When you want to decouple client code from concrete product classes.
  • When object creation logic should be centralized in one place.
  • When you need to introduce new product types without changing client code.
Advantages
Loose Coupling

Removes tight coupling between the creator and the concrete products it uses.

Single Responsibility

Follows the single responsibility principle by isolating object creation code in one place.

Open/Closed Principle

Follows the open/closed principle so new products can be added easily without changing existing code.

Centralized Creation

Provides a single place to control how objects are created.

Easier To Maintain

Makes the code easier to extend and maintain over time.

Disadvantages
More Subclasses

Introduces many new subclasses, increasing overall code complexity.

Overkill For Simple Cases

Can be excessive for simple creation scenarios that do not need the abstraction.

Parallel Hierarchy

Requires a parallel class hierarchy for creators and products.

Real-world example
  • java.util.Calendar.getInstance() – returns a locale and time-zone specific Calendar subclass chosen at runtime.
  • java.text.NumberFormat.getInstance() – hands back the right formatter subclass for the current locale.
  • Collection.iterator() – each collection returns its own Iterator implementation without exposing the class.
  • Spring BeanFactory.getBean() – produces configured bean instances so callers never call new on concrete types.
  • JDBC DriverManager.getConnection() – yields a driver-specific Connection based on the connection URL.
  • javax.xml.parsers.DocumentBuilderFactory.newDocumentBuilder() – creates a parser implementation decided by configuration.
  • Logistics app – a Transport creator whose subclasses build a Truck or a Ship depending on the delivery type.
Code
public interface Notification {
    void send(String msg);
}

public class EmailNotification implements Notification {
    public void send(String msg) {
        System.out.println("Email: " + msg);
    }
}

public class SmsNotification implements Notification {
    public void send(String msg) {
        System.out.println("SMS: " + msg);
    }
}

public abstract class NotificationCreator {
    # The factory method
    abstract Notification create();

    public void notify(String msg) {
        Notification n = create();
        n.send(msg);
    }
}

public class EmailCreator extends NotificationCreator {
    Notification create() {
        return new EmailNotification();
    }
}

void main() {
    NotificationCreator c = new EmailCreator();
    c.notify("Hello");
}
How the Factory Method works

Notification is the abstract product; each concrete class implements it.

NotificationCreator declares the abstract factory method create().

Subclasses like EmailCreator decide which concrete product to return.

The client works only with the creator and product interfaces, never with new on a concrete type.
