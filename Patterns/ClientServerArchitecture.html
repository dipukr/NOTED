Client-server Architecture

The client-server model is a computing model where client devices request resources or services from a centralized server, which processes the request and provides a response.

It is also called the request-response model: the client sends a request and waits for the server's response before sending another.

It does not support continuous flow of data such as live streaming on its own.

For updates the client must ask the server; the server does not push real-time updates by itself.

When to use / Key points
  • The default model for web and REST APIs.
  • Good when interactions are naturally request-then-response.
  • Centralizes data and business logic on the server.
  • Use WebSockets or SSE when real-time push is required instead.
Advantages
  • Centralized control over data, security, and updates.
  • Clients stay thin and simple.
  • Well understood, with mature tooling and protocols.
Disadvantages / Trade-offs
  • The server can become a bottleneck or single point of failure.
  • No native real-time push; clients must poll for updates.
  • Every interaction pays a network round-trip cost.
Code
# Server exposes a resource; the client requests it
@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserService service;

    public UserController(UserService service) {
        this.service = service;
    }

    @GetMapping("/{id}")
    public ResponseEntity<UserDto> getUser(@PathVariable Long id) {
        # client sends request, server responds once
        return ResponseEntity.ok(service.findById(id));
    }
}
How it works

The client issues a request to a known server endpoint.

The server processes it and returns exactly one response.

No further data arrives until the client asks again.
