Observer Pattern

Observer pattern is a behavioral design pattern that defines a one-to-many dependency between objects.

In this pattern an object known as subject maintains a list of its dependent objects known as observers.

When the subject's state changes, all objects that depend on it are notified and updated automatically by subject.

When-to use
  • Use Observer when you want to automatically notify multiple objects of state changes.
  • Great for event-driven systems, GUIs, distributed messaging, and real-time updates.
  • Think of it as a push-based notification system for objects.
Components
  • Subject – The core object being observed. Maintains a list of observers.
  • Observer – Interface that defines the update method.
  • ConcreteSubject – Implements subject and notifies observers.
  • ConcreteObserver – Implements observer and responds to state changes.
Code
public interface Observer {
    void update(String news);
}

public class NewsAgency {                  # Subject
    private List<Observer> observers = new ArrayList<>();

    void subscribe(Observer o) { observers.add(o); }
    void unsubscribe(Observer o) { observers.remove(o); }

    void publish(String news) {
        for (Observer o : observers) o.update(news);
    }
}

public class Subscriber implements Observer {
    private String name;
    Subscriber(String name) { this.name = name; }
    public void update(String news) {
        System.out.println(name + " received: " + news);
    }
}

void main() {
    NewsAgency agency = new NewsAgency();
    agency.subscribe(new Subscriber("Amit"));
    agency.publish("Breaking news!");
}
How the Observer works
  • NewsAgency is the subject holding a list of observers.
  • Subscriber implements update() to react to changes.
  • publish() notifies every registered observer.
  • Observers can subscribe or unsubscribe without touching the subject's logic.
