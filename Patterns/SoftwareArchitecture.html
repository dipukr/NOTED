Software Architecture

Architecture of a system describes its major components, their relationships, and how they interact with each other.

It is the high-level, strategic blueprint of a system, defining its overall structure and core components to meet business needs.

Architecture defines the what and why, while design covers the how of specific implementation.

It addresses non-functional requirements like security, performance, and scalability across the whole system.

When to use / Key points
  • Choosing an overall pattern like microservices, monolith, or serverless.
  • Addressing cross-cutting concerns: security, performance, scalability.
  • Defining interactions between major components and external systems.
  • Decisions here are expensive to reverse, so they are made early and deliberately.
Advantages
  • Gives the team a shared mental model of the system.
  • Aligns technical structure with business goals.
  • Makes quality attributes (scalability, resilience) explicit up front.
Disadvantages / Trade-offs
  • Wrong early decisions are costly and disruptive to change later.
  • Over-architecting adds complexity the product may never need.
  • Requires balancing many competing quality attributes.
Code
# A layered architecture expressed through Spring stereotypes
@RestController
@RequestMapping("/orders")
public class OrderController {

    private final OrderService service; # presentation -> service layer

    public OrderController(OrderService service) {
        this.service = service;
    }

    @GetMapping("/{id}")
    public OrderDto get(@PathVariable Long id) {
        return service.findById(id);
    }
}

@Service
class OrderService {           # business layer
    private final OrderRepository repo; # -> data layer
    OrderService(OrderRepository repo) { this.repo = repo; }
    OrderDto findById(Long id) { return new OrderDto(repo.load(id)); }
}
How it works
  • Each layer talks only to the one directly below it, a key architectural rule.
  • @RestController, @Service mark component boundaries clearly.
  • Swapping the data layer never touches the controller, keeping change localized.
