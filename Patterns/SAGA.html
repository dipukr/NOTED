SAGA Pattern

The Saga pattern is a design pattern used in microservices architecture to manage distributed transactions.

It allows a sequence of local transactions across multiple services, ensuring data consistency even when individual services fail.

For each local transaction a corresponding compensating transaction is defined to undo it.

It relies on asynchronous communication to trigger subsequent transactions and compensating actions.

When to use / Key points
  • Use when a business operation spans several services and databases.
  • Orchestration: a central coordinator instructs each service when to act.
  • Choreography: services react to events published by other services.
  • On failure, compensating transactions run in reverse to undo prior steps.
Advantages
Data Consistency

Maintains data consistency across services without relying on distributed ACID transactions.

Loose Coupling

Keeps services loosely coupled through asynchronous messaging.

Local Ownership

Each service manages only its own local transaction.

Disadvantages
Added Complexity

Compensating logic adds significant complexity to the system.

Eventual Consistency

Provides only eventual consistency, not immediate isolation.

Hard to Debug

Debugging long, multi-step sagas is difficult.

Code
# Orchestration-style saga coordinator
@Service
public class OrderSaga {

    private final PaymentClient payment;
    private final InventoryClient inventory;

    public OrderSaga(PaymentClient payment, InventoryClient inventory) {
        this.payment = payment;
        this.inventory = inventory;
    }

    public void execute(Order order) {
        payment.charge(order);          # step 1 local txn
        try {
            inventory.reserve(order);   # step 2 local txn
        } catch (Exception e) {
            payment.refund(order);      # compensating txn undoes step 1
            throw e;
        }
    }
}
How it works

Each step is a local transaction in its own service.

If a later step fails, refund compensates the earlier one.

Consistency is achieved without a global distributed transaction.
