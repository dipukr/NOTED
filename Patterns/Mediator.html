Mediator Pattern

Mediator is a behavioral design pattern that promotes loose coupling between objects by centralizing communication between them.

Instead of objects referring to each other directly, they communicate through a mediator object.

This makes the system easier to maintain, modify, and scale, especially as the number of objects increases.

Mediator pattern focuses on simplifying communication between objects by managing and coordinating their interations through a mediator.

Mediator pattern is used for coordinating communication while the proxy pattern is used for controlling access.

Components
  • Mediator interface: Declares the communication contract used by components.
  • ConcreteMediator: Implements coordination logic and knows all components (colleagues).
  • Colleague: Individual objects that communicate via mediator. Knows about the mediator but not other colleagues.
Pros and Cons
Low Coupling

Promotes low coupling between components by routing their communication through a central mediator.

Easier Maintenance

Simplifies maintenance and enhances reusability since components no longer depend on each other directly.

Centralized Communication

Centralizes complex communications in one place, making the interactions easier to follow and manage.

God Object Risk

The mediator can become a God object if it accumulates too much responsibility and grows too complex.

Poor Scalability

Too much logic packed inside the mediator can lead to poor scalability as the system grows.

Real-world example
  • java.util.Timer — coordinates scheduling and execution of TimerTask objects without them knowing each other.
  • Spring ApplicationEventPublisher — publishers and listeners communicate through the central event multicaster, not directly.
  • JMS message broker — producers and consumers exchange messages via the broker rather than point-to-point links.
  • Air traffic control tower — pilots coordinate takeoffs and landings through the tower instead of talking to each other.
  • Chat room server — users send messages to the server, which relays them to the other participants.
  • GUI dialog controller — a form controller mediates between buttons, text fields, and checkboxes to enable or disable them.
  • Enterprise Service Bus — services integrate through the bus, which routes and transforms messages between them.
Code
public interface ChatMediator {
    void send(String msg, User from);
}

public class ChatRoom implements ChatMediator {
    private List<User> users = new ArrayList<>();
    void register(User u) { users.add(u); }

    public void send(String msg, User from) {
        for (User u : users)
            if (u != from) u.receive(msg);
    }
}

public class User {
    private String name;
    private ChatMediator mediator;
    User(String name, ChatMediator m) { this.name = name; mediator = m; }

    void send(String msg) { mediator.send(msg, this); }
    void receive(String msg) {
        System.out.println(name + " got: " + msg);
    }
}

void main() {
    ChatRoom room = new ChatRoom();
    User a = new User("Amit", room);
    User b = new User("Bina", room);
    room.register(a); room.register(b);
    a.send("Hello");  # Bina got: Hello
}
How the Mediator works

ChatRoom is the mediator that routes all messages.

User objects never reference each other directly.

A user calls send(); the mediator decides who receives it.

Adding a new user needs no change to existing users.
