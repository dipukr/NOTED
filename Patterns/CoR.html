Chain of Responsibility Pattern

CoR design pattern is a behavioral design pattern that decouples sender and receiver of a request by connecting multiple handlers in a chain.

The request is then passed along the chain until it is processed by one of the handlers.

When-to use
  • When we have multiple objects that can handle a request but the specific object that handles it is determined at runtime.
Components
  • Handler interface: Declares a method for handling requests and a reference to the next handler.
  • ConcreteHandler: Handles requests it is responsible for or forwards them to the next handler.
  • Client: Sends the request to the first handler in the chain.
Workflow
  • A client sends a request to the first handler in the chain, if the handler can handle it, it does.
  • Otherwise, it forwards the request to the next handler in the chain.
  • This continues until the request is handled or the end of the chain is reached.
Real-world example
  • Java Servlet Filter chain – each filter processes the request and calls FilterChain.doFilter to pass it on.
  • Spring Security filter chain – authentication and authorization filters are linked, each handling or forwarding the request.
  • Java util logging – a log record travels up parent loggers until a handler at the right level processes it.
  • Servlet HandlerInterceptor and middleware – Express or ASP.NET middleware pipelines pass a request through ordered handlers.
  • Try-catch exception propagation – an exception bubbles up the call stack until a matching catch block handles it.
  • Expense approval workflow – a request moves from manager to director to VP until someone with enough authority approves it.
  • Technical support escalation – a ticket goes from level 1 to level 2 to level 3 until an agent can resolve it.
Code
public abstract class Handler {
    protected Handler next;

    public Handler setNext(Handler next) {
        this.next = next;
        return next;
    }

    public abstract void handle(int amount);
}

public class Manager extends Handler {
    public void handle(int amount) {
        if (amount <= 1000)
            System.out.println("Manager approved " + amount);
        else if (next != null)
            next.handle(amount);
    }
}

public class Director extends Handler {
    public void handle(int amount) {
        if (amount <= 10000)
            System.out.println("Director approved " + amount);
        else if (next != null)
            next.handle(amount);
    }
}

void main() {
    Handler chain = new Manager();
    chain.setNext(new Director());
    chain.handle(5000);  # Director approved 5000
}
How the chain works

Handler holds a reference to the next handler.

Each concrete handler either processes the request or forwards it.

Manager handles small amounts; larger ones flow to Director.

The client calls only the first handler and stays unaware of who handles it.
