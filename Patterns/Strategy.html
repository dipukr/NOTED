Strategy Pattern

Strategy is a behavioral design pattern that defines a family of algorithms, encapsulates each one in its own class, and makes them interchangeable.

The strategy lets the algorithm vary independently from the clients that use it.

The context holds a reference to a strategy object and delegates the work to it, so the behavior can be swapped at runtime.

When to use
  • When you have several variants of an algorithm and want to switch between them.
  • When you want to choose an algorithm's behavior at runtime.
  • When many related classes differ only in their behavior.
  • Typical uses: sorting strategies, payment methods, compression algorithms, and routing.
Advantages
Runtime Swapping

Algorithms can be swapped at runtime without changing the context.

Encapsulated Details

Isolates algorithm implementation details from the code that uses it.

Removes Conditionals

Replaces conditional logic for selecting behavior with polymorphism.

Open/Closed Principle

Follows the Open/Closed Principle, so new strategies add cleanly.

Disadvantages
More Classes

Increases the number of objects and classes in the application.

Client Awareness

Clients must be aware of the differences to choose the right strategy.

Possible Overkill

Overkill if the algorithm rarely changes or has only one variant.

Real-world example
  • java.util.Comparator – passing different Comparator objects to Collections.sort or List.sort swaps the ordering algorithm.
  • Java layout managers – Swing containers delegate positioning to interchangeable LayoutManager strategies like BorderLayout and GridLayout.
  • Spring Resource loading – ResourceLoader picks different Resource strategies (classpath, file, URL) based on the location prefix.
  • Spring PlatformTransactionManager – the transaction behavior varies by implementation (JPA, JDBC, JTA) behind one interface.
  • Payment checkout – an online store applies card, UPI, or wallet payment strategies chosen at runtime.
  • Compression tools – an archiver selects ZIP, GZIP, or RAR compression strategies for the same file operation.
  • Navigation apps – a maps app switches between driving, walking, and transit route-calculation strategies.
Code
public interface PaymentStrategy {
    void pay(int amount);
}

public class CardPayment implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("Paid " + amount + " by card");
    }
}

public class UpiPayment implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("Paid " + amount + " by UPI");
    }
}

public class Checkout {                   # Context
    private PaymentStrategy strategy;
    void setStrategy(PaymentStrategy s) { strategy = s; }
    void checkout(int amount) { strategy.pay(amount); }
}

void main() {
    Checkout checkout = new Checkout();
    checkout.setStrategy(new UpiPayment());
    checkout.checkout(500);  # Paid 500 by UPI
}
How the Strategy works

PaymentStrategy is the common algorithm interface.

CardPayment and UpiPayment are interchangeable strategies.

Checkout delegates to whichever strategy it holds.

The behavior can be swapped at runtime with setStrategy().
