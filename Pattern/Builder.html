Builder Pattern

Builder is a creational design pattern that provides a step-by-step approach for constructing complex objects.

This separates the process of constructing an object from its final representation, allowing the same construction mechanism to create objects with different configurations. It is particularly useful when an object has many required and optional parameters, helping avoid large or telescoping constructors while making object creation more readable, flexible, and maintainable. The final object is also commonly designed to be immutable.

When to use
  • When an object requires many parameters, several of them optional.
  • When you want to avoid long, ambiguous telescoping constructors.
  • When you want to build an immutable object in readable steps.
  • When the construction process should be independent of the parts that make up the object.
  • When you need to enforce validation before the object is created.
Pros and Cons
Readable Creation

Produces highly readable, self-documenting object creation code.

Clean Optional Params

Handles optional parameters cleanly without multiple constructors.

Immutable Objects

Allows the final object to be immutable and thread-safe.

Isolated Construction

Isolates complex construction logic from the object itself.

Pre-build Validation

Enables validation of the object state before it is built.

Extra Boilerplate

Requires writing extra boilerplate for the builder class.

More Classes

Increases the overall number of classes in the codebase.

Overkill For Simple

Can be overkill for simple objects with few fields.

Real-world example
  • StringBuilder — appends characters step by step through chained calls before producing the final string.
  • Stream.Builder in Java — adds elements one at a time and then calls build to create a stream.
  • Lombok @Builder — generates a fluent builder class for any annotated POJO at compile time.
  • HttpRequest.newBuilder (Java 11 HttpClient) — sets URI, headers, and method fluently before building an immutable request.
  • Spring SpringApplicationBuilder — configures sources, profiles, and properties step by step to bootstrap an application.
  • OkHttp Request.Builder and Retrofit.Builder — assemble HTTP requests and client instances through chained configuration.
  • Ordering a custom meal — you choose bun, patty, and toppings one by one, and the burger is assembled at the end.
Code
public class User {
    private final String name;      # required
    private final int age;          # optional
    private final String email;     # optional

    private User(Builder b) {
        this.name  = b.name;
        this.age   = b.age;
        this.email = b.email;
    }

    public static class Builder {
        private final String name;
        private int age;
        private String email;

        public Builder(String name) {
            this.name = name;
        }
        public Builder age(int age) {
            this.age = age; return this;
        }
        public Builder email(String email) {
            this.email = email; return this;
        }
        public User build() {
            return new User(this);
        }
    }
}

void main() {
    User u = new User.Builder("Alice")
                    .age(30)
                    .email("alice@mail.com")
                    .build();
}
How the Builder works

The User constructor is private, objects are created only through the builder.

Required fields go into the Builder constructor; optional ones use fluent setters.

Each setter returns this, allowing calls to be chained.

build assembles a final, immutable User instance.
