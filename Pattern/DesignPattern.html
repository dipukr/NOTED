Design Patterns

Design patterns are reusable solutions to commonly occurring problems in software design.

Design patterns are solutions or techniques to avoid code design problems.

Design patterns help us write robust, clean, modular and extensible code.

They provide a template for solving design issues in various contexts, helping developers write code that is more maintainable, scalable and understandable. Design patterns are divided into three categories.


C
Creational

Deals with object creation — how objects are instantiated, hiding the construction details.

S
Structural

Deals with object composition — how classes and objects assemble into larger structures.

B
Behavioral

Deals with object interaction and responsibility — how objects communicate and share work.


Reusability

Provide a reusable solution to common software design problems, saving developers from reinventing the wheel whenever they hit a new problem — they reach for a tried and tested pattern instead.

Maintainability

Promote clean, organized, maintainable code, making it easier to maintain and modify as the software evolves.

Rapid Development

Provide a standard way to solve common design problems, saving time and effort so developers can focus on other aspects of the software.

Common Vocabulary

Give teams a shared language — saying “use a Strategy here” conveys an entire design in two words, making discussion and reviews faster.

Flexibility and Extensibility

Favor loose coupling and programming to interfaces, so new behavior can be added with little or no change to existing, tested code.

Testability

Well-separated responsibilities and injected dependencies make components easy to isolate and unit test.

SingletonCreationalEnsures a class has only one instance and gives a global point of access to it.
BuilderCreationalBuilds a complex object step by step, separating construction from its representation.
Factory MethodCreationalDefines an interface for creating an object but lets subclasses decide which class to instantiate.
Abstract FactoryCreationalCreates families of related objects without specifying their concrete classes.
PrototypeCreationalCreates new objects by cloning an existing instance instead of building from scratch.
AdapterStructuralConverts one interface into another that the client expects.
BridgeStructuralDecouples an abstraction from its implementation so the two can vary independently.
CompositeStructuralTreats individual objects and groups of objects uniformly as a tree.
DecoratorStructuralAdds responsibilities to an object dynamically by wrapping it.
FacadeStructuralProvides a simplified, unified interface to a complex subsystem.
FlyweightStructuralShares common state across many objects to save memory.
ProxyStructuralProvides a placeholder that controls access to another object.
Chain of ResponsibilityBehavioralPasses a request along a chain of handlers until one of them handles it.
CommandBehavioralEncapsulates a request as an object so it can be queued, logged, or undone.
IteratorBehavioralAccesses elements of a collection in sequence without exposing its structure.
MediatorBehavioralCentralizes communication between objects to reduce direct coupling.
MementoBehavioralCaptures and restores an object's state without breaking encapsulation.
ObserverBehavioralNotifies dependent objects automatically when a subject's state changes.
StateBehavioralLets an object change its behavior when its internal state changes.
StrategyBehavioralDefines a family of interchangeable algorithms and swaps them at runtime.
Template MethodBehavioralDefines the skeleton of an algorithm, letting subclasses fill in specific steps.
VisitorBehavioralAdds new operations to an object structure without changing its classes.
