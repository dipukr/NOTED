Facade

Facade pattern is a structural design pattern that provides a unified interface to a set of interfaces in a subsystem.

A complex interface to the client is considered as a fault in the design of a system.

Facade defines a higher-level interface that makes the subsystem easier to use.

Facade pattern makes a complex interface easier to use using a Facade class.

When-to use
  • When you want to simplify the usage of a complex system.
  • When there are multiple subsystems that need to be integrated.
  • To decouple clients from the internal components of a system.
  • When you want to create a layered architecture.
Pros and Cons
Simplifies Interfaces

It provides a single, unified interface that hides the complexity of the underlying subsystems.

Easier To Use

It makes the system easier to use by exposing only the operations clients actually need.

Promotes Loose Coupling

It decouples clients from the internal components, reducing dependencies between them.

Improves Readability

It improves code readability by keeping client code clean and focused on high-level intent.

Real-world example
  • SLF4J — provides a simple logging facade over backends like Logback, Log4j and Java logging.
  • JDBC DriverManager — offers a unified interface hiding vendor-specific database driver complexity.
  • Spring JdbcTemplate — wraps connection, statement and result-set handling behind simple query methods.
  • SLF4J LoggerFactory and Java Faces external context — hide framework wiring behind one entry point.
  • FacesContext — acts as a facade over the whole JSF request-processing subsystem.
  • Home theater remote — a single button turns on the TV, receiver and player, hiding each device.
  • Car ignition — turning the key starts fuel, ignition and electrical systems through one action.
public class PaymentService {
    public void processPayment() {
        System.out.println("Payment processed");
    }
}

public class NotificationService {
    public void sendNotification() {
        System.out.println("Notification sent");
    }
}

public class OrderFacade {

    @Autowired
    private PaymentService paymentService;

    @Autowired
    private NotificationService notificationService;

    public void placeOrder() {
        paymentService.processPayment();
        notificationService.sendNotification();
    }
}
How the Facade works

PaymentService and NotificationService
are subsystem classes.

OrderFacade provides one simple entry point for the client.

The client does not need to call each subsystem directly.

placeOrder() coordinates the required subsystem operations.
