Prototype Pattern

Prototype is a creational design pattern that lets you create new objects by copying an existing object, known as the prototype, instead of instantiating from scratch.

It is useful when object creation is costly or complex, and when a new object should start as a duplicate of a configured instance.

In Java the pattern is often implemented with the Cloneable interface and the clone() method, taking care to choose between shallow and deep copying.

When to use
  • When creating an object is expensive compared to copying an existing one.
  • When you want to avoid a hierarchy of factory classes.
  • When objects have only a few different states you can configure once.
  • When the concrete type to instantiate is decided at runtime.
  • When you need many similar objects that differ only slightly.
Advantages
  • Avoids the cost of expensive object initialization.
  • Lets you clone objects without coupling to their concrete classes.
  • Reduces the need for repeated subclassing of factories.
  • Allows adding and removing prototypes at runtime.
  • Produces complex pre-configured objects conveniently.
Disadvantages
  • Cloning objects with circular references can be tricky.
  • Deep copying of complex object graphs is hard to implement correctly.
  • Java's default clone() is shallow and can cause shared-reference bugs.
Code
class Document implements Cloneable {
    private String title;
    private List<String> pages;

    public Document(String title, List<String> pages) {
        this.title = title;
        this.pages = pages;
    }

    @Override
    public Document clone() {
        // Deep copy of the mutable list
        return new Document(title, new ArrayList<>(pages));
    }

    public void setTitle(String t) { this.title = t; }
}

void main() {
    Document original =
        new Document("Draft", new ArrayList<>());
    Document copy = original.clone();
    copy.setTitle("Final");  // original unaffected
}
How the Prototype works
  • Document implements Cloneable and overrides clone().
  • The overridden clone() copies the mutable pages list to give a true deep copy.
  • New objects are produced by copying an existing prototype, not via new with full setup.
  • Changing the copy leaves the original untouched because its data was duplicated.
