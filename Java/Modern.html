Modern Java: Features After Java 8

Java 8 (2014) was a turning point: it brought lambdas, streams, Optional and the java.time API. The releases after it changed the language and the platform even more. Since Java 10 (2018) a new feature release ships every six months, and every few releases is a long-term support (LTS) release: 11, 17, 21 and 25.

This page covers the important features from Java 9 to Java 25, grouped by topic, with an example for each. The examples print with IO.println, which was added in Java 25; on older versions use System.out.println. For Java basics, see Java.

1. Local Variable Type Inference: var (Java 10)

var lets the compiler infer the type of a local variable from its initializer. The variable is still statically typed: var only saves you from writing the type.

var names = new ArrayList<String>(); # Inferred as ArrayList<String>
var counts = new HashMap<String, Integer>();
for (var entry : counts.entrySet()) {
    IO.println(entry.getKey() + " = " + entry.getValue());
}
BiFunction<Integer, Integer, Integer> add = (@NonNull var a, @NonNull var b) -> a + b; # Java 11: var in lambda parameters
  • Allowed: local variables with an initializer, the variable of an enhanced for loop, a classic for loop index, and try-with-resources variables.
  • Not allowed: fields, method parameters, return types, variables without an initializer, and var x = null;.
  • Lambda parameters (Java 11): var in lambda parameters is mainly useful for adding annotations to them.

Use var when the type is obvious from the right-hand side, as in var list = new ArrayList<String>(). Spell out the type when it helps the reader, for example when the value comes from a method call whose return type is not obvious.

2. Switch Expressions (Java 14)

switch can now be an expression that produces a value. The arrow form case X -> does not fall through, so break is no longer needed, and one case can list several labels. A block uses yield to return its value. For enums and sealed types, the compiler checks that every case is covered.

public enum Day { MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY }

int letters = switch (day) {
    case MONDAY, FRIDAY, SUNDAY -> 6;
    case TUESDAY -> 7;
    case THURSDAY, SATURDAY -> 8;
    case WEDNESDAY -> {
        int length = day.name().length(); # A block returns its value with yield
        yield length;
    }
};

The arrow form also works in a switch statement, which removes the risk of accidental fall-through in ordinary code.

3. Text Blocks (Java 15)

A text block is a multi-line string literal between """ delimiters. The compiler removes the common leading indentation, so the text can be indented together with the code. Inside a text block, \ at the end of a line joins it with the next line, and \s keeps a trailing space.

String json = """
        {
          "id": 42,
          "name": "Laptop Pro"
        }
        """;
String sql = """
        SELECT id, name
        FROM orders
        WHERE status = 'NEW'\
        """; # The \ at the end of a line removes the final newline

Text blocks are useful for JSON, SQL, HTML and test data. Combine them with formatted(...) to fill in values.

4. Records (Java 16)

A record is a concise, immutable data carrier. From the header record Point(int x, int y), the compiler generates private fields, a canonical constructor, accessor methods x() and y() (not getX()), and equals, hashCode and toString. A compact constructor validates or normalizes the arguments before the fields are assigned.

public record Point(int x, int y) {
    public Point { # Compact constructor: runs before the fields are assigned
        if (x < 0 || y < 0) throw new IllegalArgumentException("Coordinates must be positive");
    }

    public double distanceToOrigin() {
        return Math.sqrt(x * x + y * y);
    }
}

var p = new Point(3, 4);
IO.println(p.x()); # 3
IO.println(p); # Point[x=3, y=4]
IO.println(p.equals(new Point(3, 4))); # true
  • Records are implicitly final and cannot extend another class, but they can implement interfaces.
  • Their fields cannot be changed after construction. A record can still hold a reference to a mutable object, such as a List, so copy such arguments with List.copyOf in the compact constructor.
  • Records can have static fields and methods, instance methods and nested types, but no extra instance fields.
  • Records work well as DTOs, API responses, map keys, value objects and results of multi-value methods.
5. Pattern Matching for instanceof (Java 16)

instanceof can declare a variable that is bound when the test succeeds, so the cast disappears. The variable is in scope only where the match is known to have succeeded.

if (obj instanceof String) { # Before Java 16
    String s = (String) obj;
    IO.println(s.length());
}

if (obj instanceof String s && !s.isBlank()) { # Java 16: test, cast and bind in one step
    IO.println(s.toUpperCase());
}
6. Sealed Classes and Interfaces (Java 17)

A sealed class or interface lists exactly which types may extend or implement it, with permits. Each permitted subclass must be final, sealed or non-sealed. Records are implicitly final, so they fit naturally. Because the set of subtypes is closed, the compiler can check that a switch covers all of them.

public sealed interface Shape permits Circle, Square, Rectangle {}

public record Circle(double radius) implements Shape {}

public record Square(double side) implements Shape {}

public non-sealed class Rectangle implements Shape { # non-sealed: open again for further subclassing
    private double width;
    private double height;

    public double area() {
        return width * height;
    }
}

Sealed types model a fixed set of alternatives, such as payment methods, events or the outcome of an operation. They are the Java equivalent of algebraic data types in functional languages.

7. Pattern Matching for switch (Java 21)

switch can match on the type of any object. A case can add a guard with when, case null handles null explicitly, and a switch over a sealed type needs no default when all subtypes are covered.

double area(Shape shape) {
    return switch (shape) {
        case Circle c -> Math.PI * c.radius() * c.radius();
        case Square s when s.side() == 0 -> 0; # Guard: an extra condition after when
        case Square s -> s.side() * s.side();
        case Rectangle r -> r.area();
    };
}

String describe(Object obj) {
    return switch (obj) {
        case null -> "null"; # Without this case, a null selector throws NullPointerException
        case Integer i when i > 0 -> "positive int " + i;
        case Integer i -> "int " + i;
        case String s -> "string of length " + s.length();
        default -> "something else";
    };
}

If a new class is added to permits Circle, Square, Rectangle, the area method stops compiling until the new case is handled. More specific cases must come before more general ones; the compiler reports a case that can never match.

8. Record Patterns (Java 21)

A record pattern matches a record and deconstructs it into its components in one step. Patterns can be nested, and var can be used for component types.

public record Line(Point start, Point end) {}

if (obj instanceof Point(int x, int y)) {
    IO.println("x = " + x + ", y = " + y);
}
Line line = new Line(new Point(0, 0), new Point(3, 4));
if (line instanceof Line(Point(var x1, var y1), Point(var x2, var y2))) { # Nested record patterns
    IO.println("dx = " + (x2 - x1) + ", dy = " + (y2 - y1));
}
9. Unnamed Variables and Patterns (Java 22)

An underscore _ declares a variable or pattern component that is never used. It makes the intent clear and removes warnings about unused variables.

int total = 0;
for (Order _ : orders) { # The element itself is not needed
    total++;
}
try {
    Integer.parseInt(text);
} catch (NumberFormatException _) { # The exception object is not needed
    IO.println("Not a number");
}
map.forEach((_, value) -> IO.println(value)); # Ignore the key
if (obj instanceof Line(Point(var x, _), _)) { # Bind only the components that are used
    IO.println("start x = " + x);
}
10. Compact Source Files and Instance main Methods (Java 25)

A source file can now contain a main method, fields and other methods without declaring a class; the compiler wraps them in an implicitly declared class. main no longer has to be public static, and the String[] args parameter is optional. A compact source file automatically imports all packages of the java.base module, so List, Map and other common classes need no imports. The new java.lang.IO class provides IO.println, IO.print and IO.readln for simple console input and output.

void main(String[] args) {
    String name = IO.readln("What is your name? ");
    IO.println("Hello, " + name + "!");
}

This makes small programs and scripts much shorter, and it is a gentler start for learners. Larger programs still use ordinary classes.

11. Flexible Constructor Bodies (Java 25)

A constructor may now run statements before calling super(...) or this(...), as long as they do not use the object being constructed. This lets you validate or prepare arguments before calling the superclass constructor, instead of squeezing that logic into a static helper.

public class PositiveBigInteger extends BigInteger {
    public PositiveBigInteger(long value) {
        if (value <= 0) throw new IllegalArgumentException("Value must be positive"); # Runs before super()
        super(String.valueOf(value));
    }
}
12. Module Import Declarations (Java 25)

import module java.sql; imports all public top-level types from every package that the java.sql module exports, and from the modules it requires transitively. It replaces long lists of single-type and on-demand imports. If two imported packages contain a type with the same simple name, a single-type import resolves the conflict.

13. Private Interface Methods (Java 9)

Java 8 added default and static methods to interfaces. Java 9 adds private methods, so default methods can share code without exposing a helper to implementing classes.

public interface Logger {
    default void info(String message) {
        log("INFO", message);
    }

    default void error(String message) {
        log("ERROR", message);
    }

    private void log(String level, String message) { # Shared helper, not visible to implementing classes
        IO.println("[" + level + "] " + message);
    }
}
14. Smaller Language Improvements
  • Try-with-resources (Java 9): An effectively final variable declared before the try can be used as a resource directly: try (reader) { ... }.
  • Diamond with anonymous classes (Java 9): new Comparator<>() { ... } infers the type argument.
  • Underscore (Java 9): _ is no longer a valid identifier. Java 22 reused it for unnamed variables.
  • Helpful NullPointerExceptions (Java 14): The message names exactly what was null. For order.getCustomer().getName().length(), it says: Cannot invoke "String.length()" because the return value of "Customer.getName()" is null.
  • Markdown documentation comments (Java 23): Javadoc comments can be written in Markdown using /// lines instead of HTML inside /** ... */.
15. Module System (Java 9)

The Java Platform Module System (JPMS) groups packages into modules. A module declares, in module-info.java, which modules it depends on and which of its packages other modules may use. Packages that are not exported are inaccessible from outside, even through reflection, unless they are explicitly opened.

module-info.java
module com.example.orders {
    requires java.net.http; # A module this module depends on
    requires transitive com.example.common; # Modules that read this one also read com.example.common
    exports com.example.orders.api; # Only exported packages can be used by other modules
    opens com.example.orders.model to com.fasterxml.jackson.databind; # Allow reflection for one module
}

The JDK itself was split into about 70 modules, such as java.base, java.sql and java.net.http. That allows jlink to build a small runtime containing only the modules an application needs. Applications are not required to use modules: code on the class path keeps working as before, in the unnamed module.

16. Collection Factory Methods (Java 9 and 10)
List<String> list = List.of("a", "b", "c"); # Unmodifiable: add() throws UnsupportedOperationException
Set<Integer> set = Set.of(1, 2, 3);
Map<String, Integer> map = Map.of("one", 1, "two", 2);
Map<String, Integer> big = Map.ofEntries(Map.entry("one", 1), Map.entry("two", 2)); # For more than 10 pairs
List<String> copy = List.copyOf(names); # Java 10: unmodifiable copy of any collection
  • The collections are unmodifiable and do not allow null elements, keys or values.
  • Set.of and Map.of reject duplicate elements or keys, and their iteration order is not specified.
  • Collectors.toUnmodifiableList() (Java 10) and Stream.toList() (Java 16) also produce unmodifiable lists.
17. Sequenced Collections (Java 21)

New interfaces SequencedCollection, SequencedSet and SequencedMap give every collection with a defined order the same methods for the first and last elements and a reversed view. List, Deque, LinkedHashSet, SortedSet, LinkedHashMap and SortedMap implement them.

List<String> letters = new ArrayList<>(List.of("a", "b", "c"));
IO.println(letters.getFirst()); # a (before: letters.get(0))
IO.println(letters.getLast()); # c (before: letters.get(letters.size() - 1))
letters.addFirst("z");
IO.println(letters.reversed()); # [c, b, a, z]
var scores = new LinkedHashMap<String, Integer>();
scores.put("x", 1);
scores.put("y", 2);
IO.println(scores.firstEntry()); # x=1
IO.println(scores.pollLastEntry()); # y=2, and removes it
18. Stream API Additions
Stream.of(1, 2, 3, 4, 1).takeWhile(n -> n < 3).toList(); # [1, 2] (Java 9)
Stream.of(1, 2, 3, 4, 1).dropWhile(n -> n < 3).toList(); # [3, 4, 1] (Java 9)
Stream.iterate(1, n -> n <= 100, n -> n * 2).toList(); # [1, 2, 4, 8, 16, 32, 64] (Java 9)
Stream.ofNullable(value).count(); # 0 if value is null (Java 9)
List<String> names = people.stream().map(Person::name).toList(); # Unmodifiable list (Java 16)

Stream gatherers (Java 24)

Stream.gather(...) adds custom intermediate operations, the way collect(...) allows custom terminal operations. The Gatherers class provides ready-made ones.

Stream.of(1, 2, 3, 4, 5).gather(Gatherers.windowFixed(2)).toList(); # [[1, 2], [3, 4], [5]]
Stream.of(1, 2, 3, 4).gather(Gatherers.windowSliding(2)).toList(); # [[1, 2], [2, 3], [3, 4]]
Stream.of(1, 2, 3, 4).gather(Gatherers.scan(() -> 0, Integer::sum)).toList(); # Running totals: [1, 3, 6, 10]

22. HTTP Client (Java 11)

java.net.http.HttpClient replaces the old HttpURLConnection. It supports HTTP/1.1 and HTTP/2, synchronous and asynchronous calls, and WebSockets.

HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder(URI.create("https://api.example.com/orders/42"))
                                 .header("Accept", "application/json").GET().build();
HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString()); # Synchronous
IO.println(response.statusCode() + " " + response.body());
client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
      .thenApply(HttpResponse::body).thenAccept(IO::println); # Asynchronous: returns a CompletableFuture

24. Virtual Threads (Java 21)

Virtual threads are lightweight threads managed by the JVM instead of the operating system. Many virtual threads run on a small pool of platform (carrier) threads. When a virtual thread blocks, for example on I/O or Thread.sleep, the JVM unmounts it and the carrier thread runs another virtual thread. An application can therefore run millions of concurrent blocking tasks in the simple thread-per-request style, without reactive code.

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) { # One new virtual thread per task
    for (int i = 0; i < 10_000; i++) {
        int id = i;
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1)); # Blocking parks the virtual thread, not an OS thread
            return id;
        });
    }
} # close() waits until all tasks finish: about 1 second in total, not 10,000
Thread.ofVirtual().start(() -> IO.println("Hello from " + Thread.currentThread()));
Thread.startVirtualThread(() -> IO.println("Another virtual thread"));
  • Virtual threads are best for I/O-bound work, such as web requests, database calls and remote APIs. They do not make CPU-bound code faster.
  • Do not pool virtual threads. Create one per task; they are cheap. To limit access to a scarce resource, use a Semaphore.
  • Since Java 24, blocking inside a synchronized block no longer pins the virtual thread to its carrier thread.
  • In Spring Boot 3.2 and later, spring.threads.virtual.enabled=true runs request handling on virtual threads.
25. Scoped Values (Java 25)

A scoped value shares immutable data with the methods a thread calls, and with child threads, for a bounded period. It is a safer, cheaper alternative to ThreadLocal for passing context such as the current user or request ID: the value cannot be changed, and it is automatically unbound when the scope ends.

public class RequestContext {
    public static ScopedValue<String> USER = ScopedValue.newInstance();
}

ScopedValue.where(RequestContext.USER, "sam").run(() -> handleRequest()); # USER is bound only while run() executes

void handleRequest() {
    IO.println("Current user: " + RequestContext.USER.get());
}

Structured concurrency (preview)

Structured concurrency, a preview feature in Java 25, treats a group of related tasks running in different threads as one unit of work. If one subtask fails, the others are cancelled, and the parent waits for all of them before continuing, so no task is left running in the background.

Response handle() throws InterruptedException {
    try (var scope = StructuredTaskScope.open()) {
        Subtask<String> user = scope.fork(() -> findUser());
        Subtask<Integer> order = scope.fork(() -> fetchOrder());
        scope.join(); # Waits for both; throws if either subtask failed
        return new Response(user.get(), order.get());
    }
}
26. Foreign Function and Memory API (Java 22)

The Foreign Function and Memory API (java.lang.foreign) lets Java call native libraries and work with memory outside the heap safely, without writing JNI code in C. It replaces most uses of JNI and of sun.misc.Unsafe for off-heap memory.

Linker linker = Linker.nativeLinker();
MethodHandle strlen = linker.downcallHandle(linker.defaultLookup().find("strlen").orElseThrow(),
                                            FunctionDescriptor.of(ValueLayout.JAVA_LONG, ValueLayout.ADDRESS));
try (Arena arena = Arena.ofConfined()) { # Off-heap memory is freed when the arena closes
    MemorySegment text = arena.allocateFrom("Hello");
    long length = (long) strlen.invokeExact(text); # Calls the C function strlen: 5
}

Container awareness (Java 10)

The JVM reads the CPU and memory limits of its Docker or Kubernetes container instead of the host machine’s resources. Size the heap relative to the container with -XX:MaxRAMPercentage=75.

Faster startup: CDS and AOT cache (Java 10 to 25)

Class Data Sharing stores pre-parsed classes in an archive that is shared between JVM runs. Java 24 and 25 extend it into an ahead-of-time (AOT) cache: a training run records which classes are loaded and linked, and which methods are hot, so later runs start and warm up faster.

java -XX:AOTCacheOutput=app.aot -jar app.jar # Java 25: training run that creates the cache
java -XX:AOTCache=app.aot -jar app.jar # Later runs use the cache

Other JVM improvements

  • Compact object headers (Java 25): -XX:+UseCompactObjectHeaders shrinks object headers on 64-bit platforms from 12 to 8 bytes, which reduces heap usage.
  • Java Flight Recorder (Java 11): A low-overhead profiler built into the JVM, now open source: java -XX:StartFlightRecording=duration=60s,filename=app.jfr -jar app.jar.
  • UTF-8 by default (Java 18): File and stream APIs use UTF-8 when no charset is given, on every operating system.
  • Multi-release JARs (Java 9): One JAR can contain different class versions for different Java releases.
29. Removed and Deprecated
  • Java EE and CORBA modules removed (Java 11): JAXB (javax.xml.bind), JAX-WS and javax.annotation are no longer in the JDK. Add them as separate dependencies, now under the Jakarta EE names.
  • Nashorn removed (Java 15): The JavaScript engine is gone; use GraalJS if needed.
  • Strong encapsulation (Java 16 and 17): Code can no longer reach JDK internals through reflection; the --illegal-access option was removed. Use --add-opens for the rare cases that still need it.
  • Finalization deprecated for removal (Java 18): Use try-with-resources or Cleaner instead of finalize().
  • Security Manager permanently disabled (Java 24).
  • sun.misc.Unsafe memory access deprecated for removal (Java 23): Use VarHandle and the Foreign Function and Memory API instead.
Example: Result Type Instead of Exceptions

This example combines records, sealed interfaces, pattern matching for switch and record patterns. A service method returns a sealed Result that is either a success or one of a fixed set of failures, instead of returning null or throwing exceptions. The caller must handle every outcome, and the compiler enforces it.

public sealed interface Result<T> permits Ok, NotFound, InvalidInput, Forbidden {}

public record Ok<T>(T value) implements Result<T> {}

public record NotFound<T>() implements Result<T> {}

public record InvalidInput<T>(String reason) implements Result<T> {}

public record Forbidden<T>(String message) implements Result<T> {}

public class OrderService {
    public Result<Order> getOrderById(long id, User user) {
        if (id <= 0) return new InvalidInput<Order>("Order ID must be positive");
        if (user == null || !user.hasRole("VIEW_ORDERS"))
            return new Forbidden<Order>("Not authorized to view orders");
        return id == 1001 ? new Ok<Order>(new Order(id, "Laptop Pro", 1299.99)) : new NotFound<Order>();
    }
}

public String describeOrder(long id, User user) { # The compiler ensures every case is handled
    return switch (orderService.getOrderById(id, user)) {
        case Ok(Order o)                 -> "Order %d: %s ($%.2f)".formatted(o.id(), o.name(), o.price());
        case NotFound()                  -> "Order not found";
        case InvalidInput(String reason) -> "Invalid request: " + reason;
        case Forbidden(String message)   -> "Access denied: " + message;
    };
}
  • Each failure record is generic (NotFound<T> and so on), so it can stand in for any Result<T>. A failure that implements Result<Void> could not be returned from a method declared to return Result<Order>.
  • The switch has no default branch. Because Result is sealed, the compiler knows these four cases cover every possibility.
  • Record patterns such as case InvalidInput(String reason) test the type and pull out the component in one step, so no cast or accessor call is needed.
Example: Sealed Interface in a Compact Source File

This Java 25 program uses a sealed interface, records, a pattern-matching switch and an unnamed variable _ for the case that needs no data. Types declared in a compact source file become members of the implicitly declared class.

public sealed interface Answer permits RealAnswer, NoAnswer {}

public record RealAnswer(String value) implements Answer {}

public record NoAnswer() implements Answer {}

void main(String[] args) {
    List<Answer> answers = List.of(new RealAnswer("Yes, absolutely"), new NoAnswer(), new RealAnswer("42"), new NoAnswer());
    for (Answer a : answers) {
        switch (a) {
            case RealAnswer r -> IO.println("Answer: " + r.value());
            case NoAnswer _ -> IO.println("No answer provided");
        }
    }
}

Output:

Answer: Yes, absolutely
No answer provided
Answer: 42
No answer provided
