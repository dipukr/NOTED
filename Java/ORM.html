ORM and JPA

Object-relational mapping (ORM) is the process of mapping Java objects to the tables of a relational database. Each row in a table corresponds to a single object, and each column corresponds to a field of that object.

ORM is a layer between an object-oriented language and the SQL language of a relational database. The ORM layer works like an adapter: it adapts the language of object graphs to the language of relational tables. In the object-oriented program, data is structured into object graphs; in the relational database, it is structured into tables.

The Java Persistence API (JPA) is the Java standard API for object-relational mapping, and one of many possible approaches to ORM. The API is a set of concepts that defines which objects within the application should be persisted and how they should be persisted.

JPA is only a specification, so it needs an implementation to work. The most popular implementation of JPA is Hibernate.

JPA is concerned with persistence, which means any mechanism by which Java objects outlive the application process that created them.

JPA

JPA is a specification: a set of rules that any ORM framework must implement to be part of the standard mechanism for persisting data in Java.

JPA is not a framework like Hibernate. It is only an interface that an ORM framework implements.

One of the main purposes of JPA is a standard approach to persisting data in Java, which improves interoperability between the ORM frameworks that implement it.

Imagine an application that uses Hibernate and later needs to replace it with another ORM tool, such as EclipseLink. If both follow the JPA standard, the switch is much easier. Even so, features native to one framework, outside the JPA standard, may not exist in the other; Hibernate has many such features.
