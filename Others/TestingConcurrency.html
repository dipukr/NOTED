Testing Concurrency

Concurrency bugs are non-deterministic, so ordinary unit tests rarely surface them.

Effective tests run many threads simultaneously and stress shared state repeatedly.

Tools like CountDownLatch, CyclicBarrier, and high iteration counts increase the chance of exposing races.

Static analyzers and stress harnesses complement runtime tests.

When to use / Key points
  • Use a barrier to release all threads at the same instant.
  • Run high iteration counts to widen the timing window.
  • Assert final invariants after all threads join.
  • Consider jcstress for rigorous memory-model testing.
Advantages
Exposes Hidden Races

Catches concurrency races that single-threaded tests would never surface.

Builds Confidence

Builds confidence in correctness before production deployment.

Deliberate Contention

Reproduces contention scenarios deliberately to stress shared state.

Disadvantages
No Absence Proof

Passing tests do not prove the absence of races.

Flaky Failures

Flaky failures are hard to reproduce and diagnose.

Slow And Machine-Specific

Timing-dependent tests can be slow and vary from machine to machine.

Code
public class CounterTest {

    @org.junit.jupiter.api.Test
    void concurrentIncrements() throws InterruptedException {
        int threads = 50, perThread = 1000;
        AtomicInteger counter = new AtomicInteger();
        CyclicBarrier start = new CyclicBarrier(threads);
        ExecutorService pool = Executors.newFixedThreadPool(threads);
        CountDownLatch done = new CountDownLatch(threads);

        for (int i = 0; i < threads; i++) {
            pool.submit(() -> {
                try {
                    start.await(); // fire all at once
                    for (int j = 0; j < perThread; j++) counter.incrementAndGet();
                } catch (Exception e) { /* ignore */ }
                finally { done.countDown(); }
            });
        }
        done.await();
        pool.shutdown();
        assertEquals(threads * perThread, counter.get());
    }
}
How it works

CyclicBarrier releases all threads simultaneously to maximize contention.

CountDownLatch lets the test wait for every worker to finish.

The final assertEquals verifies no increments were lost.
