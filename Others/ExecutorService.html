ExecutorService

ExecutorService manages a pool of worker threads and the tasks submitted to them.

It reuses threads to avoid the cost of creating one per task.

Tasks are submitted as Runnable or Callable and tracked via Future.

A pool limits concurrent threads, protecting the system from resource exhaustion.

When to use / Key points
  • Any workload with many short tasks that would otherwise spawn threads.
  • Create via the Executors factory (fixed, cached, scheduled).
  • Always shutdown() to release threads when done.
  • Use invokeAll/invokeAny for batches of tasks.
Pros and Cons
Thread Reuse

Reusing worker threads reduces the overhead of creating a new thread per task.

Bounded Resources

Bounded pools cap the number of concurrent threads and keep resource usage under control.

Rich Task Tracking

Futures provide results, cancellation and completion tracking for submitted tasks.

Thread Leaks

Forgetting to call shutdown() leaks worker threads.

Hidden Back-Pressure

Unbounded queues can hide back-pressure and grow memory unchecked.

Wrong Pool Sizing

Sizing the pool incorrectly causes contention or starvation.

Code
void main(String[] args) throws Exception {
    ExecutorService pool = Executors.newFixedThreadPool(4);

    List<Callable<Integer>> tasks = new ArrayList<>();
    for (int i = 1; i <= 5; i++) {
        final int n = i;
        tasks.add(() -> n * n);
    }

    List<Future<Integer>> results = pool.invokeAll(tasks);  // run all
    for (Future<Integer> f : results) System.out.println(f.get());

    pool.shutdown();     // release worker threads
}
How it works

newFixedThreadPool(4) creates four reusable workers.

invokeAll submits every task and returns their futures.

f.get() retrieves each computed result, blocking as needed.

shutdown stops accepting tasks and frees the threads.
