Exception Handling in Threads

An uncaught exception in a thread terminates that thread but not the whole application.

Because it does not propagate to the starting thread, such failures are silently lost by default.

An UncaughtExceptionHandler catches these so they can be logged or recovered.

With executors, exceptions surface through the returned Future.

When to use / Key points
  • Set an UncaughtExceptionHandler for raw threads.
  • Always inspect Future.get(), which rethrows as ExecutionException.
  • Wrap Runnable bodies in try/catch for fire-and-forget tasks.
  • Override afterExecute in a custom executor for centralized logging.
Advantages
  • Prevents silent failures from going unnoticed.
  • Centralizes error logging and alerting.
  • Enables graceful recovery or restart of failed work.
Disadvantages / Trade-offs
  • Easy to forget, leading to invisible thread death.
  • submit() swallows exceptions until get() is called.
  • Handlers add boilerplate to thread setup.
Code
public class SafeTasks {

    public void rawThread() {
        Thread t = new Thread(() -> {
            throw new RuntimeException("boom");
        });
        // catch what would otherwise be lost
        t.setUncaughtExceptionHandler((thread, ex) ->
            System.err.println(thread.getName() + " failed: " + ex));
        t.start();
    }

    public void viaExecutor() throws InterruptedException {
        ExecutorService pool = Executors.newSingleThreadExecutor();
        Future<?> f = pool.submit(() -> { throw new IllegalStateException(); });
        try {
            f.get(); // rethrows wrapped exception
        } catch (ExecutionException e) {
            System.err.println("Task error: " + e.getCause());
        }
        pool.shutdown();
    }
}
How it works

setUncaughtExceptionHandler catches errors that escape a raw thread's run.

submit() captures the exception inside the Future.

get() rethrows it as ExecutionException, exposing the original cause.
