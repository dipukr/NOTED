ReadWriteLock

ReadWriteLock separates locking into a shared read lock and an exclusive write lock.

Many threads can read concurrently as long as none is writing, since read-read sharing is safe.

Writes are exclusive: a writer blocks all readers and other writers.

ReentrantReadWriteLock is the standard implementation.

When to use / Key points
  • Ideal for read-heavy data structures with infrequent writes.
  • Read lock is shared; write lock is exclusive.
  • Supports lock downgrading (write to read) but not upgrading.
  • Not worth it if writes are frequent, contention overhead dominates.
Advantages
  • Higher throughput than a plain lock when reads dominate.
  • Readers do not block each other.
  • Supports fairness and reentrancy.
Disadvantages / Trade-offs
  • Overhead is higher than a simple lock for write-heavy workloads.
  • Risk of writer starvation without fairness.
  • No lock upgrade from read to write.
Code
public class Cache {

    private final Map<String, String> map = new HashMap<>();
    private final ReentrantReadWriteLock rw = new ReentrantReadWriteLock();

    public String get(String key) {
        rw.readLock().lock(); // shared read
        try {
            return map.get(key);
        } finally {
            rw.readLock().unlock();
        }
    }

    public void put(String key, String value) {
        rw.writeLock().lock(); // exclusive write
        try {
            map.put(key, value);
        } finally {
            rw.writeLock().unlock();
        }
    }
}
How it works

readLock() can be held by many threads at once for concurrent reads.

writeLock() is exclusive and blocks all readers and writers.

Each lock is released in finally to avoid leaking it on exceptions.
