Spin Locks

A spin lock is a lock where a thread repeatedly checks a flag in a loop instead of sleeping.

It "busy-waits", burning CPU cycles while it waits for the lock to become free.

In Java it is typically built with an AtomicBoolean or AtomicReference and CAS.

It only pays off when the critical section is extremely short and contention is low.

When to use / Key points
  • Only for very short critical sections where blocking overhead exceeds spin cost.
  • Built on compareAndSet for the acquire path.
  • Add Thread.onSpinWait() (Java 9+) to hint the CPU.
  • Avoid on single-core systems; the spinner starves the holder.
Advantages
  • No thread parking/unparking, so no context-switch cost.
  • Very low latency when the lock is released quickly.
  • Simple to implement with atomics.
Disadvantages / Trade-offs
  • Wastes CPU while spinning, harmful under high contention.
  • Can starve other threads and drain battery.
  • Poor choice for long-held locks.
Code
public class SpinLock {

    private final AtomicBoolean locked = new AtomicBoolean(false);

    public void lock() {
        // spin until we flip false -> true
        while (!locked.compareAndSet(false, true)) {
            Thread.onSpinWait(); // CPU hint, Java 9+
        }
    }

    public void unlock() {
        locked.set(false); // release
    }

    public void runGuarded(Runnable task) {
        lock();
        try {
            task.run();
        } finally {
            unlock();
        }
    }
}
How it works

compareAndSet(false, true) atomically grabs the lock only if it was free.

The while loop keeps retrying (spinning) until acquisition succeeds.

Thread.onSpinWait() tells the CPU this is a busy-wait, improving efficiency.
