ThreadPoolTaskExecutor

ThreadPoolTaskExecutor is Spring's wrapper around a Java ThreadPoolExecutor.

It exposes core pool size, max pool size, queue capacity, and keep-alive as simple properties.

It is the recommended executor bean backing @Async and other Spring async work.

Correct sizing is critical to avoid resource exhaustion or task rejection.

When to use / Key points
  • Back @Async methods with a bounded, tuned pool.
  • Threads grow to core size, then queue, then up to max.
  • Set a rejection policy for when the queue and pool are full.
  • Give threads a name prefix for easier debugging.
Pros and Cons
Property-Driven Config

Configuration is simple and driven entirely by properties.

Graceful Shutdown

It supports graceful shutdown integrated with the Spring lifecycle.

Bounded Resources

A bounded queue and pool prevent runaway thread creation.

Confusing Interplay

Misunderstood core, max, and queue interplay leads to surprises.

Hidden Latency

A large queue plus a small pool hides latency until it overflows.

Silent Task Drops

The wrong rejection policy can silently drop work.

Code
@Configuration
public class ExecutorConfig {

    @Bean("taskExecutor")
    public ThreadPoolTaskExecutor taskExecutor() {
        ThreadPoolTaskExecutor ex = new ThreadPoolTaskExecutor();
        ex.setCorePoolSize(8);
        ex.setMaxPoolSize(16);
        ex.setQueueCapacity(100);
        ex.setKeepAliveSeconds(60);
        ex.setThreadNamePrefix("async-");
        // run rejected tasks on the caller thread
        ex.setRejectedExecutionHandler(
            new ThreadPoolExecutor.CallerRunsPolicy());
        ex.initialize();
        return ex;
    }
}
How it works

Tasks run on core threads first, then queue, then expand toward max.

CallerRunsPolicy applies backpressure by running overflow on the caller.

initialize() builds the underlying ThreadPoolExecutor.
