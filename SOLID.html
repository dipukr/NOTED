SOLID Principles

Solid principle is a set of guidelines for writing code that makes it easier to manage, extend and debug.

Solid principle help us break big problem into smaller easier to handle parts.

Solid reduces dependencies on code so changes in one area won't break another.

Solid reduces tight coupling, making code more flexible and easier to maintain.

Code
# D: depend on an abstraction
public interface Switchable {
    void turnOn();
}

# S: Fan has a single responsibility
public class Fan implements Switchable {
    public void turnOn() { System.out.println("Fan on"); }
}

# Switch depends on Switchable, not Fan
public class Switch {
    private final Switchable device;
    Switch(Switchable device) { this.device = device; }
    public void press() { device.turnOn(); }
}
How SOLID is applied here
  • Switch depends on the Switchable abstraction, not Fan.
  • New devices implement Switchable without changing Switch (open/closed).
  • Any Switchable can substitute another (Liskov).
  • The small Switchable interface follows interface segregation.
