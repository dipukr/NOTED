Content Delivery Networks

A CDN is a geographically distributed network of edge servers that cache content near users.

Requests are routed to the closest edge, cutting latency and offloading the origin server.

CDNs serve static assets, media, and increasingly dynamic and API responses.

Cache behavior is controlled with TTLs, cache-control headers, and invalidation rules.

When to use / Key points
  • Use a CDN for images, CSS, JS, video, and downloadable files served globally.
  • Set correct Cache-Control and ETag headers so edges cache and revalidate.
  • Use cache busting (versioned filenames) instead of frequent purges.
  • CDNs also add TLS termination, DDoS protection, and edge compute.
Advantages
Lower Latency

Content is served from a nearby edge location, cutting round-trip time for users.

Reduced Origin Load

Caching at the edge lowers origin server load and bandwidth costs.

Higher Availability

Edge distribution improves resilience against traffic spikes and attacks.

Disadvantages
Stale Content

Outdated content can be served until caches expire or are purged.

Hard Invalidation

Invalidating caches across many edges instantly is difficult.

Added Cost

A CDN adds cost and another vendor dependency to the stack.

Code
// Set cache headers so a CDN can cache static responses
@RestController
public class AssetController {

    @GetMapping("/assets/logo")
    public ResponseEntity<byte[]> logo() {
        byte[] bytes = assetService.loadLogo();

        return ResponseEntity.ok()
                // public + long max-age lets the CDN cache aggressively
                .cacheControl(CacheControl.maxAge(Duration.ofDays(30)).cachePublic())
                .eTag(Integer.toHexString(Arrays.hashCode(bytes)))
                .contentType(MediaType.IMAGE_PNG)
                .body(bytes);
    }
}
How it works

CacheControl.maxAge(...).cachePublic() tells edges and browsers to cache for 30 days.

eTag(...) enables conditional revalidation so unchanged assets return 304.

contentType ensures correct MIME handling at the edge and client.

Versioned URLs (not shown) let you replace content without waiting for TTL expiry.
