Authentication and Authorization (OAuth, JWT, Sessions, Cookies)

Authentication verifies who a user is; authorization decides what they may do.

Sessions store server-side state and reference it via a cookie.

JWTs are self-contained, signed tokens carrying claims, enabling stateless auth.

OAuth 2.0 delegates access, letting apps act on a user's behalf without their password.

When to use / Key points
  • Use sessions/cookies for classic server-rendered web apps.
  • Use JWTs for stateless APIs and cross-service auth; keep them short-lived.
  • Use OAuth 2.0 / OpenID Connect for third-party login and delegated access.
  • Set cookies HttpOnly, Secure, and SameSite to reduce theft and CSRF.
Pros and Cons
Stateless Scaling

JWTs scale statelessly and carry claims that drive authorization decisions.

Instant Revocation

Sessions are easy to revoke instantly on the server.

No Password Sharing

OAuth avoids sharing passwords with third-party apps.

Hard To Revoke

JWTs are hard to revoke before expiry without extra machinery.

Shared State Needed

Sessions require shared or sticky state, complicating horizontal scaling.

Complex OAuth Flows

OAuth flows are complex and easy to misconfigure insecurely.

Code
// Issue and validate a signed JWT
public class JwtService {

    private final Key key = Keys.hmacShaKeyFor(secret.getBytes());

    public String issue(String userId, List<String> roles) {
        return Jwts.builder()
                .setSubject(userId)
                .claim("roles", roles)
                .setExpiration(Date.from(Instant.now().plusSeconds(900)))
                .signWith(key)
                .compact();
    }

    public Claims validate(String token) {
        return Jwts.parserBuilder().setSigningKey(key).build()
                .parseClaimsJws(token).getBody(); // throws if invalid/expired
    }
}
How it works

setSubject and claim("roles", ...) embed identity and authorization data.

signWith(key) produces a signature so tampering is detectable.

A 900-second expiration limits the damage window of a leaked token.

parseClaimsJws verifies the signature and rejects expired tokens.
