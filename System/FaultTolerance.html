Fault Tolerance

Fault tolerance is a system's ability to keep operating correctly even when some components fail.

When a component of one system fails, the entire system does not fail.

It is achieved through redundancy, isolation, and graceful degradation rather than by preventing all faults.

Patterns like circuit breakers, bulkheads, and failover contain faults so they do not cascade.

When to use / Key points
  • Use redundancy so a backup can take over when a primary fails.
  • Isolate failures with bulkheads so one overloaded dependency cannot exhaust all threads.
  • Use a circuit breaker to stop calling a failing dependency and fail fast.
  • Provide graceful degradation - serve cached or partial results instead of erroring.
  • Test with chaos engineering to verify tolerance before real incidents.
Pros and Cons
Stops Cascading Failures

It prevents localized failures from cascading into full system outages.

Graceful Degradation

It keeps core features working even during partial degradation.

Higher Availability

It improves overall availability and reliability of the system.

Increased Cost

Redundant components increase cost and operational overhead.

Added Complexity

Fallback logic adds code paths that must themselves be tested.

Hard to Tune

Poorly tuned circuit breakers can trip too early or too late.

Code
# Circuit breaker with a fallback (Resilience4j style)
@Service
public class PricingService {

    @CircuitBreaker(name = "pricing", fallbackMethod = "cachedPrice")
    public BigDecimal getPrice(String sku) {
        return remoteClient.fetchPrice(sku); # may fail or time out
    }

    # invoked when the breaker is open or the call fails
    public BigDecimal cachedPrice(String sku, Throwable t) {
        return priceCache.getOrDefault(sku, BigDecimal.ZERO);
    }
}
How it works

@CircuitBreaker tracks failures and opens the circuit when they exceed a threshold.

While open, calls skip the failing dependency and go straight to the fallback.

cachedPrice degrades gracefully instead of propagating the error.

The breaker periodically half-opens to test if the dependency recovered.
