RabbitMQ

RabbitMQ is a mature open-source message broker built on the AMQP protocol.

Producers publish to exchanges, which route messages to queues via bindings and routing keys.

Consumers subscribe to queues and acknowledge messages once processed.

It excels at flexible routing, per-message reliability, and traditional task queues.

When to use / Key points
  • Use for task/work queues, RPC, and complex routing between services.
  • Choose an exchange type: direct, topic, fanout, or headers, per routing need.
  • Use manual acks and dead-letter queues for reliable failure handling.
  • Prefer Kafka instead when you need high-throughput event replay and log retention.
Advantages
  • Rich, flexible routing through multiple exchange types.
  • Strong per-message delivery guarantees with acks and persistence.
  • Mature tooling, management UI, and broad client support.
Disadvantages / Trade-offs
  • Lower throughput than log-based brokers like Kafka for huge streams.
  • Messages are removed after consumption, so no long-term replay by default.
  • Deep queues under load can strain broker memory and performance.
Code
// Declaring a topic exchange, queue, and binding in Spring AMQP
@Configuration
public class RabbitConfig {

    @Bean
    public TopicExchange ordersExchange() {
        return new TopicExchange("orders.exchange");
    }

    @Bean
    public Queue ordersQueue() {
        // durable queue survives broker restarts
        return QueueBuilder.durable("orders.queue").build();
    }

    @Bean
    public Binding ordersBinding(Queue q, TopicExchange ex) {
        return BindingBuilder.bind(q).to(ex).with("orders.*");
    }
}
How it works

TopicExchange routes by pattern-matching routing keys against bindings.

QueueBuilder.durable(...) persists the queue so it survives restarts.

BindingBuilder...with("orders.*") binds keys like orders.created to the queue.

The exchange decouples publishers from the concrete queues receiving messages.
