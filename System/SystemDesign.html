System Design

System design is the process of defining the architecture, components, interfaces, and data of a software system to meet specific requirements.

It ensures a system is well-structured, efficient, and able to meet the evolving needs of its users.

It balances functional needs against quality attributes like scalability, availability, and consistency.

It spans everything from load balancers and caches to data stores and communication protocols.

When to use / Key points
  • Scalability: handle increasing load by adding more nodes.
  • Availability: stay operational even if some nodes fail.
  • Consistency: keep data correct across components.
  • Fault tolerance and security are designed in, not bolted on.
Pros and Cons
Exposes Weak Points Early

It reveals bottlenecks and single points of failure before any code is written.

Shared Blueprint

It gives the whole team a common blueprint to build against.

Explicit Trade-offs

It makes trade-offs such as cost versus performance explicit.

Premature Scaling

Designing for scale you do not yet need wastes effort and money.

Uncertain Estimates

Estimates are uncertain, so designs must stay adaptable.

No Perfect Design

No single design satisfies every quality attribute at once.

Code
# A cache-aside read path, a common system-design building block
@Service
public class ProductService {

    private final Cache cache;
    private final ProductRepository repo;

    public ProductService(Cache cache, ProductRepository repo) {
        this.cache = cache;
        this.repo = repo;
    }

    public Product getProduct(Long id) {
        Product cached = cache.get(id);
        if (cached != null) return cached; # cache hit

        Product fromDb = repo.findById(id)
            .orElseThrow(() -> new NotFoundException(id));
        cache.put(id, fromDb);           # populate for next time
        return fromDb;
    }
}
How it works

The cache is checked first to cut latency and database load.

On a miss the DB is queried once, then the result is cached.

orElseThrow handles the missing-record case safely.
