API Design

An API is a set of rules and protocols that allows different software applications to communicate with each other.

Good API design makes an interface intuitive, consistent, and stable for the clients that depend on it.

API authentication ensures the right person is accessing the right data.

Well-designed APIs use clear resources, correct HTTP semantics, versioning, and predictable errors.

When to use / Key points
  • Model resources as nouns; use HTTP verbs (GET, POST, PUT, DELETE) for actions.
  • Return correct status codes (200, 201, 400, 404, 500) and consistent error bodies.
  • Version the API (e.g. /v1) so changes do not break existing clients.
  • Use pagination, filtering, and sorting for large collections.
  • Secure with authentication/authorization; validate all inputs; keep responses idempotent where possible.
Advantages
  • Predictable, consistent APIs are easy to learn and integrate.
  • Versioning and clear contracts allow safe evolution.
  • Proper status codes and errors simplify client handling.
Disadvantages / Trade-offs
  • Public contracts are hard to change once clients depend on them.
  • Over-engineering (too many options) hurts usability.
  • Versioning and backward compatibility add maintenance burden.
Code
# RESTful, versioned resource with proper status codes and validation
@RestController
@RequestMapping("/v1/orders")
public class OrderController {

    private final OrderService service;

    OrderController(OrderService service) { this.service = service; }

    @GetMapping("/{id}")
    public OrderDto get(@PathVariable Long id) {
        return service.findById(id); # 404 if missing via handler
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED) # 201 on create
    public OrderDto create(@Valid @RequestBody CreateOrder body) {
        return service.create(body);
    }
}
How it works
  • /v1/orders versions the resource so clients are shielded from breaking changes.
  • HTTP verbs map to actions; @ResponseStatus(CREATED) returns a correct 201.
  • @Valid enforces input validation and yields 400 on bad requests.
  • DTOs form the stable contract, decoupling clients from internal entities.
