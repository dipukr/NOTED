DNS Resolution

DNS resolution translates human-readable domain names into IP addresses.

A resolver walks the hierarchy: root, then TLD, then authoritative name servers.

Records like A, AAAA, CNAME, and MX describe how to reach a domain's services.

Caching at multiple layers and TTLs make repeat lookups fast.

When to use / Key points
  • Use low TTLs before planned migrations, higher TTLs for stable records.
  • DNS enables load balancing (round-robin, geo, weighted) and failover.
  • A records map to IPv4, AAAA to IPv6, CNAME aliases one name to another.
  • Resolution is cached by the OS, resolver, and application, honoring TTL.
Pros and Cons
Name and IP Decoupling

Stable domain names stay constant while the underlying IP addresses change freely.

Load Distribution and Failover

It enables global load distribution and failover at the DNS layer.

Low Lookup Latency

Caching and TTLs minimize lookup latency for repeat requests.

Slow Propagation

Cached records delay the propagation of changes until the TTL expires.

Global Outage Risk

Misconfiguration or outages can make services unreachable globally.

Spoofing Vulnerability

Plain DNS is unencrypted and vulnerable to spoofing without DNSSEC.

Code
// Resolve a hostname to its IP addresses in Java
public class DnsLookup {

    public List<String> resolve(String host) {
        try {
            InetAddress[] addrs = InetAddress.getAllByName(host);
            return Arrays.stream(addrs)
                    .map(InetAddress::getHostAddress)
                    .collect(Collectors.toList());
        } catch (UnknownHostException ex) {
            // name did not resolve; caller decides fallback
            return Collections.emptyList();
        }
    }
}
How it works

InetAddress.getAllByName triggers a DNS lookup, returning every mapped IP.

Multiple addresses support client-side round-robin and failover.

getHostAddress yields the textual IP for logging or connection.

UnknownHostException signals a failed resolution to handle gracefully.
