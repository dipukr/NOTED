Checksum

A checksum is a small fixed-size value derived from a block of data to detect accidental changes.

The sender computes it, transmits it alongside the data, and the receiver recomputes and compares.

Common algorithms include CRC32, MD5, and SHA-256, trading speed for collision resistance.

Checksums detect corruption but do not by themselves prevent malicious tampering.

When to use / Key points
  • Verify file downloads, backups, and messages arrived without corruption.
  • Use CRC32 for fast error detection on storage and network frames.
  • Use SHA-256 when you need strong collision resistance or integrity guarantees.
  • For authenticity against attackers, use an HMAC (keyed hash), not a plain checksum.
Advantages
  • Cheap to compute and compact to store or transmit.
  • Quickly detects bit-flips, truncation, and transfer errors.
  • Enables deduplication and change detection by comparing digests.
Disadvantages / Trade-offs
  • Weak checksums (CRC, MD5) can be forged, so they are not secure.
  • Collisions mean different inputs may share a checksum.
  • A matching checksum proves integrity only, never source authenticity.
Code
// Compute CRC32 and SHA-256 checksums for a byte array
public class ChecksumUtil {

    public static long crc32(byte[] data) {
        CRC32 crc = new CRC32();
        crc.update(data);
        return crc.getValue();
    }

    public static String sha256(byte[] data) throws Exception {
        MessageDigest md = MessageDigest.getInstance("SHA-256");
        byte[] digest = md.digest(data);
        StringBuilder sb = new StringBuilder();
        for (byte b : digest) {
            sb.append(String.format("%02x", b));
        }
        return sb.toString();
    }
}
How it works
  • CRC32 accumulates a cyclic-redundancy value ideal for fast corruption checks.
  • MessageDigest.getInstance("SHA-256") produces a 256-bit cryptographic digest.
  • md.digest(data) finalizes the hash over all supplied bytes.
  • The hex loop converts raw bytes into a comparable, printable string.
