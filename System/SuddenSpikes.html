Sudden Spikes

A sudden spike is a sharp, often unpredictable surge in traffic or load.

Causes include flash sales, viral content, marketing events, or bot attacks.

Without protection, spikes exhaust resources and cascade into outages.

Handling them combines scaling, buffering, shedding, and caching.

When to use / Key points
  • Autoscale horizontally, but pre-warm capacity since scaling is not instant.
  • Buffer bursts with a queue so backends drain at a safe rate.
  • Apply rate limiting and load shedding to protect core functionality.
  • Cache and use a CDN to absorb read-heavy spikes at the edge.
Advantages
  • Proper handling preserves availability during peak demand.
  • Graceful degradation keeps critical paths working when overloaded.
  • Queues and caches smooth load and protect databases.
Disadvantages / Trade-offs
  • Over-provisioning for rare spikes wastes cost.
  • Autoscaling lag can still drop requests during the initial surge.
  • Rate limiting and shedding reject some legitimate users.
Code
// Token-bucket rate limiter to cap load during a spike
@Component
public class RateLimiter {

    private final Semaphore permits = new Semaphore(100); // max concurrent

    public boolean tryHandle(Runnable work) {
        if (!permits.tryAcquire()) {
            return false; // shed load instead of collapsing
        }
        try {
            work.run();
            return true;
        } finally {
            permits.release();
        }
    }
}
How it works
  • Semaphore caps concurrent work so a spike cannot exhaust threads.
  • tryAcquire() returns immediately, enabling fast load shedding.
  • Rejected requests get a 429 instead of dragging down the whole service.
  • finally release guarantees permits return even when work throws.
