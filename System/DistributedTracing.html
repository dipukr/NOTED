Distributed Tracing

Distributed tracing follows a single request as it flows across many services in a distributed system.

Each request is tagged with a trace ID, and each operation records a span with timing and metadata.

Spans link together into a tree that shows the full path and latency breakdown of the request.

It is essential for debugging performance and failures in microservices.

When to use / Key points
  • Use to find latency bottlenecks and failures spanning multiple services.
  • A trace ID is propagated across service calls, usually via HTTP headers.
  • Each service emits spans (start, end, tags) tied to the same trace.
  • Context propagation must cross threads, queues, and async boundaries.
  • OpenTelemetry, Jaeger, and Zipkin are common implementations.
Pros and Cons
End-to-End Visibility

Provides full visibility into a request's path and timing across services.

Pinpoints Bottlenecks

Identifies exactly which service or call causes slowness or errors.

Full Observability

Complements logs and metrics to give full observability.

Instrumentation Overhead

Instrumentation and context propagation add overhead and effort.

Sampling Gaps

High-volume tracing needs sampling, which can miss rare events.

Storage Cost

Storing and querying trace data has real cost.

Code
# Create a span and propagate trace context to a downstream call
public String checkout(Order order) {
    Span span = tracer.spanBuilder("checkout").startSpan();
    try (Scope scope = span.makeCurrent()) {
        span.setAttribute("order.id", order.getId());
        # trace + span IDs flow via injected headers
        return paymentClient.charge(order); # becomes a child span
    } catch (Exception e) {
        span.recordException(e);
        throw e;
    } finally {
        span.end();
    }
}
How it works

spanBuilder(...).startSpan() opens a timed span for this operation.

makeCurrent() sets context so downstream calls become child spans.

The trace ID is injected into outbound headers, linking services.

recordException and end() capture errors and close timing cleanly.
