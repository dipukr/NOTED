Load Balancing

Load balancing is the method of distributing network traffic equally across a pool of resources that support an application.

A load balancer sits between the user and the server group, acting as an invisible facilitator that ensures all resource servers are used equally.

User requests first go to the load balancer, which then routes each request to the server in the farm best suited to handle it.

It improves an application's availability, scalability, security, and performance.

When to use / Key points
  • Use whenever an application runs on multiple servers (a server farm) that share duplicate data.
  • Common algorithms: round-robin, least-connections, weighted, and IP/consistent hashing.
  • Layer 4 balances on TCP/UDP; Layer 7 balances on HTTP content (paths, headers).
  • Health checks let the balancer route away from unhealthy servers.
  • Enables rolling upgrades and maintenance without application downtime.
Advantages
Higher Availability

Traffic avoids failed nodes automatically, keeping the application reachable.

Better Performance

Even resource utilization across the farm improves throughput and response times.

Zero-Downtime Updates

Supports rolling software updates and maintenance without application downtime.

Disadvantages
Single Point Of Failure

The balancer itself can become a single point of failure if it is not made redundant.

Sticky Session Complexity

Sticky sessions complicate even distribution of requests across servers.

Added Overhead

Adds a network hop along with configuration and operational overhead.

Code
# A minimal round-robin balancer over a pool of backends
public class RoundRobinBalancer {

    private final List<String> servers;
    private final AtomicInteger idx = new AtomicInteger(0);

    public RoundRobinBalancer(List<String> servers) {
        this.servers = servers;
    }

    public String next() {
        int i = Math.floorMod(idx.getAndIncrement(), servers.size());
        return servers.get(i); # spread requests evenly
    }
}
How it works

AtomicInteger makes the counter safe under concurrent requests.

Math.floorMod wraps the index around the server list cyclically.

Each call returns the next backend, distributing load evenly.

Real balancers add health checks and weighting on top of this idea.
