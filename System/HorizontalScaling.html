Horizontal Scaling

Horizontal scaling (scaling out) adds more machines to a resource pool to handle increased load.

Work is distributed across many nodes, usually behind a load balancer.

It suits stateless services where any node can serve any request.

It is the foundation of most large distributed systems because capacity grows almost linearly with nodes.

When to use / Key points
  • Use when load exceeds what a single machine can handle economically.
  • Keep services stateless; push session/state to a shared store or cache.
  • Put a load balancer in front to spread requests across instances.
  • Ideal for read-heavy and traffic-spiky workloads that need elasticity.
  • Requires handling data partitioning/sharding for stateful stores.
Advantages
  • Near-linear capacity growth by adding commodity machines.
  • No hard ceiling like a single machine's max spec.
  • Improves availability - one node failing does not stop the service.
Disadvantages / Trade-offs
  • Adds distributed-system complexity: consistency, coordination, networking.
  • Stateful data needs sharding or replication, which is hard to get right.
  • More nodes mean more operational and monitoring surface.
Code
# Stateless controller: any replica can serve any request
@RestController
@RequestMapping("/api/orders")
public class OrderController {

    private final OrderService service; # state lives in shared DB/cache

    OrderController(OrderService service) { this.service = service; }

    @GetMapping("/{id}")
    public OrderDto get(@PathVariable Long id) {
        return service.findById(id); # no in-memory session state
    }
}
How it works
  • The controller holds no per-user state, so replicas are interchangeable.
  • State lives in a shared OrderService/DB, letting any node answer.
  • A load balancer can add or remove replicas without sticky sessions.
  • This statelessness is what makes scaling out linear and safe.
