Horizontal Scaling

Horizontal scaling (scaling out) adds more machines to a resource pool to handle increased load.

Work is distributed across many nodes, usually behind a load balancer.

It suits stateless services where any node can serve any request.

It is the foundation of most large distributed systems because capacity grows almost linearly with nodes.

When to use / Key points
  • Use when load exceeds what a single machine can handle economically.
  • Keep services stateless; push session/state to a shared store or cache.
  • Put a load balancer in front to spread requests across instances.
  • Ideal for read-heavy and traffic-spiky workloads that need elasticity.
  • Requires handling data partitioning/sharding for stateful stores.
Pros and Cons
Near-Linear Scaling

Capacity grows almost linearly by adding commodity machines to the pool.

No Hard Ceiling

There is no fixed limit like a single machine's maximum specification.

Improves Availability

One node failing does not stop the service, so the system stays up.

Distributed Complexity

It adds distributed-system complexity around consistency, coordination, and networking.

Hard Data Partitioning

Stateful data needs sharding or replication, which is hard to get right.

More Operational Surface

More nodes mean more operational and monitoring surface to manage.
