Scalability (QPS, Throughput, Latency, Storage)

Scalability is the ability of a system to handle an increased workload without losing performance.

It means handling growing traffic, data, or users by adding resources rather than breaking or slowing down.

QPS (queries per second) and throughput measure how much work the system completes per unit of time.

Latency measures how long a single request takes, while storage capacity bounds how much data can be retained.

A truly scalable system keeps latency stable and throughput growing as resources are added.

When to use / Key points
  • QPS / Throughput - requests served per second; the capacity dimension of the system.
  • Latency - time to serve one request; track p50, p95 and p99, not just the average.
  • Storage - total data the system must persist and index over time.
  • Measure before scaling - find the actual bottleneck (CPU, memory, IO, network, DB) first.
  • Prefer stateless services so replicas can be added freely behind a load balancer.
Advantages
Absorbs Growth

It absorbs traffic spikes and steady growth without requiring a rewrite.

Predictable Latency

It keeps latency predictable even under increasing load.

Cost Control

It lets capacity track demand, which keeps cost under control.

Disadvantages
Added Complexity

Distributed scaling adds operational and consistency complexity.

Latency Trade-off

Throughput gains often trade against per-request latency through batching and queuing.

Provisioning Risk

Over-provisioning wastes money while under-provisioning causes outages.

Code
# Simple latency + throughput meter around a service call
public String handle(Request req) {
    long start = System.nanoTime();
    try {
        return service.process(req);
    } finally {
        long micros = (System.nanoTime() - start) / 1_000;
        metrics.timer("request.latency").record(micros);
        metrics.counter("request.count").increment(); # feeds QPS
    }
}
How it works

System.nanoTime() brackets the call to measure per-request latency.

timer.record() lets the backend compute p95/p99, not just the mean.

counter.increment() divided by time gives QPS / throughput.

The finally block guarantees metrics are recorded even on failure.
