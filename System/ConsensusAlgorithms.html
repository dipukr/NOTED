Consensus Algorithms (Paxos, Raft)

Consensus lets a cluster of nodes agree on a single value or ordered log despite failures.

Paxos is the classic, provably correct protocol but is notoriously hard to implement.

Raft targets understandability, splitting consensus into leader election, log replication, and safety.

Both tolerate crashes as long as a majority (quorum) of nodes remain available.

When to use / Key points
  • Use consensus for leader election, distributed locks, and replicated state machines.
  • Raft powers etcd, Consul, and many modern coordination systems.
  • A cluster of N nodes tolerates floor((N-1)/2) failures; prefer odd counts.
  • Writes commit only after a majority acknowledges, guaranteeing durability.
Advantages
  • Provides strong consistency and a total order of operations.
  • Survives node crashes and network partitions on the minority side.
  • Raft's clear roles make correct implementation and debugging easier.
Disadvantages / Trade-offs
  • Every commit needs a majority round trip, adding write latency.
  • Throughput is bounded by the single leader handling all writes.
  • A lost quorum halts progress, trading availability for consistency.
Code
// Simplified Raft-style majority commit check
public class RaftLeader {

    private final int clusterSize;
    private final Map<String, Long> matchIndex = new ConcurrentHashMap<>();

    public boolean isCommitted(long logIndex) {
        long replicated = matchIndex.values().stream()
                .filter(idx -> idx >= logIndex)
                .count() + 1; // +1 counts the leader itself

        int quorum = (clusterSize / 2) + 1;
        return replicated >= quorum;
    }

    public void onAppendAck(String followerId, long ackedIndex) {
        matchIndex.merge(followerId, ackedIndex, Math::max);
    }
}
How it works

matchIndex tracks the highest log entry each follower has stored.

isCommitted counts followers at or beyond an index, plus the leader.

quorum is a strict majority; only then is an entry safe to apply.

onAppendAck records replication progress from each follower's response.
