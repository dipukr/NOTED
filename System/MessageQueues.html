Message Queues

A message queue is a buffer that lets producers and consumers communicate asynchronously.

Producers enqueue messages and consumers process them at their own pace, decoupling the two.

Queues smooth traffic spikes, improve resilience, and enable background processing.

Delivery semantics range from at-most-once to at-least-once and exactly-once.

When to use / Key points
  • Offload slow work (emails, reports, image processing) from the request path.
  • Decouple services so a slow consumer never blocks a producer.
  • Buffer bursts so downstream systems drain at a sustainable rate.
  • Design consumers to be idempotent because most queues redeliver on failure.
Advantages
  • Loose coupling and independent scaling of producers and consumers.
  • Resilience: messages persist until acknowledged, surviving consumer crashes.
  • Load leveling absorbs spikes without overwhelming downstream services.
Disadvantages / Trade-offs
  • Adds operational complexity and another component to monitor.
  • Eventual, asynchronous processing complicates end-to-end tracing.
  • Redelivery and ordering guarantees force careful consumer design.
Code
// Producing and consuming with Spring AMQP (RabbitMQ)
@Service
public class OrderQueueService {

    private final RabbitTemplate rabbitTemplate;

    public OrderQueueService(RabbitTemplate rabbitTemplate) {
        this.rabbitTemplate = rabbitTemplate;
    }

    public void enqueue(OrderEvent event) {
        rabbitTemplate.convertAndSend("orders.exchange", "orders.created", event);
    }

    // Consumer acknowledges automatically on normal return
    @RabbitListener(queues = "orders.queue")
    public void onOrder(OrderEvent event) {
        orderProcessor.process(event);
    }
}
How it works
  • convertAndSend serializes the event and routes it via an exchange and routing key.
  • @RabbitListener binds a method to a queue and delivers messages to it.
  • Returning normally acks the message; throwing triggers redelivery or dead-lettering.
  • Producer and consumer share only the queue contract, never direct calls.
