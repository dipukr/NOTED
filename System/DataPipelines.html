Data Pipelines

A data pipeline moves and transforms data from sources to destinations in stages.

Stages typically extract, transform, and load (ETL) or load then transform (ELT).

Pipelines run in batch on a schedule or as continuous streaming flows.

They feed analytics, warehouses, machine learning, and reporting systems.

When to use / Key points
  • Use batch for periodic bulk loads; use streaming for near real-time needs.
  • Design stages to be idempotent and replayable after failures.
  • Track data lineage, schema, and quality checks at each step.
  • Tools include Kafka, Spark, Airflow, and Flink.
Advantages
  • Automates reliable, repeatable data movement and transformation.
  • Decouples producers from consumers of processed data.
  • Enables timely analytics and centralized, cleaned datasets.
Disadvantages / Trade-offs
  • Complex to build, monitor, and recover after partial failures.
  • Schema changes upstream can silently break downstream stages.
  • Latency and cost grow with data volume and transformation depth.
Code
// A simple streaming ETL stage consuming, transforming, publishing
@Service
public class EnrichmentStage {

    private final KafkaTemplate<String, EnrichedEvent> out;
    private final GeoLookup geoLookup;

    @KafkaListener(topics = "raw-events", groupId = "enricher")
    public void process(RawEvent raw) {
        // transform: enrich with geo data, drop invalid rows
        if (raw.getIp() == null) return;

        EnrichedEvent enriched = new EnrichedEvent(
                raw.getId(), geoLookup.country(raw.getIp()), raw.getPayload());

        out.send("enriched-events", enriched.getId(), enriched);
    }
}
How it works
  • @KafkaListener consumes the raw source topic as one pipeline stage.
  • The null-IP guard performs data-quality filtering before transformation.
  • geoLookup.country(...) enriches each record with derived fields.
  • out.send publishes to the next topic, chaining stages together.
