Pub/Sub System

Publish-subscribe is a messaging pattern where senders broadcast to topics, not to specific receivers.

Subscribers register interest in a topic and receive every message published to it.

Publishers and subscribers are fully decoupled and unaware of each other.

It underpins event-driven systems, fan-out notifications, and real-time updates.

When to use / Key points
  • Use when one event must reach many independent consumers (fan-out).
  • Good for notifications, cache invalidation, and event sourcing.
  • Contrast with point-to-point queues where each message goes to one consumer.
  • Implementations include Kafka, Google Pub/Sub, Redis, and JMS topics.
Advantages
Strong Decoupling

Subscribers can be added or removed without touching the publishers.

One-to-Many Broadcast

A single event is efficiently broadcast to many consumers at once.

Natural Scaling

The system scales naturally as new consumers subscribe independently.

Disadvantages
No Direct Feedback

Publishers get no confirmation that a specific subscriber processed a message.

Variable Guarantees

Delivery guarantees and message ordering vary widely by implementation.

Hard to Debug

Tracing and debugging is difficult across many loosely coupled subscribers.

Code
// In-app pub/sub with Spring's ApplicationEventPublisher
@Service
public class OrderService {

    private final ApplicationEventPublisher publisher;

    public OrderService(ApplicationEventPublisher publisher) {
        this.publisher = publisher;
    }

    public void placeOrder(Order order) {
        repository.save(order);
        // one publish, many independent listeners react
        publisher.publishEvent(new OrderPlacedEvent(order.getId()));
    }
}

@Component
class EmailSubscriber {
    @EventListener
    public void on(OrderPlacedEvent e) {
        emailService.sendConfirmation(e.getOrderId());
    }
}
How it works

publishEvent broadcasts to every listener of that event type.

@EventListener subscribes a method without the publisher knowing it exists.

Adding a new subscriber requires no change to OrderService.

For cross-service pub/sub, swap this for Kafka or a cloud pub/sub broker.
