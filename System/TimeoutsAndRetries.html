Timeouts and Retries

Timeouts cap how long a caller waits for a response before giving up.

Retries re-attempt a failed operation in the hope that a transient fault has cleared.

Together they make remote calls resilient without hanging forever or failing on brief glitches.

Used carelessly, they can amplify load and worsen outages, so they need backoff, jitter, and limits.

When to use / Key points
  • Always set timeouts on network, DB, and RPC calls - never wait indefinitely.
  • Retry only transient/idempotent failures; never retry a non-idempotent write blindly.
  • Use exponential backoff with jitter to avoid synchronized retry storms.
  • Cap total attempts and combine with a circuit breaker to fail fast when a dependency is down.
  • Budget end-to-end: nested timeouts should shrink as you go deeper in the call chain.
Advantages
  • Prevents threads from hanging on slow or dead dependencies.
  • Recovers automatically from brief, transient failures.
  • Improves perceived reliability and stability.
Disadvantages / Trade-offs
  • Aggressive retries can overload an already-struggling service (retry storms).
  • Retrying non-idempotent operations can duplicate side effects.
  • Too-short timeouts cause false failures; too-long ones waste resources.
Code
# Per-call timeout + bounded retries with backoff and jitter
public String fetch(String url) {
    int max = 3;
    for (int i = 0; i < max; i++) {
        try {
            return client.get(url, Duration.ofSeconds(2)); # timeout
        } catch (TimeoutException | TransientException e) {
            if (i == max - 1) throw e;
            long backoff = (long) (Math.pow(2, i) * 100);
            long jitter = ThreadLocalRandom.current().nextLong(50);
            sleep(backoff + jitter); # avoid retry storms
        }
    }
    throw new IllegalStateException("unreachable");
}
How it works
  • Each call carries a 2-second timeout so it never hangs indefinitely.
  • Only timeouts and transient errors are retried, up to a fixed cap.
  • Math.pow(2, i) backoff spaces attempts out exponentially.
  • Random jitter desynchronizes clients to prevent retry storms.
