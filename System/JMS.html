JMS

JMS (Java Message Service) is a standard Java API for producing and consuming messages.

It abstracts the underlying broker so code targets the API, not a specific vendor.

JMS supports two models: point-to-point queues and publish-subscribe topics.

Implementations include ActiveMQ, Artemis, and IBM MQ.

When to use / Key points
  • Use JMS in Java/Jakarta EE and Spring apps needing a broker-neutral API.
  • Queues deliver each message to exactly one consumer (point-to-point).
  • Topics broadcast each message to all active subscribers (pub-sub).
  • Use transacted sessions or client acks for reliable processing.
Advantages
Vendor-Neutral API

It is a standard API that stays portable across any compliant broker.

Built-In Reliability

It offers transactions, acknowledgment modes, and durable subscriptions out of the box.

First-Class Spring Support

It integrates cleanly with Spring through JmsTemplate and listeners.

Disadvantages
Java-Centric

It is tied to Java and not suited to polyglot ecosystems.

Lower Throughput

It offers less throughput and replay capability than Kafka for large streams.

Hidden Broker Features

The abstraction hides broker-specific tuning and features.

Code
// Sending and receiving with Spring JMS
@Service
public class NotificationService {

    private final JmsTemplate jmsTemplate;

    public NotificationService(JmsTemplate jmsTemplate) {
        this.jmsTemplate = jmsTemplate;
    }

    public void send(String payload) {
        jmsTemplate.convertAndSend("notifications.queue", payload);
    }

    // Container invokes this for each message on the queue
    @JmsListener(destination = "notifications.queue")
    public void receive(String payload) {
        notifier.deliver(payload);
    }
}
How it works

JmsTemplate.convertAndSend converts the object to a JMS message and sends it.

@JmsListener registers a method-driven consumer on a destination.

The destination name maps to a queue (point-to-point) or topic (pub-sub).

Acknowledgment/transaction settings on the container control redelivery.
