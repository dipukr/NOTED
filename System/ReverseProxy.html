Reverse Proxy

A reverse proxy sits in front of one or more servers and forwards client requests to them.

Clients talk to the proxy as if it were the origin, unaware of the backend servers behind it.

It commonly handles load balancing, TLS termination, caching, compression, and security.

A forward proxy represents the client; a reverse proxy represents the server.

When to use / Key points
  • Use to hide and protect backend servers behind a single public endpoint.
  • Terminate TLS/SSL centrally so backends can serve plain HTTP internally.
  • Load balance requests across a pool of backend instances.
  • Cache static content and compress responses to improve performance.
  • Nginx, HAProxy, and Envoy are common reverse proxies; an API gateway is a specialized one.
Advantages
Hides Backend Topology

It conceals the backend server layout and shrinks the attack surface exposed to clients.

Centralizes Cross-Cutting Concerns

TLS termination, caching, and load balancing are all handled in one central place.

Zero-Downtime Deploys

It enables zero-downtime deploys by shifting traffic between backend instances.

Disadvantages
Single Point of Failure

It becomes a potential single point of failure unless it is made redundant.

Added Latency

It adds an extra network hop and some latency to every request.

Operational Overhead

It is another component that must be configured, secured, and monitored.

Code
# A tiny reverse proxy endpoint that forwards to a backend
@RestController
public class ProxyController {

    private final WebClient backend =
        WebClient.create("http://internal-service:9000");

    @GetMapping("/api/**")
    public Mono<String> forward(ServerHttpRequest req) {
        # client never learns the backend address
        return backend.get()
            .uri(req.getURI().getPath())
            .retrieve()
            .bodyToMono(String.class);
    }
}
How it works

The client calls the proxy's public path, not the internal service.

WebClient forwards the request to the hidden backend.

The backend host stays private, reducing the attack surface.

This point is where TLS, caching, and balancing would be centralized.
