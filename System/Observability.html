Observability

Observability is the ability to understand a system's internal state from its external outputs.

It rests on three pillars: metrics, logs, and traces.

Unlike basic monitoring, it helps answer unanticipated questions about behavior.

Good observability shortens the path from symptom to root cause.

When to use / Key points
  • Essential for distributed systems where failures span many services.
  • Metrics show trends, logs give detail, traces reveal request flow.
  • Correlate the three with shared IDs (trace/correlation IDs).
  • Instrument with standards like OpenTelemetry for portability.
Advantages
  • Faster detection and diagnosis of incidents.
  • Ability to investigate novel, unforeseen problems.
  • Data-driven insight into performance and capacity.
Disadvantages / Trade-offs
  • Telemetry volume drives significant storage and cost.
  • Instrumentation adds overhead and development effort.
  • Too much low-value data buries the useful signals.
Code
// Attach a correlation id so logs, metrics, traces align
@Component
public class CorrelationFilter implements Filter {

    @Override
    public void doFilter(ServletRequest req, ServletResponse res,
                         FilterChain chain) throws IOException, ServletException {
        String id = ((HttpServletRequest) req).getHeader("X-Correlation-Id");
        if (id == null) id = UUID.randomUUID().toString();

        MDC.put("correlationId", id); // added to every log line
        try {
            chain.doFilter(req, res);
        } finally {
            MDC.clear();
        }
    }
}
How it works
  • The filter reads or generates a correlation id per incoming request.
  • MDC.put stores it so every log line within the request carries it.
  • The same id can propagate downstream to link traces across services.
  • MDC.clear() prevents id leakage between pooled threads.
