Kafka

Kafka is an open-source distributed event streaming platform.

Kafka allows systems to publish, subscribe, store, and process streams of records (events) in a fault-tolerant manner.

It decouples services and enables event-driven architectures for real-time analytics, data integration, and monitoring.

Kafka brokers are machines running the Kafka server, which could be containers or VMs.

When to use / Key points
  • A topic is a logical, ordered collection of related messages, thought of as a log of events.
  • Topics are split into partitions, which provide parallelism and ordering within a partition.
  • Any number of producers can write to a topic and many consumers can read from it.
  • Use the Producer, Consumer, Streams, and Connect APIs for the different integration needs.
Advantages
  • Producers and consumers are decoupled and can fail and evolve independently.
  • Slow consumers do not affect producers, and consumers can be added freely.
  • High throughput and durability through partitioned, replicated logs.
Disadvantages / Trade-offs
  • Operating a cluster (brokers, ZooKeeper/KRaft, tuning) is complex.
  • Ordering is guaranteed only within a partition, not across a topic.
  • Consumers must manage offsets and idempotency to avoid duplicates.
Code
// Producing and consuming with Spring for Apache Kafka
@Service
public class EventService {

    private final KafkaTemplate<String, OrderEvent> kafkaTemplate;

    public EventService(KafkaTemplate<String, OrderEvent> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    public void publish(OrderEvent event) {
        // key routes related events to the same partition, preserving order
        kafkaTemplate.send("orders", event.getOrderId(), event);
    }

    @KafkaListener(topics = "orders", groupId = "order-processors")
    public void consume(OrderEvent event) {
        orderProcessor.handle(event);
    }
}
How it works
  • KafkaTemplate.send publishes to the topic; the key determines the partition.
  • Using orderId as the key keeps all events for one order in order.
  • @KafkaListener with a groupId joins a consumer group that shares partitions.
  • Each partition is consumed by one member of the group, enabling parallel scaling.
