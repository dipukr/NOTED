Availability

Availability is the proportion of time a system is operational and able to serve requests.

It is usually expressed as a percentage of uptime, such as the "nines" (99.9%, 99.99%).

Higher availability means less downtime: 99.99% allows only about 52 minutes of downtime per year.

It is achieved through redundancy, failover, and removing single points of failure.

When to use / Key points
  • Availability % = uptime / (uptime + downtime) over a measured window.
  • Eliminate single points of failure with redundant nodes across zones/regions.
  • Use health checks and load balancers to route away from unhealthy instances.
  • Availability = MTBF / (MTBF + MTTR) - lowering recovery time raises availability.
  • Set an SLA/SLO target; more nines cost disproportionately more.
Advantages
Always Reachable

Users can reach the service whenever they need it.

Survives Partial Outages

Failover keeps the service up during partial outages.

Supports SLAs

Directly supports SLAs and customer commitments.

Disadvantages
Rising Cost

Each additional nine of availability multiplies infrastructure cost.

Consistency Trade-off

Under CAP, favouring availability may sacrifice strong consistency.

Operational Complexity

Redundant multi-region setups are complex to operate and test.

Code
# Health endpoint the load balancer polls to route only to healthy nodes
@RestController
public class HealthController {

    private final DataSource ds;

    HealthController(DataSource ds) { this.ds = ds; }

    @GetMapping("/health")
    public ResponseEntity<String> health() {
        try (Connection c = ds.getConnection()) {
            boolean ok = c.isValid(2);
            return ok ? ResponseEntity.ok("UP")
                      : ResponseEntity.status(503).body("DOWN");
        } catch (SQLException e) {
            return ResponseEntity.status(503).body("DOWN");
        }
    }
}
How it works

/health checks a real dependency (the DB), not just that the process is alive.

A 503 tells the load balancer to stop sending traffic to this node.

Routing away from unhealthy nodes keeps the overall service available.

The 2-second validation timeout prevents the check itself from hanging.
