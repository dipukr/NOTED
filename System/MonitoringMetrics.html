Monitoring and Metrics (Prometheus, Grafana, Micrometer)

Monitoring collects numeric time-series metrics to track system health and performance.

Micrometer is a vendor-neutral metrics facade for JVM applications.

Prometheus scrapes and stores metrics and evaluates alerting rules.

Grafana visualizes those metrics in dashboards.

When to use / Key points
  • Use Micrometer to instrument counters, gauges, timers, and histograms.
  • Prometheus pulls metrics from an exposed endpoint on a schedule.
  • Track the RED (rate, errors, duration) and USE (utilization, saturation, errors) signals.
  • Build Grafana dashboards and Prometheus alert rules on the same data.
Advantages
  • Micrometer decouples code from any specific monitoring backend.
  • Prometheus is powerful, open source, and query-rich via PromQL.
  • Grafana gives flexible, shareable visualization.
Disadvantages / Trade-offs
  • High-cardinality labels can explode storage and slow queries.
  • Pull model needs service discovery and reachable endpoints.
  • Long-term storage requires extra components like Thanos or Cortex.
Code
// Time a method and expose the metric via Micrometer
@Service
public class SearchService {

    private final Timer searchTimer;

    public SearchService(MeterRegistry registry) {
        this.searchTimer = Timer.builder("search.duration")
                .publishPercentiles(0.5, 0.95, 0.99)
                .register(registry);
    }

    public List<Result> search(String query) {
        // record() measures wall-clock time of the lambda
        return searchTimer.record(() -> index.query(query));
    }
}
How it works
  • Timer records call durations and computes p50/p95/p99 percentiles.
  • MeterRegistry is the Micrometer backend that Prometheus scrapes.
  • record(...) times the lambda and returns its value transparently.
  • Grafana then charts search.duration from the Prometheus datasource.
