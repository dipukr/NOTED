Reliability Patterns (Retries, Idempotency, Backpressure, Circuit-Breakers)

Reliability patterns keep distributed systems working despite partial failures.

Retries recover from transient errors; idempotency makes them safe to repeat.

Circuit breakers stop hammering a failing dependency to allow recovery.

Backpressure signals upstream to slow down when a consumer is overloaded.

When to use / Key points
  • Retry only idempotent operations, with exponential backoff and jitter.
  • Make writes idempotent using unique request keys to avoid duplicates.
  • Use a circuit breaker around remote calls that can fail or hang.
  • Apply backpressure (bounded queues, rate limits) to prevent overload.
Advantages
  • Automatic recovery from transient faults improves availability.
  • Circuit breakers prevent cascading failures and give systems time to heal.
  • Backpressure keeps systems stable under sustained load.
Disadvantages / Trade-offs
  • Naive retries amplify load and can cause retry storms.
  • Idempotency keys add storage and lookup overhead.
  • Tuning breaker thresholds and timeouts is tricky and workload-specific.
Code
// Circuit breaker + retry with Resilience4j
@Service
public class PricingClient {

    @CircuitBreaker(name = "pricing", fallbackMethod = "cachedPrice")
    @Retry(name = "pricing")
    public BigDecimal getPrice(String sku) {
        return restClient.get()
                .uri("/prices/{sku}", sku)
                .retrieve()
                .body(BigDecimal.class);
    }

    // invoked when the breaker is open or retries exhausted
    private BigDecimal cachedPrice(String sku, Throwable t) {
        return priceCache.getOrDefault(sku, BigDecimal.ZERO);
    }
}
How it works
  • @Retry re-invokes the call on transient failures with configured backoff.
  • @CircuitBreaker trips open after too many failures, short-circuiting calls.
  • fallbackMethod supplies a degraded response instead of failing hard.
  • The cached fallback keeps the feature usable while the dependency recovers.
