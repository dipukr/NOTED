Template Method Pattern

Template Method is a behavioral design pattern that defines the skeleton of an algorithm in a base class and lets subclasses override specific steps without changing the algorithm's overall structure.

The base class provides a "template method" that calls a sequence of steps, some of which are abstract and implemented by subclasses.

This lets subclasses redefine certain steps while the invariant parts of the algorithm stay fixed.

When to use
  • When several classes share the same algorithm structure but differ in some steps.
  • When you want to control which parts of an algorithm subclasses may change.
  • When you want to eliminate duplicated code across similar subclasses.
  • Typical uses: frameworks, build/parse pipelines, and data-processing workflows.
Advantages
  • Removes code duplication by keeping the common algorithm in one place.
  • Lets subclasses customize only the parts that vary.
  • Enforces a fixed algorithm structure, reducing errors.
  • Follows the "Hollywood Principle": the base class calls the subclass steps.
Disadvantages
  • Relies on inheritance, which is less flexible than composition.
  • The fixed skeleton can limit what subclasses are able to change.
  • Maintaining the base class becomes harder as the number of steps grows.
Code
abstract class DataProcessor {

    // Template method: fixed algorithm skeleton
    public final void process() {
        read();
        transform();
        save();
    }

    abstract void read();
    abstract void transform();

    void save() {            // common step
        System.out.println("Saving result");
    }
}

class CsvProcessor extends DataProcessor {
    void read() { System.out.println("Read CSV"); }
    void transform() { System.out.println("Transform CSV"); }
}

void main() {
    DataProcessor p = new CsvProcessor();
    p.process();  // Read CSV, Transform CSV, Saving result
}
How the Template Method works
  • process() is the template method and is final.
  • It fixes the order: read, transform, then save.
  • Subclasses supply the varying steps like read().
  • Common steps such as save() stay in the base class.
