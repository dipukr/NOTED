Interface

An interface is a contract that defines what a class must be able to do, without necessarily defining how it does it.
It specifies what a class can do without dictating how, enabling pure abstraction and multiple inheritance of type.

Key Points
  • Declares a contract that implementing classes must fulfill.
  • A class implements an interface with the implements keyword.
  • A class can implement multiple interfaces.
  • Methods are implicitly public and abstract (unless default or static).
  • Use interfaces to program to an abstraction, not an implementation.
Advantages
  • Supports multiple inheritance of type in Java.
  • Decouples callers from concrete implementations.
  • Enables polymorphism and easy substitution of implementations.
  • Makes code more testable through mocking.
  • Defines clear, stable contracts between components.
Disadvantages
  • Cannot hold instance state or constructors.
  • Adding new abstract methods breaks existing implementers.
  • Too many small interfaces can fragment a design.
Code
public interface Payment {
    void pay(double amount);   # abstract by default
}

public class CreditCardPayment implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("Paid by card: " + amount);
    }
}

void main(String[] args) {
    Payment p = new CreditCardPayment();
    p.pay(100);
}
How the interface works

Payment defines the contract method pay().

CreditCardPayment implements the contract with real logic.

The variable's type is the interface, hiding the concrete class.

Any implementation can be swapped in without changing callers.
