Object-oriented Programming

Object-oriented programming is a programming paradigm that organizes code around data, which are self-contained units that bundle data and functions together. Object-oriented programming uses concepts like classes (templates for objects), encapsulation (bundling data and methods), inheritance (reusing properties from other classes), and polymorphism (objects taking on many forms) to create modular, reusable, and maintainable code.


An object oriented program is basically a collection of objects and relationships among them and they communicate or interact with each other using message passing.

Four main concept of OOPs are abstraction, encapsulation, inheritance and polymorphism which help us to write modular, reusable, extensible and generic software system.

Use cases
  • Domains that map naturally to real-world entities with state and behaviour (orders, accounts, users, devices).
  • Large, long-lived systems where modularity and clear ownership of data matter more than raw brevity.
  • When many variations of a concept share common behaviour, so inheritance or interfaces can capture the commonality.
Advantages
Modularity

Encapsulation bundles data with the methods that operate on it, so each class is a self-contained unit.

Reusability

Inheritance and composition let existing classes be reused without duplicating code or data.

Maintainability

One part of the code can change without breaking others, because internals stay hidden behind interfaces.

Extensibility

New types can be added without modifying existing code, following the open-closed principle.

Data hiding and security

Private fields with getters and setters protect state from uncontrolled external modification.

Flexibility through polymorphism

One interface can work with many implementations, chosen at runtime.

Easier modelling

Classes and relationships map closely to the problem domain, making designs easier to reason about.

Testability

Depending on abstractions rather than concrete classes makes components easy to mock and test in isolation.

Disadvantages
Added complexity

Simple problems can end up spread across many small classes and layers of indirection.

Steeper learning curve

Abstraction, inheritance hierarchies and dynamic dispatch take time to understand and design well.

Performance overhead

Object allocation, indirection and virtual method calls cost more than plain procedural code.

Fragile base class problem

Deep inheritance hierarchies couple subclasses tightly to their parents, so parent changes ripple downward.

Over-engineering

It is easy to build abstractions for flexibility that is never actually needed.

Shared mutable state

Objects holding mutable state need careful synchronisation in multi-threaded environments.

Harder to trace flow

Behaviour resolved at runtime through polymorphism can make execution paths less obvious when debugging.
